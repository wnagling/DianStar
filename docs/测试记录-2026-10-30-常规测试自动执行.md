# 常规 Python 测试默认自动执行（2026-10-30）

后续已将同一策略扩展到 Python 编译、依赖一致性与 Git 空白检查；当前范围和集成验收见 [项目常规验证](./测试记录-2026-10-31-项目常规验证.md)。本文保留测试命令首次实现时的范围和记录。

## 问题与范围

上一轮仅将 Git 暂存、提交和普通推送组合为一次确认，`workspace_run` 仍将所有命令逐次审批，因此运行 `python -m pytest -q` 依然出现确认卡片。本次调整常规 Python 验证的默认行为，不增加 UI 开关，不给予模型任意命令权限。

## 实现

- `security/command_policy.py` 识别 Python 的 `-m unittest`、`-m pytest` 及常见安静/详细输出、测试选择、发现目录和失败摘要参数。解析真实解释器的绝对路径，记录程序文件状态；程序本身位于项目内时仅信任当前应用已经使用的 Python，支持以项目虚拟环境启动的应用，不因任意文件被命名为 python 就自动放行。
- 测试文件或发现目录须位于当前项目内，显式目标不能经过链接指向项目外，受保护路径不属于自动范围。任意脚本、`python -c`、shell 包装、安装依赖、额外插件、`--basetemp`、项目外报告路径等不属于默认自动形式，仍使用既有确认流程。未覆盖的框架和参数也继续确认，不推断为安全。
- `ToolRegistration.auto_approve` 是应用可信代码中的同步回调，读取已经预检的命令状态。网关只在没有显式后台策略时使用它；`ToolPolicy(requires_approval=True)` 仍要求确认，`enabled=False` 仍阻止执行，原有明确禁止、撤销和关闭请求也优先。
- 默认自动测试仍先检查参数和项目范围，再生成并消费绑定完整参数的单次授权。没有可重用的通用写入授权；模型提供 `auto_approve` 等额外字段会被参数校验拒绝。没有审批回调时常规测试也能正常执行，其他命令不会因此执行。
- 执行前再次核对解析后的程序、文件状态与参数，确认期间执行程序被替换则停止。保留原有进程超时、输出上限、最小环境、输出脱敏和命令后文件审计。
- `mcp_status` 对默认的条件审批工具返回 `conditional_approval=true`；模型说明同步标明常规验证与其他命令的区别。Agent 应按项目已有测试框架执行；当前项目以 unittest 为主，不能因为 pytest 缺失就擅自安装或报告项目不能测试。

## 边界

测试、测试配置和插件本身会执行项目代码。识别常规调用是默认任务授权与界面策略，不是对代码副作用的证明，也不是操作系统沙箱；命令后审计不能撤销已经发生的文件或网络行为。后台显式配置仍可要求任何测试先审批，或者完全禁止命令。

本次没有增加 JavaScript 等其他测试框架的自动策略，也没有放宽强推、删除、文件编辑或 GitHub 管理审批。真实模型是否选择正确测试框架和发布工具，仍需实际对话联调。
