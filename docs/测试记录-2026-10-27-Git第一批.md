# Git 工程能力第一批验收

日期：2026-10-27（Asia/Shanghai）。

## 实现范围

- 完整工作区状态：分支、暂存/未暂存、重命名/冲突和未忽略的新文件。
- 本地分支及上游/领先落后信息；已配置远程的安全地址查询。
- 精确文件暂存和取消暂存；新分支创建，可选择从当前 HEAD 创建并切换；干净工作区切换已有分支。
- 对已批准的暂存快照创建提交，保留其他工作区内容；提交与推送分别确认。
- fetch 更新指定远程跟踪引用，不合并、不改写工作区；普通 push 固定已批准提交并核对远程 SHA，可设置上游。
- 写能力默认关闭，配置中单独允许申请；每项操作先检查、展示具体预览、确认、再检查状态。
- 预览令牌不交给模型，不注册内部 git_apply；单次使用、10 分钟有效、限当前 Server 实例。取消、无确认入口、撤销、过期或状态变化不执行。
- Git hooks、签名、外部 diff、过滤器和子模块递归不自动执行；不支持特殊索引、partial clone、共享/链接元数据和 worktree。换行设置选择性继承，避免 Windows 将未改文件误报为修改。

## 验证结果

- 完整回归：`python -m unittest discover -s tests`，**280 项全部通过，130.048 秒**。
- 先前 Git/MCP/授权专项回归：57 项通过；另验证 80×24 窗口下 400 行审批预览可滚动，确认/取消按钮仍可见。
- 使用真实 Git、真实本地 stdio MCP、一次性工作区及 bare 远程完成“创建并切换分支 → 精确暂存 → commit → push → 设置上游 → 核对远程 SHA”。无关文件修改保持原样。
- 覆盖取消暂存、新仓库初始提交、fetch 不合并、非快进推送拒绝、不覆盖远程提交、审批期间修改/远程配置变化、令牌重放/过期、敏感文件、越界参数、detached HEAD、整合中状态和关闭写操作。
- Python 编译检查、依赖检查和 `git diff --check` 通过。

## 验证边界

- 测试远程全部为临时本地 bare 仓库，没有提交或推送用户真实项目。
- 没有使用真实 DeepSeek 响应或付费 API；GitHub 官方 MCP 查询、真实 HTTPS/GCM 和 SSH 凭据路径未做在线端到端验收。
- 没有实现 pull、merge、rebase、强制推送、删除分支、冲突修复、worktree、通用文件编辑或操作系统沙箱。
- 应用状态检查和锁不能隔离其他本机进程。超时可能发生在写入之后，必须查询状态核验，不能自动重试或声称未产生变更。
