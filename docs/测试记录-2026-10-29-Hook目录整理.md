## 职责与调用

Hook 按工具能力分组。本地文件工具和 Git MCP 服务使用同一套注册、调度机制；多个 Git 工具共享 Git 分组，不为每个工具重复写一份检测逻辑。共享的内容规则仍属于 `security/content_guard.py`，通过 `check_content` 供各分组调用。

- `workspace.content` 绑定 `before_write`，应用仅本地配置例外，同时保护应用自身凭据和受限目录。
- `workspace.audit` 绑定 `after_command`，报告执行后新增、修改、删除文件中的问题。
- `git.content` 绑定 `before_stage`、`before_commit`、`before_push` 和 `after_clone`，使用同一发布策略，不能用本地保存标志放行。
- 工具继续在取得实际内容、不可变 Git 树和历史时调用检查。预览和执行前的再次检查继续保留；审批和工具策略不替代 Hook。

这不是给所有工具自动套上的通用生命周期框架。当前注册的六种事件均为已有内容检查点；其他工具需要检查时，由可信应用代码显式增加分组或事件并接入实际操作位置。GitHub 官方远程 API 参数不因目录整理而改变。

## 注册与扩展约束

`HookRegistration` 包含唯一名称、事件元组、同步检查函数和优先级。函数收到只读字段组成的 `HookContext`、文件路径及实际内容字节，返回 `Finding` 列表。优先级从小到大，同优先级按注册顺序执行。

`HookRunner(additional_hooks=...)` 只供可信 Python 代码添加检查。工厂始终合并内置安全注册；重名不能覆盖原检查。重复事件、未知事件、空注册、无效函数和异步函数会拒绝。事件绑定使用只读映射、元组和不可变注册项；没有模型参数、配置文件或仓库脚本可以注册 Hook。

当前回调逐文件执行；空文件集合仍校验事件和时限，但不会调用文件检查函数。Git MCP 服务运行在独立进程，共用注册机制和源码，不共享父进程中的 Python 回调实例；`additional_hooks` 只作用于当前 Runner。需要对 Git 服务增加规则时，应在应用内置的 Git 分组中声明，不通过 MCP 参数传递可执行代码。

默认注册和执行边界保持原有策略：单文件、总内容、文件数量、历史数量及凭据规则不变。执行前事件汇总发现后拒绝实际工具操作，执行后事件返回报告；回调异常、无效结果、输入迭代异常或检查超时均不会被视为检查成功。错误报告不输出异常原文。

20 秒是同步检查的协作式总时限，会在处理文件和回调返回后检查。它不能强行中断任意 Python 回调；不接受仓库提供的代码，也不宣称具备子进程或网络隔离。通用异步 Hook、用户可配置插件和隔离执行仍未实现。
