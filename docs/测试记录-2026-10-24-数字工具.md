# 2026-10-24 数字计算工具验收

## 实现范围

新增 `dianstar/tools/number_calculator.py`，工具名为 `calculate_number`，仅接收字符串参数 `expression`。工具定义、执行函数接入 `agent.py` 的统一注册表；运行时 Prompt 和蓝图均补充选择工具、正确列式、百分比及精度规则。没有增加临时辅助脚本。

- 支持十进制加减乘除、括号、正负号、科学计数法和整数次幂。
- 从原表达式读取 Decimal 字面量，不经二进制浮点数转换；运算使用独立的 50 位有效数字上下文，舍入方式为 ROUND_HALF_EVEN。
- 返回十进制字符串及 `approximate`，中间或最终运算发生非精确舍入时标记为近似值。
- 限制长度 512 字符、128 个 AST 节点、32 层求值嵌套、字面量 50 位有效数字，数字量级指数在 ±1000 内，幂指数为 -1000 至 1000 的整数。
- 白名单解析和求值，不使用 `eval`。不支持变量、函数、代码执行、单位换算、符号求解、`%`、`^` 或 `//`；百分比由模型列为除以 100。
- 计算不联网、不读写用户文件。除零、范围、语法和复杂度错误交回模型，可在现有循环限额内修正。

## 真实模型验证

使用当前默认 DeepSeek 模型，正式记录 5 个场景、10 次模型请求；覆盖流式和非流式回答。真实调用本地计算函数，未模拟计算结果。此前测试因控制台 GBK 输出编码中断，已发生的两个场景共 4 次请求不计入正式记录；修正终端 UTF-8 编码后完成本批验证。

| 提问 | 实际表达式 | 观察结果 |
| --- | --- | --- |
| 0.1 加 0.2 | `0.1+0.2` | 工具返回精确 `0.3`，回答一致 |
| 9.11 和 9.8 哪个数字更大 | `9.8-9.11` | 返回精确 `0.69`，回答 9.8 更大 |
| 计算 (125.5-20.5)*3/7 | `(125.5-20.5)*3/7` | 工具和回答均为精确 `45` |
| 1 除以 3，说明是否近似 | `1/3` | 返回 50 位有效数字及 `approximate=true`，回答明确区分分数精确值与有限小数近似值 |
| 1 除以 0 | `1/0` | 返回 `division_by_zero`，回答没有定义，没有编造计算结果 |

原始问题、工具参数与结果、回答、耗时和请求数保存在忽略目录 `.local/evaluations/number-tool-20261024-015906.json`。报告只记录这些内容，不记录凭据。

## 限制

这些用例各采样一次，不保证所有问法都能正确选工具或列式。模型仍负责理解百分比、单位及版本号等含义；工具不能纠正错误列式。部分真实回答仍有多余解释，工具调用和计算通过不代表表达风格已全部达标。
