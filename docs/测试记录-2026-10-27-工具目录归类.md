# 工具目录归类

日期：2026-10-27。按调用方式将工具统一放在 `dianstar/tools/` 下的两个子目录。

```text
tools/
├── local/                 程序在进程内直接调用
│   ├── registry.py
│   ├── weather.py / weather_contract.py
│   ├── date_calculator.py / number_calculator.py
│   └── web.py / web_search.py / web_reader.py / web_access.py
└── mcp/                   通过 MCP 协议调用
    ├── client.py / connection.py / launch.py
    ├── schemas.py / results.py
    ├── git_adapter.py / github_adapter.py / git_contract.py
    └── servers/git/       我们维护的 Git MCP 服务
        ├── server.py
        ├── reader.py
        └── operations.py
```

`local` 表示由程序直接调用，天气和网页工具仍会联网。Git 是我们实现的 MCP 服务，GitHub 是接入的外部 MCP 服务。

本地工具和 MCP 工具分别注册，在应用层合并后经过相同的权限网关和循环。MCP 客户端不导入服务端实现，本地工具不依赖 MCP；已有依赖隔离测试按新路径继续验证。

旧 `tools/builtin/` 和 `integrations/` 已删除，无转发模块。源码、测试、文档、服务启动和 Windows 构建脚本统一引用新路径。标准程序命令、配置和会话格式未变；内部服务入口为 `python -m dianstar.tools.mcp.servers.git.server`。

- 真实模型调用 `calculate_number`、`calculate_date`，分别返回正确的大整数乘积和 `2028-03-01`，流式输出正常。
- 干净构建 wheel 成功；源码与包内均只有 `tools/local/`、`tools/mcp/` 两个实现目录，无旧目录残留。
- 从全新目录加载安装包，配置路径、模拟冻结路径、提示词、菜单和图案资源、无窗口 TUI 启动通过。
- 安装包实际启动 Git MCP 服务，成功发现工具和读取临时 Git 仓库；主程序和新服务入口 `--help` 均通过。
