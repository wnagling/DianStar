# DianStar 的工具授权与外部资料边界

本页描述当前代码的实际机制。目标是在模型受网页诱导、误判任务或伪造授权时，阻止未经允许的执行。它不是完整的提示词注入解决方案，也不是操作系统沙箱。

## 两类状态分开

对话、网页、搜索摘要、引用、历史与工具输出属于模型处理的资料。授权属于程序控制状态，不能从这些文字恢复。

- 长期网页开关与付费策略继续存放在固定 `.local/search.json`。
- 每次 `ask_deepseek` 创建独立 `Authorization`，包含随机请求编号、能力批准、精确调用绑定、剩余次数及检查记录。
- 一轮结束、异常退出或取消时关闭上下文，临时批准失效；下一轮重新创建，不从会话文件反序列化。
- 检查记录只在内存保留工具名、能力、决定和原因，不保存参数、网页文本或凭据；目前没有持久化安全审计界面。
- 本机配置文件视为可信应用状态。此机制不防御有本机权限的其他程序篡改配置或 Python 进程。

## 用户如何修改权限

权限解析先于研究工具执行，只接收当前原始用户输入，不接收对话历史、网页、工具结果或总结。

1. 对严格完整匹配的独立命令使用本地规则。例如“以后禁止付费”“关闭网页访问”“撤销始终允许”可以直接收紧权限。不会从长文、引用或命令子串提取自动授权。还要核对当前状态：从“禁止付费”恢复“询问”属于扩大可能的使用范围，仍须确认。
2. 其余包含权限相关表达的输入，使用独立、无工具的模型请求提取一项候选。关键词只决定是否解析，不能授予权限。该请求不携带历史或研究资料。
3. 模型候选全部需要用户确认，包括候选为收紧权限时。明确的开启、长期允许、仅本轮允许也需确认。界面使用程序固定的操作说明，不使用模型自由生成的说明。
4. 只有确认回调实际返回布尔 `True` 才执行；没有交互确认入口时拒绝变更。Esc、取消、字符串“true”均不等于确认。
5. 解析失败、超时、多个不同变更或不明确时不生成授权。超过 16000 字符的非直接命令不进行候选解析。用户可单独发送明确变更。
6. 对持久化修改，程序创建一次性、绑定工具名和完整参数的批准，经控制流程的工具网关调用固定配置处理函数。研究模型看不到修改工具定义。

权限解析不是可靠的攻击分类器，可能误判引用或漏掉请求；因此它的非确定性输出只能成为需确认的提案。不能将“来源是用户输入”误认为其中每一句话都是授权。

目前只实现网页权限的自然语言映射，每次处理一项变更，处理发生在研究之前，不支持“读到一半再修改”的任意流程编排。未来文件或命令权限需要另外增加可审查的意图映射，不能让模型任意指定权限字段。

权限结果以应用生成的成对工具调用/结果写入模型消息，用于解释本次发生了什么；以后再次看到该结果不会恢复授权。

## 工具执行前的统一检查

入口是 `dianstar/security/gateway.py` 的 `ToolGateway`，由 `app/runtime.py` 使用。每个 `ToolRegistration` 同时声明 schema、能力和执行函数。

依次检查：

1. 工具已注册，名称一致，能力声明非空。
2. 参数符合工具定义：使用本地 JSON Schema 校验闭合顶层对象、必填字段、字符串、数字、布尔值、数组、嵌套对象和枚举；拒绝非有限数字、空字符串、过深或过大的参数，不联网解析外部 Schema 引用。工具内部仍负责数值、长度、地址等更细校验。
3. 能力是否属于默认低影响能力或具有程序批准。未知能力默认拒绝，不能因新工具已注册就自动允许。
4. 授权请求编号、工具名、完整参数、次数与生命周期匹配。改变目标或参数不能沿用精确批准。
5. 在真正执行前扣减尝试额度，失败也不自动返还，防止无限重试。

默认能力为计算、天气、公开网页搜索/读取和权限状态查询。计算合计每轮 64 次、天气 30 次、权限查询 16 次；网页网关分别最多 60 次分派，具体网页工具进一步限制合计 30 次免费操作及 30 次付费备用。

需要询问的未来敏感工具，可以在可信注册代码中提供 `approval_description`，并使用确认回调。网关对批准创建绑定完整参数的单次授权，再检查后执行。没有这种明确策略时直接拒绝。相同调用被拒绝后不重复弹窗；明确禁止、过期和额度耗尽不通过询问绕过。等待确认期间若工具被移除、替换或能力被禁止，也不执行。

传给执行函数的参数在检查前复制，界面等待期间外部改动原参数对象不会替换执行目标。真实文件路径、符号链接、网络重定向等仍要在实际使用资源时由工具检查；参数复制不能解决所有资源竞态。

## 普通问答不能修改权限

研究模型只获得 `WEB_ACCESS_STATUS_TOOL`，`action` 枚举只有 `status`。完整修改定义保留在独立控制流程注册表中。

即使模型提交 `allow`、`disable`，或增加 `authorized=true` 参数，后端也会拒绝。状态查询处理函数还固定只查询 `status`，不把模型参数转发给配置写入函数。

网页可以提供新的搜索线索，但不能创建批准、改变配置或选择审批结果。搜索和读取仍可按任务正常进行，不要求每个公开来源都单独确认。

## 付费访问的附加限制

继续保留原有免费优先与备用机制：

- 符合条件的免费失败只产生本轮随机备用标识；还需尝试其他合理免费路径。
- 标识绑定原工具与参数，不能改换网址、查询或跨轮使用；已成功取得内容、重新免费访问同目标或消费标识会使旧标识失效。
- 网络错误、安全拒绝、404、限流和空结果不通过付费绕过。
- 免费搜索内置 Bing → 360 有界备用；无关结果、解析或网络问题不生成付费搜索标识。两个入口都明确受限才可申请，且不能用读取首页凑齐第二个查询。具体正文读取受限仍沿用原审批机制。
- 付费调用需应用持久化策略、真实审批回调或本轮独立确认；随后还经 `web.paid` 能力批准和额度检查。
- 默认最多 30 次付费尝试；本轮同意不跨提问生效，只有用户选择长期允许才保存。
- 明确禁止策略优先于本轮允许。单独批准本轮使用不能顺便撤销长期禁止。

用户批准付费不等于证明模型选择的每个请求都有必要。当前不以关键词或域名匹配强行判断研究相关性，仍可能发生授权额度内的无效访问。

## 消息来源不会因兼容处理被提升

DeepSeek 原生调用继续使用 `assistant.tool_calls` 与对应 `tool` 消息。DSML 兼容调用也由程序生成调用 ID，转换为相同结构，不再将工具结果伪装成新 `user` 消息。

保留 `tool` 角色是来源保护，不是模型绝不会被诱导的保证。SDK 适配层不掌握授予权限的入口；即使最终回答声称“已授权”，真实状态也不会因此改变。

## 当前没有解决的风险

- 未实现 Bash、通用本地文件读写或操作系统沙箱。通用授权接口不代表已有这些能力。
- 已增加本地 stdio MCP 接入：Git 查询及受控工程操作，以及指定公开仓库的 GitHub 只读工具。只读每轮各服务最多 30 次，Git 操作预览另限 30 次。写操作默认关闭，用户启用后仍须逐次确认；应用预览绑定仓库状态和完整参数，内部单次令牌不交给模型，执行前重查状态，拒绝扩权、重放和过期。commit 使用批准的索引快照并比较旧 HEAD 更新引用，push 固定批准的提交哈希且不强制覆盖。MCP 程序以当前用户运行，并不受操作系统沙箱隔离；详见 [MCP 接入](./MCP接入.md)。
- 不能保证回答不被恶意内容污染，也不能保证引用支持每个结论。来源记录不是语义事实核查。
- 没有通用机密数据流追踪、搜索词脱敏或外传检测。公开网络目标也可能用于收集信息；增加私密文件读取前，需要单独设计对外发送控制。
- 程序不证明“该工具调用与用户任务语义相关”，授权范围检查目前以能力、精确参数、期限和额度为准。
- 固定配置写入函数、网络内部函数和 SDK 是可信应用代码。当前不是对任意本地 Python 调用者的安全隔离。
- 操作系统沙箱和工具自身的资源检查仍需与未来命令/文件能力一同设计，不能由 Hook 或提示词替代。
- 撤销阻止后续执行及尚在等待确认的操作，不保证中断已经发送的网络请求，也不能回滚已执行的副作用。

## 验证方法

`tests/test_permissions.py` 使用假模型和假凭据，不访问外网、不产生 API 费用。覆盖未知能力默认拒绝、枚举/额外参数拦截、精确单次批准、跨轮失效、撤销、审批期间变更、参数复制、恶意网页申请改权限、隔离解析与实际界面确认。

`test_web_access.py`、`test_web_fallback.py` 和 `test_deepseek.py` 继续检查付费审批、固定配置、免费优先、备用标识及消息结构。离线测试不能替代真实模型、真实服务和攻击集的端到端评估；当前不宣称已达到完整提示词注入防御。

2026-10-25 本次实现验证：完整 `unittest discover -s tests -q` 共 225 项通过，包含新增的 20 项授权边界与界面测试；`git diff --check` 通过。未进行真实模型和付费网页服务的端到端调用验证。
