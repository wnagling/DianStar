# DianStar 的工具授权与外部资料边界

本地工具使用独立 ProjectContext 与 `.local/projects.json`，Git/MCP 开关不授予或撤销本地文件能力。旧配置明确的 workspace_write_enabled=false 在没有独立配置时迁移为本地只读；本地配置损坏则停止本地工具，旧 MCP 配置损坏且无独立配置时保守保留只读。打开目录不会授权写入、执行或安装；本地根目录不因 Git 父仓库自动扩大。读写、命令、环境保存及回收执行点重检本地策略，仍统一经过原网关、Hook、文件锁、恢复和 Windows 隔离。

2026-11-03：Windows 命令已接入实际 AppContainer，旧文中的“命令无操作系统隔离”仅描述历史状态。当前复杂命令采用 PowerShell 7，SDK/脚本不兼容时拒绝执行，不使用无限制后备。统一路径规则在 `security/system_paths.py`，机器管理指令规则在 `security/host_commands.py`，由 `before_command` Hook 调用；文件入口、项目接入、Git 仓库与创建目标、回收入口共用系统禁区。驱动、启动和磁盘操作不能通过一次确认放行。

最终使用 LPAC 创建属性，排除普通公共应用包权限。普通 AppContainer 在对 `ALL APPLICATION PACKAGES` 开放写入的测试目录上确实能越界，因此已替换并增加真实拒绝用例。实际启动仍核对 AppContainer身份和精确包SID；本机不支持通过用户态 class46 查询LPAC标志，不依赖该查询或未文档化令牌属性。LPAC创建属性由系统API强制应用，异常即停止。运行时仅添加注册表只读查询能力，选定的PowerShell 7另加日志及COM初始化能力；网络能力仍需本次请求。

`platform/command_isolation.py` 管理每次调用的包身份、项目及临时目录权限和私有桌面；`windows_command_worker.py` 从固定代码、私有输入启动挂起进程，核对令牌确为预期 AppContainer 后才运行。子进程仅继承标准输出/错误与空输入句柄，不继承启动描述或授权记录。启动失败标记绑定私有随机标识，不接受程序伪造普通输出作为“未执行”证明。程序可能已运行时明确返回执行不完整，不建议盲目重试。

敏感路径采用访问白名单排除，暂停继承项目包权限，保留正常用户的有效权限；Git 元数据仅给命令只读访问。权限变更前记录原 ACL、目录身份及预期状态；结束恢复时核对状态，发现外部权限变化就保留记录，避免覆盖。不是所有 Windows 包/能力 SID 拒绝项都能代替白名单排除，专项测试包含实际 .env 读取。应用状态目录不能经项目接入或 Git init 变成可写项目，程序绑定的临时工作区使用单独受控入口。

命令默认无网络能力，单次 network=true 需具体确认且不扩大文件范围。系统凭据、设备、宿主进程与注册表由 AppContainer 的边界约束；不添加宿主回环豁免。另有进程数、总内存、超时、输出限额和 Job 清理。SDK只读访问不覆盖整个用户主目录、桌面或应用状态，SDK自身的权限和运行时兼容性不足时停止。详见 [系统保护记录](./测试记录-2026-11-03-系统保护与PowerShell.md)。

tmp/trash 通过原 ToolGateway 和 `hooks/storage.py` 处理。回收前冻结路径、内容哈希、文件身份及父目录身份，确认期间不持锁；执行前重建计划，相同才操作。系统锁顺序为管理锁、排序后的仓库/祖先锁、数据库事务；原文件读写和命令仍遵守同一仓库锁。tmp 使用独立跨进程使用锁，防止另一进程清理活跃脚本；会话身份来自应用，模型不能指定会话。后台停用、基础删除工具停用、撤销及强制审批优先。

trash 同盘移动原件，跨盘先流式复制并校验，再把原件停放至同盘受保护的中转位置；整批持久确认后才清理冗余原件。每个阶段先写恢复意图，进程退出后可区分回收、恢复、永久清理和残留清理。失败尝试逆序补偿，目标被重建或内容变化时保留现场，不覆盖用户文件。清理仅逐项删除记录范围及身份仍匹配的对象，未知子项阻止继续；不使用通配符或递归强删。恢复本身不判断代码语义，旧文件事务记录、Git 和任务日志保持独立。

Windows 目录位于当前用户的本地应用数据区；`storage.sqlite3` 的路径/校验/恢复状态使用当前用户 DPAPI 保护，目录正文作为本机文件保存，**不声明正文已加密**，不把 `.env` 等文件内容返回模型。POSIX 受管理目录要求0700。回收整目录会保留其受保护子项；单独敏感文件目标仍被 Hook 拒绝。链接、硬链接、NTFS附加数据流、加密或离线文件不进入这条复制路径，避免不完整备份。

默认保留30天，活跃、标记保留、恢复冲突、操作残留及变化过的备份不参与自动清理；无空间不提前删除。正常轮结束经网关做小批维护，显式禁用/撤销或强制审批时跳过后台维护。与外部编辑器不共享的锁、磁盘损坏、持续无空间和断电仍可能阻止恢复；不承诺所有文件系统元数据跨盘完全保留或外部 shell 操作自动进入回收站。完整范围见 [tmp 与 trash 验收](./测试记录-2026-11-02-tmp与trash.md)。

本页描述当前代码的实际机制，目标是在模型受网页诱导、误判任务或伪造授权时阻止未经允许的执行。授权及 Hook 与 Windows 命令的实际隔离分别生效；仍不承诺完整解决提示词注入或操作系统漏洞。

新项目默认审批在 `app/task_scope.py` 中按当前用户的直接创建/运行请求绑定到一个具体目录，不从模型参数或历史恢复；提问、示例、否定及不识别的措辞不扩大默认范围。只有新建空项目、预检确认尚不存在的普通新文件、该项目内明确要求的 Go 运行/构建及固定版本查询可免重复确认。覆盖、删除、模块安装、执行注入参数、其他项目和任意 shell 脚本不借此放行；后台禁止、撤销、明确要求审批均优先。默认范围仅省掉重复交互，文件恢复、敏感内容 Hook、命令准备及执行前重检仍执行，不能隔离程序的文件或网络副作用。

受限的环境查询通过 `workspace_environment_inspect` 完成，只执行固定程序版本参数，不执行包管理器、用户脚本或 WSL。Go 版本查询禁止自动下载工具链；返回的是 PATH 和有限位置的发现结果，不声明全盘不存在。发现程序也不等于可以免确认安装；安装仍是单独具体动作。面向用户的命令用途说明来自可信分类代码，仅用于显示，不参与授权判断，也不接收模型提供的“安全”标签。

文件写入、Git 暂存、提交和推送现在有应用内安全 Hook，检查敏感路径和实际内容，审批通过也不会跳过检查。普通项目配置和不含凭据的环境模板允许使用；仅在本地保存的运行凭据不等于允许发布。命令和克隆后提供风险报告，不能撤销已发生的操作。实现范围、扫描限制与验收见 [敏感配置 Hook](./测试记录-2026-10-29-敏感配置Hook.md)。

Hook 已独立组织在 `hooks/`，按文件、Git 和 GitHub 写操作分组，使用统一注册表与执行器。仅可信应用代码可增加同步检查，不能从模型参数、仓库脚本或配置文件注册；重名不能替换内置规则。具体接口、顺序与协作式超时边界见 [Hook 目录整理](./测试记录-2026-10-29-Hook目录整理.md)。

`hooks/github.py` 为官方 GitHub MCP 的七个写工具注册 `before_github_write` 内容检查，覆盖 PR、Issue、会话评论和审查的标题、正文及嵌套字符串参数。预览前检查一次，批准后在调用写工具前再次检查；失败、检查不完整或回调异常时停止发送。复用现有内容检测与凭据指纹，额外纳入当前 GitHub 登录凭据；完整参数 JSON 和原始多行字符串分别检查，避免换行被 JSON 转义后漏掉文本规则。检查受既有资源和协作式时限约束，不增加审批次数，也不改官方工具字段。此检查不保证识别所有未知机密、外传意图或语义风险；网络写入结果不明仍按原流程处理，不宣称自动回滚。管理 REST 工具不属于这七个官方写工具。

`credentials.py`、`secrets.ts` 等已识别的源码文件不再仅因文件名被拒绝，但仍检查完整内容；凭据数据文件、私钥和受保护目录继续拒绝。提交检查读取完整暂存快照，包含本次未修改的文件；工作区已修正而未重新暂存时，检查的仍是旧内容。失败结果会标记 `source=git_index` 并说明这一点。复现、边界和验证见 [Hook 误报修复](./测试记录-2026-10-30-Hook误报修复.md)。

普通提交发布新增有界组合工具 `git_publish`。一次批准覆盖明确文件、提交说明和远程目标的暂存、提交、普通推送与核验；不会为模型创建可任意使用的整轮写权限。组合注册通过可信 `required_tools` 声明底层工具，底层禁用、缺失、禁止或确认期间撤销都会阻止执行。各阶段内容 Hook、状态绑定和远程核验继续生效；不含强推、分支删除或任意命令。推送失败可留下已成功的本地提交，结果明确返回部分进度。详见 [发布计划验收](./测试记录-2026-10-30-单次确认发布.md)。

`workspace_run` 的常规 Python 验证使用可信注册回调 `ToolRegistration.auto_approve` 判断已准备的命令。该默认行为只省略弹窗，仍经参数检查、执行预检和精确单次授权；模型不能传入自动批准标记。后台明确指定 `ToolPolicy` 时以该策略为准，仍可强制审批或禁止。解释器解析为绝对路径并绑定文件状态，执行前重查。测试和测试配置仍能执行项目代码，这种分类用于区分用户体验，不构成文件系统或网络隔离。范围与测试见 [常规验证](./测试记录-2026-10-30-常规测试自动执行.md)。

同一默认验证策略覆盖测试、Python 编译、`pip check` 和 Git 空白检查。编译必须明确选择存在的项目内目标，不能省略目标后遍历 Python 安装路径，也不接受外部输入文件列表；compileall 增加项目内源文件链接限制。Git 空白检查复用 Git 工具的配置限制和受控环境，关闭外部 diff、textconv 和 fsmonitor，不把普通 `git` 命令整体放行。详见 [项目验证验收](./测试记录-2026-10-31-项目常规验证.md)。

## 文件读写保护

命令入口共用 `before_command` Hook，预览和实际启动前检查命令内容中的已知凭据及共享敏感规则，异常/拒绝停止执行；不尝试用危险命令关键字列表代替授权或隔离。bash 的免确认仅适用于无展开/拼接的常规验证，并绑定实际程序直接执行；其他脚本保留具体确认。只读/禁用和 `workspace_run` 的基础禁用继续有效，后台策略也可强制确认。

Windows 命令以挂起状态创建，归入 kill-on-close Job 并核对 AppContainer 令牌后才恢复，超时/取消与前台退出时清理归属进程树、排空并关闭管道。Job 管生命周期，AppContainer 管访问边界；任何一项失败都停止。普通命令结束还有文件审计，整轮取消或超时不能声称已回滚。其他平台的旧进程组实现不作为无限制执行后备。依据参见 [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)，实测范围见本页开头的系统保护记录。

开发环境覆盖仅接受有界的公共构建变量，拒绝凭据名、BASH_ENV 等启动注入参数和无关任意键。变量值在共享 before_command Hook 内检查，宿主继承值若命中共享凭据检测则省略；不把系统/应用凭据复制到子进程。非空环境覆盖可能改变解释器、模块或链接器解析，默认要求确认，不借常规验证分类静默执行。确认绑定命令、项目、覆盖参数与实际准备环境；等待期间改变环境/程序时不执行。后台免确认只能省弹窗，不能省预检。本次 environment 不写全局或保存配置，不构成文件/网络隔离。

会话项目环境仅保存公开构建变量及 PATH 前置目录，保存与命令复用都经过共享 Hook。SQLite 的联合键来自应用会话身份与项目路径，模型不能传入其他会话 ID；Windows 内容使用当前用户 DPAPI，POSIX 沿用私有目录/文件权限。保存不记录审批，不传播到其他会话，也不以“已保存”为由免除命令审批。修改采用事务和版本比较；清除保留递增版本，旧计划不能覆盖新记录。配置操作在同批次作为共享状态屏障，跨进程使用与命令一致的项目锁；命令拿到项目锁后重做准备检查，配置变化则不执行。数据库首开 WAL/建表使用短 OS 锁，避免任务记录和环境记录并发初始化冲突。损坏或无法解密的环境记录停止复用，不静默退回其他工具链。

`read`、`glob`、`grep`、`edit`、`write` 共用项目范围和授权网关，不直接从模型循环执行。路径拒绝越界、符号链接、目录联接、硬链接及 Windows 设备名和备用数据流写法；明确禁止和只读后台策略继续有效。旧工具的明确禁用或审批要求迁移到新名称，不因改名放开权限。

`hooks/workspace.py` 注册 `before_read`，拒绝受保护路径；普通源码先经过公共内容扫描器脱敏再返回，搜索也只把脱敏文本交给固定搜索进程。脱敏保留行数，不把私钥块的中间行泄漏给分页读取。现有文件必须在本轮成功读取，写入前验证完整快照；审批期间或实际替换前有变化则停止，保留用户修改。

`before_write` 在预览与执行前分别检查目标内容，Hook 失败或异常不写文件，免弹窗策略也不跳过检查。确认范围绑定具体文件和内容；使用同目录临时文件、刷新后原子替换，新建遇到并发创建不覆盖。禁止将含敏感内容的脱敏读取结果直接写回。公共规则仍在 `security/content_guard.py`，文件工具不复制令牌判断规则。

搜索设文件数、文件大小、总量、分页与输出上限，正则在独立可信进程中限时执行。统一文件锁和持久化补偿事务现已接入，具体行为见下节；Hook 与锁不构成操作系统隔离，无法保证消除所有外部进程的竞争窗口。首批工具范围见 [文件工具验收](./测试记录-2026-10-31-文件工具第一批.md)。

## 文件锁、持久记录与恢复

`security/file_locks.py` 提供所有 DianStar 实例共用的系统锁。Windows 使用 LockFileEx，其他平台使用 flock；文件读取共享、文件写入独占，多文件按规范路径排序。仓库和祖先目录协调锁允许不同文件正常操作，Git 应用计划和项目命令取得仓库独占锁；父仓库命令也与嵌套项目文件操作协调。锁文件不删除，进程退出由系统释放锁。审批期间不持锁，执行时重新加锁并复查版本；磁盘工作在线程执行，取消会等待写入线程处理补偿或保留恢复状态。

每次文件修改先持久化原始字节、目标内容、文件身份/版本和目录身份，再替换或删除目标。SQLite 使用 WAL 和 FULL 同步，目标临时文件刷新后将预期身份写入日志，随后发布；进程在发布前后退出都可依据这些状态判断是否已经应用。批量工具 `file_batch` 最多处理 20 个不同路径，一次审批，失败时逆序补偿；补偿也持久化进度，可以再次中断后继续。

patch 和 move 使用同一事务体系，预检全部源/目标，确认后复查所有版本与父目录身份；新目标拒绝覆盖，补丁拒绝模糊或重复上下文，任一段无效时不开始文件写入。移动先持久发布目标，再删除源；失败/取消逆序补偿，进程退出后可按日志恢复。源和目标同时纳入锁、恢复和模型复核。目标内容在预览与执行前经过 before_write，已有源也经过 before_read；不提供 local_only，受保护路径、凭据、链接和越界限制保持有效。基础 edit/write/delete 的明确禁用与撤销约束按组合工具依赖继续生效。

Windows 默认状态目录为 `%LOCALAPPDATA%/DianStar/file-state`，不随项目提交。恢复原文和独立摘要都使用当前用户 DPAPI 加密；非 Windows 使用 0700 目录和 0600 文件，不声明已加密。可信运行环境可用绝对路径 `DIANSTAR_FILE_STATE_ROOT` 隔离状态；测试必须设置到临时目录。历史列表只读取小摘要，不批量加载恢复原文。备份不返回模型，也不写进聊天或审批详情。

`file_history` 查询编号和状态；`file_restore` 预览后撤销已完成记录或继续中断恢复，并保留新恢复记录以便再次撤销。连续撤销只接受实际文件版本，或已持久化的 DianStar 恢复版本链，外部重新写入相同内容也不自动视为同一版本。原有秘密被重新写入时，普通历史撤销仍要经过内容 Hook；失败操作的原状补偿仅使用可信备份，不接受模型传入的恢复字节。

读取不自动执行恢复，严格只读策略仍有效，返回 recovery_pending 提醒存在中断记录；新的写入或命令预检可以先补偿未完成操作。Git 写操作发现未处理的文件恢复会拒绝继续。恢复遇到外部改动时标记冲突并保留现场；用户可确认 keep_current，保留当前所有文件并结束该记录，原副本不删除。批量和恢复工具依赖基础 edit/write/delete 权限，不能绕过单工具禁用。

这是可恢复的补偿事务，不是文件系统对所有外部程序的多文件原子可见性保证。磁盘/数据库损坏、持续无可用空间、系统断电及不遵守锁的程序仍可能阻止恢复；状态会保留或报告错误，不能宣称已恢复成功。临时文件或非空目录无法安全清理时保留并报告，绝不递归删除用户文件。命令和 Git 的锁只协调执行，通用命令、Git 历史和远程副作用不属于文件工具的自动回滚范围。验收见 [文件恢复与并发记录](./测试记录-2026-11-01-文件恢复与并发.md)。

## 修改证据与并发边界

所有类型工具都参与并发；资源声明只能来自可信注册与应用映射，不接受模型提供的锁元数据或授权。共享读取可并行，有写入的重叠范围按调用顺序等待；同一项目的通用命令独占整个项目，无法确定的资源保守独占，项目切换和共享配置独占运行。资源顺序不会自动判断前一步成功，也不能识别所有语义依赖；依赖返回值或条件判断的后续动作要在模型收到整批结果后另发。审批回调共用互斥锁，避免多个弹窗争用界面，但独立工具仍可执行。

文件事务先取得跨进程存活锁再保存日志；独立写入略过仍活跃的事务，只有事务已中断时才重新取得仓库独占锁恢复。系统锁按祖先目录、仓库、排序并去重后的父目录/文件路径取得，重复路径以独占模式为准，事务存活锁最后取得且不再请求文件锁；审批期间不持系统锁，不使用共享锁升级。该顺序用于消除协作实例之间的循环等待，锁超时明确失败，不能保证外部程序遵守锁。网页免费与付费请求各自保存服务选择，并发付费请求复用本轮决定并重查撤销、令牌和额度，网络请求可在确认后并行。

`app/change_review.py` 只接受实际工具回执中的事务编号和验证结果，不相信模型文本中的“已通过”。本地差异来自受保护恢复副本，脱敏后返回，正文属于不可信资料；受保护本机配置只展示状态，不展示正文。复核记录绑定修改代次和最新文件版本，修改后旧证据失效；当前失败检查不能通过选择其他成功证据来忽略。模型选择 uncertain 可以交付明确限制，不能因此伪造通过记录。Reflect 是业务判断，不是新的权限或内容 Hook。

逐项任务台账保存在原文件状态目录的 `tasks.sqlite3`，与完整备份分开；内容先脱敏，再按文件状态模块的同一规则保护（Windows 当前用户 DPAPI）。SQLite WAL/FULL 提交完成才通知界面，单事件超过 512 KiB 明确标记截断，文件恢复副本继续保留。历史查询限定同会话，分页且有输出上限；中断记录不会作为当前文件状态或新授权。任务日志保留实际执行、取消和预算耗尽状态，但不承诺外部远程副作用自动回滚、磁盘永久可靠或模型一定发现所有语义错误。测试范围见 [编排复核与工具并发](./测试记录-2026-11-01-编排复核与工具并发.md)。

## 两类状态分开

GitHub 账号切换将新账号选择与旧登录的 `pending_cleanup` 一起原子保存；退出先持久化禁用状态及待清理记录，再尝试系统凭据库清理。失败记录保留，可在后续账号状态检查重试。待清理条目只允许有效账号名及 DianStar 命名空间，不包含令牌，也不能引用当前正在使用的命名空间。同一账号服务实例串行处理操作；这不是跨进程隔离。实现及尚未执行的回归用例见 [旧凭据清理记录](./修复记录-2026-10-31-GitHub旧凭据清理.md)。

对话、网页、搜索摘要、引用、历史与工具输出属于模型处理的资料。授权属于程序控制状态，不能从这些文字恢复。

- 长期网页开关与付费策略继续存放在固定 `.local/search.json`。
- 每次 `ask_deepseek` 创建独立 `Authorization`，包含随机请求编号、能力批准、精确调用绑定、剩余次数及检查记录。
- 一轮结束、异常退出或取消时关闭上下文，临时批准失效；下一轮重新创建，不从会话文件反序列化。
- 检查记录只在内存保留工具名、能力、决定和原因，不保存参数、网页文本或凭据；目前没有持久化安全审计界面。
- 本机配置文件视为可信应用状态。此机制不防御有本机权限的其他程序篡改配置或 Python 进程。

GitHub 登录通过用户专用界面/命令进行，不注册为模型工具。浏览器或隐藏令牌输入核验账号后，将凭据保存在独立的系统凭据库位置；配置只记录非秘密元数据。退出阻止后备凭据自动生效，不改变范围或审批。详见 [账号登录](./测试记录-2026-10-30-GitHub账号登录.md)。

## 用户如何修改权限

权限解析先于研究工具执行，只接收当前原始用户输入，不接收对话历史、网页、工具结果或总结。

1. 对严格完整匹配的独立命令使用本地规则。例如“以后禁止付费”“关闭网页访问”“撤销始终允许”可以直接收紧权限。不会从长文、引用或命令子串提取自动授权。还要核对当前状态：从“禁止付费”恢复“询问”属于扩大可能的使用范围，仍须确认。
2. 其余包含权限相关表达的输入，使用独立、无工具的模型请求提取一项候选。关键词只决定是否解析，不能授予权限。该请求不携带历史或研究资料。
3. 模型候选全部需要用户确认，包括候选为收紧权限时。明确的开启、长期允许、仅本轮允许也需确认。界面使用程序固定的操作说明，不使用模型自由生成的说明。
4. 只有确认回调实际返回布尔 `True` 才执行；没有交互确认入口时拒绝变更。Esc、取消、字符串“true”均不等于确认。
5. 解析失败、超时、多个不同变更或不明确时不生成授权。超过 16000 字符的非直接命令不进行候选解析。用户可单独发送明确变更。
6. 对持久化修改，程序创建一次性、绑定工具名和完整参数的批准，经控制流程的工具网关调用固定配置处理函数。研究模型看不到修改工具定义。

权限解析不是可靠的攻击分类器，可能误判引用或漏掉请求；因此它的非确定性输出只能成为需确认的提案。不能将“来源是用户输入”误认为其中每一句话都是授权。

目前只实现网页权限的自然语言映射，每次处理一项变更，处理发生在研究之前，不支持“读到一半再修改”的任意流程编排。未来文件或命令权限需要另外增加可审查的意图映射，不能让模型任意指定权限字段。

权限结果以应用生成的成对工具调用/结果写入模型消息，用于解释本次发生了什么；以后再次看到该结果不会恢复授权。

## 工具执行前的统一检查

入口是 `dianstar/security/gateway.py` 的 `ToolGateway`，由 `app/runtime.py` 使用。每个 `ToolRegistration` 同时声明 schema、能力和执行函数。

依次检查：

1. 工具已注册，名称一致，能力声明非空。
2. 参数符合工具定义：使用本地 JSON Schema 校验闭合顶层对象、必填字段、字符串、数字、布尔值、数组、嵌套对象和枚举；拒绝非有限数字、过深或过大的参数，不联网解析外部 Schema 引用。本地工具继续拒绝空字符串；GitHub 工具遵循官方定义，允许空正文等更新语义，仓库和搜索范围另外检查。工具内部仍负责数值、长度、地址等更细校验。
3. 能力是否属于默认低影响能力或具有程序批准。未知能力默认拒绝，不能因新工具已注册就自动允许。
4. 授权请求编号、工具名、完整参数、次数与生命周期匹配。改变目标或参数不能沿用精确批准。
5. 在真正执行前扣减尝试额度，失败也不自动返还，防止无限重试。

默认能力为计算、天气、公开网页搜索/读取和权限状态查询。计算合计每轮 64 次、天气 30 次、权限查询 16 次；网页网关分别最多 60 次分派，具体网页工具进一步限制合计 30 次免费操作及 30 次付费备用。

需要询问的未来敏感工具，可以在可信注册代码中提供 `approval_description`，并使用确认回调。网关对批准创建绑定完整参数的单次授权，再检查后执行。没有这种明确策略时直接拒绝。相同调用被拒绝后不重复弹窗；明确禁止、过期和额度耗尽不通过询问绕过。等待确认期间若工具被移除、替换或能力被禁止，也不执行。

传给执行函数的参数在检查前复制，界面等待期间外部改动原参数对象不会替换执行目标。真实文件路径、符号链接、网络重定向等仍要在实际使用资源时由工具检查；参数复制不能解决所有资源竞态。

## 普通问答不能修改权限

研究模型只获得 `WEB_ACCESS_STATUS_TOOL`，`action` 枚举只有 `status`。完整修改定义保留在独立控制流程注册表中。

即使模型提交 `allow`、`disable`，或增加 `authorized=true` 参数，后端也会拒绝。状态查询处理函数还固定只查询 `status`，不把模型参数转发给配置写入函数。

网页可以提供新的搜索线索，但不能创建批准、改变配置或选择审批结果。搜索和读取仍可按任务正常进行，不要求每个公开来源都单独确认。

## 付费访问的附加限制

继续保留原有免费优先与备用机制：

- 符合条件的免费失败只产生本轮随机备用标识；还需尝试其他合理免费路径。
- 标识绑定原工具与参数，不能改换网址、查询或跨轮使用；已成功取得内容、重新免费访问同目标或消费标识会使旧标识失效。
- 网络错误、安全拒绝、404、限流和空结果不通过付费绕过。
- 免费搜索内置 Bing → 360 有界备用；无关结果、解析或网络问题不生成付费搜索标识。两个入口都明确受限才可申请，且不能用读取首页凑齐第二个查询。具体正文读取受限仍沿用原审批机制。
- 付费调用需应用持久化策略、真实审批回调或本轮独立确认；随后还经 `web.paid` 能力批准和额度检查。
- 默认最多 30 次付费尝试；本轮同意不跨提问生效，只有用户选择长期允许才保存。
- 明确禁止策略优先于本轮允许。单独批准本轮使用不能顺便撤销长期禁止。

用户批准付费不等于证明模型选择的每个请求都有必要。当前不以关键词或域名匹配强行判断研究相关性，仍可能发生授权额度内的无效访问。

## 消息来源不会因兼容处理被提升

DeepSeek 原生调用继续使用 `assistant.tool_calls` 与对应 `tool` 消息。DSML 兼容调用也由程序生成调用 ID，转换为相同结构，不再将工具结果伪装成新 `user` 消息。

保留 `tool` 角色是来源保护，不是模型绝不会被诱导的保证。SDK 适配层不掌握授予权限的入口；即使最终回答声称“已授权”，真实状态也不会因此改变。

## 当前没有解决的风险

- 未实现 Bash、通用本地文件读写或操作系统沙箱。通用授权接口不代表已有这些能力。
- 已增加本地 stdio MCP 接入：Git 查询及受控工程操作，以及 GitHub 搜索、PR、Issue、CI 和代码审查。Git、项目文件和命令修改默认可申请，GitHub 写入/管理默认仅当前项目；每次均须预览确认，不预先授予执行权限，无确认入口或拒绝时不执行。私有内容访问、明确禁止和自定义范围继续有效。只读每轮各服务最多 30 次，Git/GitHub 写操作预览分别另限 30 次。应用预览绑定目标状态和完整参数，执行前重查。Git 内部单次令牌不交给模型；GitHub 预览单次消费、10 分钟过期。远程状态检查与写入并非原子操作，仍有竞态；结果不明不自动重试。commit 使用批准的索引快照并比较旧 HEAD 更新引用，push 固定批准的提交哈希；普通推送不改写历史，明确申请的 force-with-lease 固定远程 SHA，不支持无条件强推。管理操作还检查真实管理员权限，额外只读仓库和账号 Token 权限不会扩大默认管理范围。MCP 程序和命令以当前用户运行，并不受操作系统沙箱隔离；详见 [MCP 接入](./MCP接入.md)。
- 不能保证回答不被恶意内容污染，也不能保证引用支持每个结论。来源记录不是语义事实核查。
- 没有通用机密数据流追踪、搜索词脱敏或外传检测。公开网络目标也可能用于收集信息；增加私密文件读取前，需要单独设计对外发送控制。
- 程序不证明“该工具调用与用户任务语义相关”，授权范围检查目前以能力、精确参数、期限和额度为准。
- 固定配置写入函数、网络内部函数和 SDK 是可信应用代码。当前不是对任意本地 Python 调用者的安全隔离。
- 操作系统沙箱和工具自身的资源检查仍需与未来命令/文件能力一同设计，不能由 Hook 或提示词替代。

后台策略补充：UI 不再显示功能启用或审批开关，可信调用方可通过 ToolPolicy 分别指定可用性与审批要求。禁用检查在授权消费前执行，即使已有授权也不能执行；免弹窗策略仍保留可信预检、参数验证、单次精确授权和执行时资源检查，不覆盖显式撤销或已结束请求。只读/全权限模式仅预留后端接口，尚无模式选择入口。模型不能从 configure_mcp、网页或历史设置 tool_policies，MCP 重连后策略继续生效。
- 撤销阻止后续执行及尚在等待确认的操作，不保证中断已经发送的网络请求，也不能回滚已执行的副作用。

## 验证方法

Git 操作记录与网页来源台账相互独立。Git 预览绑定的远程地址在执行结果中保留，成功推送需由服务核对远程分支提交与批准提交一致；编排层再核对工具、仓库、远程、分支及完整提交号。只有这些条件成立才生成远程已核对记录；普通远程配置、错误或连接中断都不是成功证明。记录中的 `web_content_read=false` 明确限制其用途，不能用来宣称 README 或网页已读。历史记录只恢复成对工具调用和结果，并标注历史状态；不从用户文本、模型回答或通用命令输出生成此类证明。实现范围见 [实现记录](./修复记录-2026-10-31-Git操作核对.md)，执行结果见 [回归记录](./测试记录-2026-10-31-账号与Git核对回归.md)。

`tests/test_permissions.py` 使用假模型和假凭据，不访问外网、不产生 API 费用。覆盖未知能力默认拒绝、枚举/额外参数拦截、精确单次批准、跨轮失效、撤销、审批期间变更、参数复制、恶意网页申请改权限、隔离解析与实际界面确认。
