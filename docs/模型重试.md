# 模型请求重试与 /retry

主 Agent 模型请求遇到连接错误、超时、未收到完整流结束标识、HTTP 408/409/429/500/502/503/504 时，最多自动重试2次（总共3次尝试），等待1秒、2秒，并显示进度提示。401、403、参数错误以及取消不自动重试。仅重发失败的模型请求，不重新执行上一步工具；可能增加模型费用。审计模型、Git、GitHub 或命令写入不因此获得通用自动重试。

非流式请求仍限时60秒；流式请求建立连接仍受 SDK 超时限制，每次读取最多等待60秒，持续输出可继续，单次流式尝试总时限180秒。收到完整结束标识即停止读取并关闭流。断流后的半截文本、思考和工具参数不作为已完成决定，也不执行。重试属于同一次决策的传输恢复，不增加16轮工具决策上限。

模型请求最终失败时，会话保存中断标识、原始目标、已完成的成对工具调用与结果、工具活动记录。未完成的工具参数不保存为执行请求。`/retry` 在 TUI 和纯文本会话均可用，重开会话后也能继续；仅当前会话最后一轮为模型请求失败时可用。它发起新一轮恢复请求，携带原目标与历史记录，要求先核对文件和外部状态。旧授权、预览及批准不恢复，后续操作仍须网关审批。程序不自动重放工具，但不能保证模型永远不会再次提议相同工具，执行仍依赖原有范围、预检和授权。

本次 /retry 不实现进程续跑或失败工具自动重放；用户主动取消、参数错误、磁盘保存失败等不按模型传输错误自动重试。网络在创建会话前失败时无法凭空恢复不存在的工具历史；已有独立任务日志仍可用于核对。

验收：`python -m unittest tests.test_model_retry -q` 使用假模型测试有界重试、不可重试状态、取消、半截工具参数丢弃、已完成工具不重放、失败历史保存、重开会话和TUI命令入口。不是人为断开真实网络的服务验收。
