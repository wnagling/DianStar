# 编排复核与工具并发验收（2026-11-01）

## 实现范围

本轮把文件恢复与本地 diff 接入应用编排，并增加有界查询并发。没有新增依赖、fiber 框架、独立 Reflect 模型或无限反思循环，没有提交或推送仓库。

| 位置 | 实际职责 |
| --- | --- |
| `tools/local/files/inspection.py` | 合并本轮可信文件事务，以首次修改前的工作副本为基线生成脱敏 diff，检查当前版本、外部变化和恢复状态，按字符分页 |
| `app/change_review.py` | 记录修改代次、事务编号、读取和真实检查结果，校验证据与差异覆盖，处理 Reflect 判断和交付前检查 |
| `app/turn_log.py` | 每项工具结果独立持久化；保存中断、预算耗尽及复核状态，支持同会话历史查询 |
| `core/scheduler.py` | asyncio TaskGroup + 信号量，最多四个独立查询并发；其余操作作为顺序屏障 |
| `tools/mcp/connection.py` | SDK 上下文由同一任务管理，子请求有界并发，隔离请求失败、取消和超时，关闭时等待收尾 |
| `app/runtime.py` / 模型适配 / UI | 每项先保存再更新进度，整批收齐才交模型；修改后自动回填差异，16 次预算内完成复核 |

工具仍通过原 `ToolGateway` 和 Hook。只读后台策略、拒绝授权和明确工具禁用继续有效；不增加权限页面或新弹窗。写入、命令、Git 修改、项目切换不并发，也不在审批期间持锁。

## 修改与证据规则

应用自动检查一批修改，模型也可以调用 `review_changes` 补读分页。`record_review` 记录 keep / repair / restore / uncertain 和实际证据编号；修复、恢复仍要调用实际工具。历史工具正文、模型自行编写的“已通过”和其他工具伪造的应用标记不构成可信完成记录。

任何新修改使旧证据失效。交付前再次检查实际版本；外部修改、差异未读完、无效证据、当前检查失败都会阻止确认 keep。uncertain 用于明确说明未验收部分，不能作为测试通过。仅 diff 或读取核对可以支持模型判断，但后端仍明确标记“未取得当前修改后的测试通过记录”。单纯提交推送不附加测试。

任务台账与文件恢复备份分开，内容先脱敏，再依文件状态模块规则保护；Windows 使用当前用户 DPAPI。工具完成结果在 SQLite 提交后才通知 UI。异常和取消不冒充成功会话；台账可按同会话任务编号分页查询，历史不是当前状态或授权。

主要覆盖：

- 查询实际重叠、最多四项、完成次序变化但模型结果按调用顺序成对；依赖操作和未知工具保持顺序。
- 单项错误和超时不取消其他查询；整批取消后已完成结果不丢，未开始调用也有取消回执；下一轮模型不会提前启动。

## 真实模型验收

使用当前已配置模型，创建独立本机临时项目，明确禁止命令、测试、Git 和远程操作。只允许约定文件修改及故障组恢复。未改变默认模型；运行前后核对真实 `.env` 和本地配置文件哈希一致。历史和结果先脱敏，保存在忽略的 `.local/orchestration-live-20261101/`，不纳入仓库。

### 正常修改

要求把 `settings.py` 的 TIMEOUT 从 10 改为 20，新建中文说明 `docs/notes.md`，保留 `helper.py`。最终轮使用新建的 `normal-final` 项目。

结果：**通过，6 次模型决策，一次批量写入确认**。真实模型使用文件工具，应用自动回填 diff，模型以实际证据记录 keep；文件字节核对确认 UTF-8 BOM 和 CRLF 保留，helper 原样、说明非空、无遗留临时文件。没有运行命令或测试，没有 Git/远程操作，最终回答和后端摘要均明确未测试。

### 注入误删并恢复

测试程序注入第一步删除必须保留的 helper，以及一次错误的提前完成回答，然后交回真实模型。此注入用于稳定检验错误处理，不表示模型主动产生了同样错误。

最终代码使用全新的 `fault-final` 项目重验，结果：**通过，9 次决策（含两次注入），三次具体文件操作确认**。应用的真实差异暴露误删；模型根据任务目标调用 file_restore 恢复，再完成 settings 与说明修改并复核。最终 helper 与原始字节完全一致，没有残留临时文件，没有命令、测试或远程操作。模型首次复核引用了已经过期的修改前证据，后端正确拒绝；换用当前修改后的实际证据后成功记录。修正后的正常组直接接受当前差异证据。

## 边界

- Reflect 的业务判断仍由模型完成，后端保证记录来源、版本和实际检查状态，不能保证模型发现所有逻辑错误。
- “模型已复核”不等于测试通过，更不等于全部功能正确。用户要求不测试时可以交付明确的未测试状态。
- 统一锁协调 DianStar 实例，不约束不遵守协议的编辑器；实际执行仍需版本复查。固定顺序用于避免这些协作锁的循环等待，不宣称任意第三方程序都无死锁。
- 通用命令和 Git 工作区副作用只记录范围及检查缺口，不冒充文件工具精确可恢复事务；远程副作用不自动回滚。
- 持久化、加密及补偿仍受磁盘损坏、持续空间不足、操作系统和硬件可靠性限制；恢复不确定时保留记录并报告，不能宣称已恢复。
- 此处是同一 Agent 的工具并发，不包含子 Agent、多任务协作写入或操作系统沙箱。
