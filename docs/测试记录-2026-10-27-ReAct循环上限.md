# ReAct 循环上限统一为 16 轮

日期：2026-10-27。

## 定义与实现

参考 [OpenCode 的 Max steps 定义](https://opencode.ai/docs/agents/#max-steps)，按 Agent 决策轮数计数。16 是本项目本次设定的上限，并非 OpenCode 的默认值。

原核心循环默认 4 轮，应用却用免费网页额度、付费网页额度再加 4 算出 64 轮。现以 `core/loop.py` 的 `DEFAULT_MAX_STEPS = 16` 统一默认值；`app/runtime.py` 直接使用默认值，工具额度不再决定循环轮数。纯文本和 TUI 共用该应用入口。

- 每次 `think()` 计一轮，最终文字回答也占一轮；第 16 轮返回文字正常完成。
- 同一轮最多执行 8 个工具，多个工具不分别消耗决策轮数。
- 第 16 轮仍请求工具时，执行该批工具后到达上限，沿用循环耗尽异常；不发起第 17 轮。OpenCode 还会提示模型生成收尾总结，本次修改只调整上限与计数来源，未引入该收尾机制。
- 同名同参数允许重复执行；工具权限、额度、参数检查与逐次审批继续生效。
- 上限约束 ReAct 决策轮数。权限意图识别、模型适配层内部格式纠错请求不属于额外的 ReAct 轮次，因此不能把 16 轮等同于所有模型 HTTP 请求合计最多 16 次。

## 验证

循环专项 12 项、应用入口专项 1 项、网页专项 19 项通过。新增覆盖：

- 连续 15 轮各调用两个工具，第 16 轮回答成功：共 16 次决策、30 次工具执行。
- 16 轮均请求工具后停止，第 17 次决策不会发生；显式传入的其他上限仍生效。
- 从 `run_turn()` 经过实际模型适配、工具网关和计算工具执行，验证单工具、批量工具都使用同一 16 轮上限。
- 成功回答完整保留工具历史；超限失败不把未完成的本轮历史追加为成功会话。
- 原先依赖 31／61 轮的网页验收改为批量请求：15 批各读两页、第 16 轮回答；6 批免费读取及 6 批付费续办、第 13 轮回答。仍验证全部 30 次免费访问、30 次付费续办的目标和授权，工具额度测试不减少访问次数。

应用入口测试使用模拟模型响应与临时测试凭据，不调用真实模型 API。

全量回归：`python -m unittest discover -s tests`，300 项全部通过，133.885 秒。`git diff --check` 通过。

日志保存在 `.local/react-16-tests.log`、`.local/react-16-web-tests.log`，不进入 Git。首轮回归中两项旧网页测试依赖原 64 轮上限；批量调用适配后重跑全量通过，原始结果留在 `.local/react-16-initial-tests.log`。
