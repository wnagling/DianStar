# tmp 与 trash 实现及验收

日期：2026-11-02。项目：DianStar。此次没有提交或推送，不回收用户项目，也不安装新依赖。

## 已实现

- `tools/local/storage/` 提供10项工具：回收、列表、恢复、永久清理、状态续办、保留标记、到期清理，以及创建/查询/重新打开临时工作区。经现有 ToolGateway 注册与执行，没有新增 MCP 或权限开关页面。
- tmp 放在本机状态根的会话摘要/任务目录，read/write/bash/workspace_run 可实际使用返回的 repository，命令复用原项目会话开发环境。同会话以后能重新打开；其他会话拒绝，跨进程活跃使用锁防止并用或清理。
- trash 保存实际文件和目录，包括二进制、空目录、`.git`、未跟踪数据及整个目录内的不透明敏感子项。数据库仅保存元数据、校验、归属及恢复阶段，Windows 元数据使用当前用户 DPAPI；目录正文不声明加密，不返回模型。
- 同盘以移动原件为主；EXDEV 分支先完整复制并校验，然后把原件移到同盘保护中转位置，整批持久确认后才清理冗余原件。复制未完成时原件保持。中断记录与原文件事务、Git 历史分别管理，不混用编号。
- 多目标一次自然语言确认，恢复拒绝覆盖重建的原位置。恢复续办区分回收、恢复、永久清理和残留清理；永久清理及其续办明确说明不可恢复，保留现场模式不动文件。
- Hook 检查统一放在 `hooks/storage.py`，复用公共规则；预览及执行前重建计划。锁顺序为管理锁、固定顺序的仓库/祖先锁、数据库事务；等待审批时不持锁。后台禁用、基础操作依赖、撤销、强制审批仍有效。
- 默认30天：回收成功或任务释放时起算；正常轮结束经网关小批维护一项至多64 MiB/5000项的到期对象。较大内容支持明确调用清理到期副本。活跃、标记保留、冲突、操作残留和改变过的备份跳过自动清理；死进程临时目录获得新的30天宽限。不因空间不足提前清空。
- `app/storage_lifecycle.py` 负责收尾维护；`app/runtime.py` 重连复用管理器并释放使用锁；任务日志与橙色工具框保存实际结果和恢复编号。临时脚本的写入/运行不冒充正式项目改动或项目测试证据。

## 重点用例

- 文件夹带二进制、空目录、Git 元数据往返，整个临时 Git 项目含未跟踪文件往返；批量两个文件夹一次确认。
- 原位置重建时拒绝覆盖，指定新位置恢复；审批期间文件变化即停止。
- 第二目标移动失败时恢复先前目标；复制中断保留原件和不完整副本；协程取消等待补偿后再返回。
- 真实子进程在完成第一次移动后直接退出，新实例从持久记录恢复同批所有原位置。
- 恢复已发布、数据库完成标记写入失败时，后续核对识别已恢复状态；冗余副本清理失败可续办。
- 永久清理部分完成后续办；发现未知新增子项或改动时保留现场，重复续办不误走普通回收恢复。
- 恢复后的目标再次修改时保留回收站完整副本，避免删除最后的已知完整版本。
- 两个独立会话争用同一路径或以相反顺序回收同一批路径，无死锁且只有一项完整成功。
- 实际第二个进程持有临时目录使用锁时不能重新打开/清理；进程退出后能识别孤立活跃记录并设置宽限。
- 临时工作区写入、读取和真实脚本运行，任务结束释放；同会话重开、其他会话拒绝；原项目的公开构建变量实际传入临时脚本进程。
- 旧文件修改时间不缩短新回收期限；保留标记阻止过期清理；强制审批时后台维护跳过且不弹窗。
- DB故障、Hook异常、受保护单独路径、父子目标重叠和硬链接拒绝；实际 NTFS 附加数据流拒绝，附加内容仍在。
- 模拟模型响应通过真实 run_turn 调用批量回收与临时脚本流程，记录工具事件、恢复编号及任务释放，不额外制造项目复核成功。

## 边界与未验收

跨盘分支通过模拟系统 EXDEV 错误并实际执行字节复制、校验与清理测试；**未在不同物理磁盘实测**。模型编排使用模拟模型响应，不能当作真实模型长期自主选择这些工具的验收；本轮未调用外部模型或远程服务。

回收每批最多20个无重复/父子重叠的明确目标，总量4 GiB，每目标50000项。暂不支持符号链接、junction、硬链接、NTFS附加数据流、加密/离线文件；系统/应用自身数据及受保护单独凭据路径拒绝。跨盘不承诺 ACL、所有者、扩展属性等全部文件系统元数据完全保留。

到期清理依赖应用后续使用，不是独立常驻计时器；用户可标记保留或明确请求清理到期内容。shell、其他软件和不遵守锁的编辑器不会被自动拦截或转入回收站。持续磁盘不足、介质损坏、断电和外部并发改动仍可能妨碍恢复，系统保留或报告不确定状态，不保证任何条件下零丢失。旧文本事务日志和 Git 不随 tmp/trash 的30天规则自动删除。
