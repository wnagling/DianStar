# GitHub 账号登录（2026-10-30）

本轮完成 GitHub 收尾的第 1 项：登录入口、账号核验、持久化和退出。真实模型开发闭环、私有/跨 fork 场景及 GitHub API 的完整 Hook 覆盖继续按后续顺序验收。

## 使用入口

- TUI 输入 `/github`；或 `/config` → “GitHub 账号”。设置菜单增加账号项，仍不展示 MCP 开关或服务参数。
- “浏览器登录”：通过 Git 安装附带的 Git Credential Manager 打开 GitHub 授权页，页面中的授权应用名为 Git Credential Manager。成功后返回应用验证身份。
- “输入令牌”：在专用密码输入框输入访问令牌，先验证再保存。默认遮挡，开始验证和离开页面时清空，不加载已有令牌到输入框。
- “检查连接”验证当前账号；“退出登录”断开 DianStar 并清理本应用凭据。
- 命令行入口：`python -m dianstar --github login|status|token|logout`，无需模型 Key。`token` 使用隐藏输入，不接受令牌命令行参数；纯文本会话也可用 `/github status` 等操作。

登录不调用模型、不写会话历史。成功后下次提问自动使用该账号，不修改后台工具开关、项目范围、私有内容范围、审批策略或 Git 提交身份。

## 实现与边界

- `platform/github_credentials.py`：发现安装的登录组件，调用浏览器认证和系统凭据库；不搜索当前项目的同名程序，不继承模型 Key、追踪或不安全存储设置。组件从应用目录运行，凭据不放命令行参数，不回传原始输出或异常。
- 每次登录使用独立 `dianstar-<随机标识>` 命名空间，隔离已有 Git 登录和旧账号。Windows 强制使用系统凭据库；macOS 使用 Keychain，Linux 使用 Secret Service，无明文存储降级。后两种系统尚未实机验收。
- `app/github_account.py`：通过固定 `https://api.github.com/user` 核验身份，不跟随重定向。核验及系统保存/回读成功后才激活新连接；失败保留旧账号。浏览器登录可取消，最长等待 180 秒；取消只结束登录组件，不关闭用户浏览器。非交互组件超时会结束其拥有的进程树。
- `config/github_account.py`：`.local/github_account.json` 只保存状态、用户名和系统凭据库位置，拒绝 token 等秘密字段。原始凭据不写 `.env`、配置 JSON 或聊天记录。该文件处于受保护目录，也加入命令后的应用配置观察。
- `tools/mcp/credentials.py`：专用登录优先，没有账号文件时兼容旧环境凭据和明确允许的 Git 凭据后备。退出状态优先于全部后备来源；外部凭据保留，不会退出后又自动使用旧 Token。
- GitHub 官方组件只得到自身所需的 Token；Git 服务只得到用户名、应用命名空间和用于检测的指纹。GitHub HTTPS 操作使用此命名空间，不向其他主机发送此登录；SSH 身份仍独立管理。退出后 DianStar 的 GitHub HTTPS 操作不继续使用全局 Git 登录。
- 退出先保存停用状态，再清理系统凭据；清理失败时保留非秘密位置用于重试，连接仍保持退出。退出不等于退出 GitHub 网站或撤销 GitHub OAuth 授权，不删除其他 Git 工具的登录。

账号验证不代表具备某个仓库的写入、私有访问或管理员权限，具体操作继续检查。此机制也不提供操作系统隔离。
