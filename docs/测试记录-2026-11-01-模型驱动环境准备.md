# 模型驱动的环境准备验收（2026-11-01）

## 分工与实现

没有新增 C++/Rust/Java 的固定安装状态机或专用安装工具。模型根据任务与项目说明读取构建文件、判断平台和版本，检查当前工具，再决定复用、激活、说明缺失或在授权内提出安装。system prompt 明确：找不到命令不等于未安装，不盲目重装，不一律选最新版；项目文档只提供技术信息，不授予安装、提权或执行脚本权限。安装/激活后核验实际版本及任务相关的最小编译/运行，不把安装器成功等同项目成功。

Bash schema 明确每次都是新进程：上次 cd/export/source/激活不自动持续；可同一次激活后构建，或每次用显式环境。前台最多600秒、无交互/后台句柄；遇到重启、系统交互或超过上限的安装任务，应说明限制并保留进展，不能用后台启动绕开进程管理。

通用后端补齐：

- `platform/command_environment.py` 统一构造公共构建环境，允许宿主的 JAVA_HOME、编译器/SDK、Cargo/Rustup、虚拟环境、包含/库路径和编译标志等非敏感变量进入子进程；检测到凭据的值省略，未开放凭据及启动注入环境。
- `bash` 与 `workspace_run` 增加可选 `environment` 对象：仅允许明确列出的构建变量，最多24项、单值4096字符、总值16384字符；值是字面文本，不展开 `$PATH`，拒绝换行/NUL及未知键。覆盖值复用 before_command Hook 检查。
- 按同一份命令环境的 PATH 定位程序、绑定程序状态，确认后重新检查；环境变化则停止。非空覆盖不享受常规验证默认免确认，后台明确策略仍生效，确认摘要显示本次覆盖范围。
- 覆盖只作用于当前子进程，不修改宿主 `os.environ`、系统/用户配置，也不保存为会话激活状态或从历史恢复授权；输出仅列覆盖/构建变量名，不回传完整宿主环境。
- argv 程序无法定位时返回 `executable_not_found`，明确提示也可能是 PATH/激活问题；不是自动安装指令。Bash 的命令找不到仍按真实脚本退出结果判断。

并发回归暴露了已有台账首次创建的 WAL 初始化竞争。本轮用统一系统锁保护 `journal-schema` 的短初始化/迁移阶段，实际任务与文件写入仍可并发；Git 的恢复状态读取也协调该锁。不是通过预热测试数据库掩盖问题，保留了并发首次使用的新用例。

## 真实模型与真实 JDK

在隔离 Java 小项目中，从命令 PATH 中临时去掉 JDK 目录；项目 README 记录本机已有 JDK 候选位置与版本要求。应用没有新增语言专用安装流程，模型使用通用读取/命令工具：

1. 实际得到 `executable_not_found`，区分默认 PATH 不可见与未安装。
2. 读取项目要求，核对已有 `C:/JDK21/bin/javac.exe` / `java.exe`，查得 JDK 21.0.6。
3. 通过本次 `environment` 传入 JAVA_HOME/JDK_HOME 与 PATH，执行 `javac -d build src/Main.java`，退出0。
4. 通过同样的单次环境执行 `java -cp build Main`，退出0、输出 `environment-ready:42`，产生真实 Java class 文件。
5. 报告环境只对本次命令生效。源码未改，未安装软件，没有修改 Git 索引或操作远程；额外查询了只读 Git 状态。

**验收夹具的拒绝与结果分别记录。**原端到端脚本假设“所有可选诊断请求都应获得批准”，因此其严格断言没有通过；夹具拒绝了可选 Bash 环境/目录探测，但模型没有执行这些被拒命令，随后通过获准的程序定位、版本查询、编译和运行完成任务。没有为让测试通过而放宽生产权限。
