# 本地工具与 MCP 解耦验收

日期：2026-11-03。

## 本轮实现

- 本地文件、命令、开发环境、文件恢复和 tmp/trash 改用 ProjectContext。这个对象只包含独立项目策略、已接入目录、本轮授权和应用提供的凭据检测回调，不接收 MCPTools，不导入 Git 服务。
- `.local/projects.json` 保存本地策略和记住的目录；`.local/mcp.json` 继续管理 Git/GitHub。缺少独立配置时迁移旧的明确只读限制及已批准目录，不因 Git 关闭而关闭本地工具。独立配置损坏则停用本地工具；旧 MCP 配置损坏且尚无独立配置时保守只读。
- open_project 支持普通目录和 create=true。创建不覆盖已有目标，不自动 git init；审批期间配置、父目录身份或目标变化会停止。临时打开也应用新的只读限制，不借打开项目解除限制。
- 选中本地目录不向上扩大为 Git 父项目。Git 仓库发现移到 platform/project_paths，版本管理连接独立处理。
- 文件发现使用有界的项目内忽略规则，不调用 Git，不读取用户全局排除配置；支持根目录/子目录 .gitignore、普通 .git/info/exclude 的常用否定、目录、锚定与通配规则。规则链接、无效编码、超限或目录不可读时明确报告检查未完成。
- 通用安全 Git 查询移至 platform/git_queries，Git 服务和命令白名单查询分别复用，保留原配置限制、进程超时与输出边界。Git reader 路径保留小型兼容导出。
- MCP 重连保留本地注册、读取快照、恢复管理器及会话环境。tool_status 提供实际本地/可选服务状态；旧 mcp_status 仍可诊断连接。
- system.md 分为本地项目、文件、临时/恢复、并发复核、Shell、开发环境、Git、GitHub/MCP。独立工具仍共用 ToolGateway、Hook、资源锁和 LPAC，不引入权限页面或新依赖。

## 验收环境

使用已安装依赖的 Python 3.12、标准库 unittest；没有安装 pytest。临时夹具在仓库 `.local/test-tmp`，文件状态使用独立 `.local/project-*` 目录，不使用日常恢复数据。不读取真实账号或请求外部模型服务，不修改用户仓库的 Git 历史。

Windows DPAPI 与应用容器用例需要在允许这些本机接口的普通进程运行。首次受限测试进程出现 DPAPI 错误，随后使用允许接口的测试进程及全新测试状态重跑；没有关闭产品安全检查。初轮两条旧断言仍要求 Git 关闭后隐藏本地工具，已按本轮独立策略更新。

## 实际命令和结果

共同设置：

```powershell
$env:PYTHONUTF8='1'
$env:TEMP=Join-Path $PWD '.local/test-tmp'
$env:TMP=$env:TEMP
# 每组使用不同的绝对测试状态目录
$env:DIANSTAR_FILE_STATE_ROOT=Join-Path $PWD '.local/project-acceptance-final'
```

最终专项：

```powershell
python -W error::ResourceWarning -m unittest tests.test_local_projects tests.test_project_access tests.test_architecture tests.test_tool_policy tests.test_mcp tests.test_file_tools -q
```

结果：78 项，全部通过，41.556 秒。包含真实普通目录读写、编辑、补丁、移动、撤销、忽略规则、实际隔离 Python/PowerShell、审批时切换只读、无 MCP 运行、重连后使用旧读取快照、配置损坏与迁移，以及独立解释器中禁止导入 MCP/app/UI 后仍可构建本地工具。编排和模型响应为模拟。

并发与集成：

```powershell
python -W error::ResourceWarning -m unittest tests.test_all_tool_concurrency tests.test_orchestration tests.test_mcp_concurrency tests.test_security_hooks -q
```

结果：41 项，全部通过，44.308 秒。覆盖真实文件/命令资源冲突、独立操作并发、审批等待、跨轮依赖、逐项通知、会话编排和 MCP 共享连接。

较大范围回归：

```powershell
python -W error::ResourceWarning -m unittest tests.test_local_projects tests.test_project_access tests.test_architecture tests.test_mcp_startup tests.test_git_operations tests.test_git_engineering tests.test_git_publish tests.test_host_policy tests.test_host_safety tests.test_host_lifecycle tests.test_bash_tools tests.test_session_environments tests.test_command_environment tests.test_environment_workflow tests.test_hook_registry tests.test_secret_workspace tests.test_change_review tests.test_scheduler -q
```

该组运行 231 项，215 项通过、15 项跳过、1 项新增夹具错误，552.260 秒。夹具误用了 API_KEY 而非 DEEPSEEK_API_KEY，业务流程未开始；修正后已纳入上述最终 78 项通过结果。15 项跳过来自 Windows 不兼容的历史 Bash 用例与平台条件，不计作通过；真实 PowerShell/LPAC 由 host_safety、host_lifecycle 和本轮普通目录专项实际执行。没有为修正夹具重复运行整组已通过用例。

另一次文件/恢复/回收与旧策略回归共162项，其中160项通过；两条旧的 Git 关闭断言更新后已在较大范围回归通过。原始日志保留本机 `.local/project-refactor-regression.log`、`.local/project-final-regression.log`、`.local/project-acceptance-final.log`、`.local/project-concurrency-acceptance.log`。

## 范围和限制

- 本轮未执行完整测试发现，也未调用真实 DeepSeek、远程 GitHub 或执行远程发布；离线编排不能代替真实模型验收。
- 忽略规则面向当前项目的常用语义，不声称等同 Git 的全部全局配置与扩展；固定受保护路径、构建/依赖目录及隐藏文件过滤仍独立生效。
- 文件事务、Git 历史、回收站仍各自恢复，不将普通命令修改说成可自动逐文件回滚。命令隔离不兼容时仍拒绝，不降级为宿主执行。
- 本记录描述开发验收阶段；后续提交与远程发布以 Git 记录为准。原有本机 IDE 配置保留，不纳入本轮发布。
