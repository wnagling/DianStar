## 用户要求与行为

用户明确要求 Git 提交、推送等工程能力默认可用，不需要先进入 /config 开启权限。默认策略现为“工具可申请，执行逐次确认”，不是预先授予执行权限。

- Git 修改、项目文件编辑/单文件删除和命令默认可申请；git_write_enabled/workspace_write_enabled 缺省或 null 表示默认逐次确认，true 同样逐次确认，false 明确禁止。
- GitHub 首次配置可信程序和凭据后，写入与管理范围缺省/null 自动取当前项目 origin 与允许访问范围的交集；空列表明确禁止，自定义列表保持限制。额外只读仓库不会自动成为写入/管理范围，账号 Token 权限不扩大应用范围，管理请求仍检查真实 admin 权限。
- clone/init/worktree 默认可对具体目标申请创建，不要求先信任整个父目录；已配置的创建范围、路径/链接检查、目标状态重查和单次令牌继续有效。
- 每个编辑、命令、暂存、提交、推送或远程管理操作分别展示预览并确认。用户拒绝、没有确认入口、权限不足或状态变化时不执行。其他操作不能复用该次批准。
- 配置界面将“启用写权限”改为默认逐次确认/逐次确认/禁止，GitHub 支持当前项目默认范围、自定义范围或禁止。模型 Prompt 同步说明无需先开启权限。
- 私有内容访问、GitHub 程序安装/登录、Git 凭据后备保持原有配置要求；没有默认下载程序、使用额外账号凭据或开放全账号仓库。
