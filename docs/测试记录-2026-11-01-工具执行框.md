# 工具执行框验收

日期：2026-11-01。

## 行为

聊天中新增与模型思考独立的“工具执行”框。默认显示最多4项进行中或最近完成的操作，标题显示总项数、进行中与失败数量；点击标题查看列表，点击每项“详情”查看工具名、真实调用 ID、参数及有限命令输出。窗口变窄后重新排版。实际结果到达即更新，模型下一轮仍等待整批结果，不改变原有调度方式。

状态区分处理中、完成、失败、未执行、取消、结果待核对与事后检查需核对。开始表示应用已接收这项调用，包括预检和审批阶段，不能据此认定命令已经运行；成功只来自真实结果。取消或异常结束后没有收到结果的条目保留“结果待核对”，不伪造成功或保证未发生副作用。框本身不会请求额外确认。

## 数据与边界

- `app/tool_events.py` 使用统一 ContentScanner 对展示用文字脱敏，先处理参数值再编码 JSON。只复制受限参数字段，省略文件正文；命令输出最多约2800字符、参数显示最多约3800字符。未知机密仍受现有检测规则的识别边界限制。
- 每项显示事件有请求内独立编号、会话标识和工具调用 ID。UI 校验会话、本轮标记和回调有效性，取消后旧回调不能进入下一轮。
- 每轮显示记录最多256项。成功轮次的显示副本保存在会话助手消息的 `tool_activity`；不加入发给模型的消息，不保存授权。旧格式保持兼容，历史成对工具消息仅解析为展示，不触发执行。
- 失败/取消轮次不新增虚构问答，当前界面保留已收到的工具状态；独立任务数据库仍保留执行凭据。重开会话时能恢复的显示范围取决于已保存的问答/工具消息。
- 默认摘要不显示原始脚本；详情以纯文本显示，不把工具输出解释为界面命令或点击操作。新框不改变网关、后台禁止、审批、Hook、文件恢复或ReAct上限。

## 验收

先运行已有聊天、会话与运行时用例：38项通过。新增专项覆盖参数及输出脱敏、输入边界、拒绝/失败/取消/审计不完整状态、并发逐项更新、流式回答和思考共存、鼠标展开、历史恢复、跨会话及上一轮回调隔离。真实运行时接线用例通过模拟流式模型响应，实际调用计算工具，再检查工具框与保存内容。

较广的11模块回归运行139项。首次发现流式测试夹具误用了非流式响应，修正夹具后暴露两项界面问题：缩放没有使用聊天区的新宽度，以及全局重排清除了原有选区。将重排通知限定为聊天控件实际宽度变化后，界面和会话范围完整复验：

```powershell
python -W error::ResourceWarning -m unittest tests.test_tool_panel tests.test_tui tests.test_app_services tests.test_conversations -q
```

结果：`Ran 48 tests in 17.382s`，`OK`。其中包含90×30和52×20两种尺寸、实际缩放、原有文字选区/复制回归。其余编排、协议与并发模块在139项运行中通过；没有把有失败的139项执行写成全通过。原日志保留在 `.local/tool-panel-final.log`、`.local/tool-panel-accepted.log`，修正后日志为 `.local/tool-panel-reflow.log`。

取消后的状态栏提示单独补验：`tests.test_tool_panel.ToolPanelUITests.test_cancellation_keeps_unknown_results_and_stale_callbacks_cannot_enter_next_turn`，`Ran 1 test in 0.234s`，`OK`，日志 `.local/tool-panel-cancel.log`。

本轮使用临时会话/状态目录、模拟模型响应与真实本地工具接线，没有请求真实模型 API，也没有重新执行历史命令、安装依赖、提交或推送。需重新启动已运行的 DianStar 才会加载本轮修改。
