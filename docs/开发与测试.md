## 离线测试与后续方向

Windows 当前使用强制 AppContainer：复杂命令为 `shell`（PowerShell），简单构建、测试为 `workspace_run`。原 Git Bash 的 Windows 用例会跳过，应运行新的真实隔离验收，不能把跳过算作功能通过：

```powershell
python -W error::ResourceWarning -m unittest tests.test_host_safety tests.test_host_lifecycle tests.test_host_policy -q
```

测试仅在临时夹具尝试越界写入、删除、子进程和网络访问；系统盘、驱动目录只做不执行的预检。需普通用户进程、可用 Windows 应用容器及本机 Python/PowerShell，不安装依赖或修改系统目录权限。同项目环境检测与命令共用独占锁，不同项目可并发。SDK权限不满足时验收明确拒绝，本机系统持有的 JDK 未验收编译成功。实际命令、结果及边界见 [系统保护与 PowerShell](./测试记录-2026-11-03-系统保护与PowerShell.md)。

tmp/trash 专项用 `python -W error::ResourceWarning -m unittest tests.test_managed_storage -q`，应用联动加 `tests.test_orchestration`，原文件恢复回归加 `tests.test_file_tools tests.test_file_recovery tests.test_file_transforms`。测试覆盖真实目录/二进制/.git、批量补偿、进程退出、跨进程活跃锁、相反顺序并发、过期/保留/强制审批、NTFS数据流拒绝及临时脚本真实运行。跨盘分支以模拟 EXDEV 加真实字节复制验收，不等于不同物理磁盘实测；模型编排用模拟响应，不等于真实模型验收。使用绝对 `DIANSTAR_FILE_STATE_ROOT` 和临时测试目录，不回收用户项目。结果见 [tmp 与 trash 记录](./测试记录-2026-11-02-tmp与trash.md)。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

现有测试主要采用 Python 标准库 unittest，不需要额外安装 pytest。离线测试使用模拟的模型与服务响应，部分工程测试运行真实 Python/Git 进程和本机测试远程，不需要真实 Key；通过这些测试不代表真实模型和外部服务调用已验证。当前已实现文件工具及 Git/MCP 工程能力，范围见 [工具说明](./工具说明.md)，待办以 [todo.md](../todo.md) 为准。

要检查全球 100 个城市的真实天气查询，在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m scripts.check_weather_cities
```

脚本只调用 Open-Meteo，不读取 `.env`，也不向 DeepSeek 发送请求。它检查返回地点的国家代码、当地日期以及气温字段，把逐项结果写入 `.local/weather_city_report.json`。少量试跑可加 `--limit 3`；任一城市失败时脚本以非零状态退出。联网服务暂时不可用也会记为错误，不能据此断定程序逻辑有误。
