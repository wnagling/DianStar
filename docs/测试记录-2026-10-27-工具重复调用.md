# 移除相同参数工具调用拦截

日期：2026-10-27。

## 问题与修改

原 `core/loop.py` 将整轮出现过的工具名与 JSON 参数放进集合，再次出现就报错。该判断无法感知文件、测试、远程状态或服务是否变化，会阻止正常复查和重试。

移除调用集合和去重异常。同一批及跨模型轮次的同名同参数调用均按正常路径执行，取得新的结果，不复用先前结果。循环上限错误改用与服务商无关的 Agent 名称。

运行时提示词明确允许复读、修改后复查、重跑测试、轮询和有理由的重试。保留总循环上限、每批最多 8 次调用、工具额度、参数检查、权限撤销、逐次审批和 Git 执行令牌防重放行为。

## 验证

先添加回归用例，在旧实现下复现失败；修复后循环专项 10 项和 MCP 专项 21 项通过。

覆盖：

- 相同参数执行两次得到独立新结果；第一次失败后相同参数可重试。
- 读取临时文件、修改、再次读取同一路径，看到新内容。
- 实际运行临时 Python 检查、修复代码、运行相同命令，退出码从 1 变为 0。
- 同一批相同参数但不同调用 ID 均执行，并分别保留结果。
- 不结束的重复调用仍在总循环上限停止，原有批量数量上限不变。
- 每次调用重新检查授权；单次授权不能复用，第二次敏感调用重新审批，拒绝后不执行。
- 完整应用与模型适配链路中，相同数字工具请求执行两次，两个调用 ID 及对应结果完整进入历史和后续模型请求。

文件与命令场景使用回归测试适配器和临时目录，不代表产品新增了文件工具或通用命令执行能力。模型链路使用模拟响应，不依赖真实 API 或付费调用。
