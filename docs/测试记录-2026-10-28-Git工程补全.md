## 使用入口和日常配置

- mcp_status 始终注册，未配置时也能报告配置路径和缺失状态，避免模型根据旧会话猜测工具不存在。
- get_mcp_configuration 读取配置；configure_mcp 展示修改前后设置，经用户确认、状态重查后原子保存，并在当前提问内重连和刷新模型工具清单。服务器程序和凭据仍通过配置界面设置。
- clone/init/worktree_add 成功后，服务端及客户端立即接入新仓库；应用将新仓库保存至当前 .local/mcp.json。配置并发变化或保存失败会明确返回 configuration_saved=false，不冒称撤销已完成的 Git 操作。
- 新配置字段：git_workspace_roots、workspace_write_enabled、github_admin_repositories、github_use_git_credentials。旧配置均保持空范围或关闭；私有访问仍须独立启用。
- MCP 配置页面已加入创建目录、项目编辑/命令开关、管理仓库和 Git 凭据选项，保持密码遮挡、离页清空及固定可见按钮。

## 关键验收结果

1. 真实 MCP 克隆临时仓库后，同一轮可直接查询新仓库；拒绝 clone 不创建目标目录，已有目标不被覆盖。
2. run_turn 在同一段对话内确认接入设置、启动实际 Git MCP、初始化项目并读取状态，新仓库保存到临时日常配置。此项模型响应使用离线替身，MCP 服务及 Git 操作是真实执行。
3. 本地配置只允许仓库级已知键，不提供任意执行键、凭据键或全局写入；配置改变、令牌重放、越界、敏感路径和外部 merge 驱动均拒绝。
4. 快进更新实际新增远程文件；分叉时本地 HEAD 和工作文件保留。检查点不清空用户文件或索引，可单独恢复被 Agent 改动的文件，同时保留其他文件。
5. merge 冲突解决后继续产生正确的两个父提交；rebase 冲突时允许暂存 detached HEAD，继续后回到原分支。merge/rebase 中止均恢复原提交与文件。
6. 远程分支删除核验目标 SHA 并保留 main；force-with-lease 在预览后远程发生变化时拒绝，不覆盖协作者提交。普通 push 仍默认拒绝非快进。
7. GitHub 管理测试覆盖空描述清除、完整设置回读、保留未修改的管理员/审批/检查规则、官方 permission 字段、待接受邀请撤回、拒绝确认、范围外仓库及写入结果不明时不重试。

## 实际边界

- 文件/命令与 MCP 仍是应用层授权，未实现操作系统沙箱；测试和构建脚本拥有当前用户权限。命令使用 argv，无隐式 shell；后台任务管理、交互式终端尚未实现。
- 不支持无条件 force push、hard reset、递归 clean；恢复通过明确文件和检查点进行。未实现完整 submodule/LFS/partial-clone 工作流；已有执行过滤器或非受管元数据不会自动放行。
- 检查点排除敏感、忽略文件及不支持的链接/子模块，不保证回滚数据库、已发出的网络请求、远程推送或部署。
- 远程配置重查与 HTTP 写入不是统一事务；结果不明会停止并要求回读。Git 远程删除和历史替换通过明确 SHA 的 lease 额外限制并发覆盖。
- 所有代码、测试和文档仍在本地，未提交或推送；用户已有编辑器文件不纳入本次交付。
