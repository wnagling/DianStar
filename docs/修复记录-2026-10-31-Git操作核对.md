# Git 操作核对与来源核验分离（2026-10-31）

## 问题

最终回答中的 Git 远程地址被统一视为资料引用。即使推送已核对远程提交，仍可能显示“未见成功检索或读取记录，引用未核验”，混淆发布结果与网页读取状态。

## 本次实现

- 新增 `dianstar/evidence/git_operations.py`，与原有资料来源台账分开记录 Git 操作。`app/runtime.py` 接入 Git 工具结果，程序生成 `operation_evidence`；不采信文本中的成功字样或外部自带的同名字段。
- 远程配置只说明地址来源。推送与单次确认发布需工具、操作、仓库、远程、分支匹配，成功标记、远程核对标记和完整提交号有效，才标为该次远程提交已核对。Windows 路径比较兼容斜杠和大小写差异。
- Git 服务返回实际远程地址；适配层保留批准预览中的目标供失败或连接中断后说明。内部单次令牌仍只用于服务执行，不交给模型。失败不复用同分支旧成功；已发生的本地提交等部分进度继续按原结果报告。
- 最终回答将已登记的 Git 目标放入“Git 操作核对”，不再因未读网页把该目标标为未核验资料。支持 GitHub HTTPS、常用 SSH 仓库地址和 `.git` 后缀的对应关系，仅登记已核对的提交链接及对应分支链接，不把 README 等下级内容自动视为已读。
- 实际搜索、网页读取及读取失败仍按原资料来源台账处理；同一链接有操作与读取记录时分别说明。无链接回答不新增链接或核验段落。
- 历史恢复只读取成对的工具调用和结果，明确标为历史操作，不能当作本轮重新核对；历史提交记录也不代表当前分支位置。旧会话若缺少新增的目标字段，不能凭空补出远程已核对结论。
- 同步更新运行时提示词、工具说明、安全机制及待办；没有新增审批弹窗，也没有为生成操作记录额外访问网络。

## 验证状态

新增 `tests/test_git_evidence.py` 的回归用例，覆盖配置地址、推送/发布成功与失败、仓库/分支/远程不匹配、Windows 路径归一化、未读 README、真实网页读取失败、历史恢复、SSH 与链接别名、无效地址、连接中断保留目标及内部令牌不外露；现有发布用例增加服务目标字段断言。

初次实现时只修改代码、补充用例并阅读差异，未运行测试。用户随后澄清开发修复可以按需测试，现已补做相关离线回归，具体命令、结果和环境限制见 [回归记录](./测试记录-2026-10-31-账号与Git核对回归.md)。本轮没有访问真实 GitHub 服务，也没有提交或推送当前项目。
