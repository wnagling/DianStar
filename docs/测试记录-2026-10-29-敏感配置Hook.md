## 目标与实际实现

区分本地运行配置与 Git 发布：普通项目配置正常使用；运行所需的凭据可以在用户明确选择仅本地保存后写入项目配置，但不能借此发布。应用自己的凭据及 `.local`、`.git`、`.aws`、`.ssh` 等受保护目录不允许普通文件工具覆盖。

- `security/content_guard.py`：统一路径分类、内容检测、脱敏和不含原值的检测结果。识别应用已知凭据、GitHub 令牌格式、私钥，以及配置字段中的疑似硬编码凭据；单有字段名、变量引用或随机字符串不视为凭据。明确占位值和模板按规则排除，高可信格式和已知真实凭据不受模板放行影响。
- `security/hooks.py`：应用拥有的固定 Hook，包含 `before_write`、`before_stage`、`before_commit`、`before_push`、`after_command`、`after_clone`。工具在能取得实际字节的位置调用；不加载仓库提供的脚本，没有模型可修改的检查开关。后台免审批策略不会跳过这些检查。
- `tools/local/workspace.py`：在预览前及真正写入前检查最终完整内容。`workspace_edit.local_only` 只用于用户明确要求仅在本机保存的配置，仍按后台审批策略确认；不能写入应用自己的 `.env` 或受保护目录。差异中的新旧凭据都遮挡。此参数不自动修改 `.gitignore`、停止跟踪或授予提交权限。
- `tools/mcp/servers/git/security.py`：读取真实 Git blob、索引和提交树，批量获取对象并复用历史中相同的 blob，避免只检查截断差异或逐文件启动大量进程。
- `security/workspace_audit.py`：命令执行前后比较项目文件和应用配置快照，报告新增、修改、删除及不完整检查；不自动回滚。排除依赖目录、Git 元数据和一般仓库外文件，应用配置作为单独受保护项观察。

## Git 发布关口

1. 暂存前检查所选工作区文件；实际执行前重验，拒绝时暂存区不变。
2. 提交前检查完整索引内容；执行时用已经批准的私有索引构造提交树，再对这棵不可变树重验，之后才创建提交和更新分支。工作区含有未暂存的凭据不会被误认为是已提交内容。
3. 推送前查询目标分支的真实远程提交，不依赖可能过期的本地跟踪记录。检查待上传区间的每次提交树和提交说明，包括后来删除的文件。远程提交本地不可得时保守扫描全部本地可达历史；首次推送同样扫描全部可达历史。
4. 执行推送前重新核对远程分支并扫描固定的待推送提交；确认期间远程变化即停止。Git 原有精确参数、一次性令牌、状态绑定和正常推送/force-with-lease 规则继续有效。
5. 误暂存的敏感文件允许明确取消暂存；已经跟踪的敏感文件允许提交删除跟踪的变更。保留本地文件与停止 Git 跟踪是两个动作，工具不自动替用户执行清理，也不改写已经存在的历史。

真实 `.env`、`.env.*`、`*.env`、凭据路径和私钥路径默认受保护；`.env.example`、`.env.sample`、`.env.template` 允许作为不含凭据的模板。本仓库 `.gitignore` 增加相应环境文件模式及模板例外；其他项目不会被自动修改。已经跟踪的文件不能仅靠 `.gitignore` 停止跟踪。

## 凭据、报告与限制

- Git 服务只接收应用已知凭据的 SHA256 指纹，既有模型和 GitHub 原始凭据不作为扫描参数传给它；Git 命令子进程也不继承指纹环境变量。指纹用于识别原样出现的文本候选，不代表可以识别编码、拆分或加密后的内容。
- 检测结果只保留文件、行号、类型和置信级别，最多返回 30 项，不包含命中的值或片段。明确格式与上下文疑似项分开标记；发布关口均停止，不能简单点确认绕过。Git/MCP 查询内容、文件差异及命令输出也按规则脱敏。
- 内容检查有边界：单文件最多 2 MiB，一次最多 32 MiB、5000 个文件版本；推送最多 500 个待检查提交，Hook 检查有 20 秒时限，外部 Git 查询另有自身超时。达到限制、扫描异常、缺失对象或浅克隆历史不完整时停止发布，不默认为通过。
- 支持 UTF-8 及带 BOM 的 UTF-16 文本检查；二进制中只可能识别可见文本模式，不做压缩包展开、编码还原或所有服务令牌的穷举检测。不会联网验证令牌真伪，疑似项可能需要人工核对。
- 克隆后只检查当前检出的提交树并报告风险；不扫描完整克隆历史，也不自动删除或修改仓库。推送时再按发布范围检查历史。
- 命令的检查是事后观察。命令可能已经写文件、访问仓库外路径或发送网络请求；检查报告不表示这些行为被阻止或撤销。通用命令、外部 Git 操作、进程并发修改和数据外发仍需要操作系统隔离解决，不能宣称 Hook 构成沙箱。
- 未实现通用用户自定义 Hook、持久化安全报告界面或 GitHub 端推送保护。仓库自带 Git hooks 继续禁用；本实现不依赖它们。

令牌格式参考 [GitHub 官方身份认证说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github)；模式检测的能力边界参考 [GitHub 官方 secret scanning 模式说明](https://docs.github.com/en/code-security/reference/secret-security/supported-secret-scanning-patterns)。本地规则并非 GitHub Secret Scanning 的完整实现。
