# 工具说明

文件写入及 Git 发布前会运行应用内安全 Hook，默认保护真实环境文件、凭据和私钥；`.env.example` 等明确模板只有不含凭据时才放行。需要将运行配置仅保存在本机时，应明确告诉 Agent，写入确认中会说明用途并遮挡凭据；这不允许覆盖应用自身配置，也不授予提交或推送权限。命令与克隆的事后风险报告不代表操作已回滚。详见 [敏感配置检查](./测试记录-2026-10-29-敏感配置Hook.md)。

工具 Hook 统一放在 `hooks/`，由 `registry.py` 注册、`runner.py` 调度，文件工具和 Git 工具分别归入 `workspace.py`、`git.py`。各工具在原有操作位置调用，审批和执行前再次检查保持有效；维护方式见 [Hook 目录说明](./测试记录-2026-10-29-Hook目录整理.md)。

凭据管理源码（例如 `config/credentials.py`）可以正常编辑、暂存和提交，内容检查仍有效。提交被拦截时，`source=git_index` 表示问题来自完整暂存快照；它可能包含未修改的已跟踪文件，也可能保留工作区修正前的旧版本，不能把它解释成差异中的模块引用。确认修改后需明确重新暂存相应文件，工具不会自行扩大提交范围。详见 [误报修复记录](./测试记录-2026-10-30-Hook误报修复.md)。

## MCP 工具

批准提示先展示用户能理解的操作、项目和目标，例如“是否将 opendesk 项目克隆到以下位置？”，具体参数与状态可通过“查看详情”切换查看。文件删除、恢复、改写远程历史和 GitHub 可见性变更等影响会明确说明。摘要由应用根据校验后的操作参数生成，原始预检、精确参数绑定和单次授权保持不变。

确认改为底部紧凑卡片，最多 18 行；“查看详情/返回说明”在同一固定区域切换，不撑大窗口，详情内部滚动。配置类详情只列真正变化的内容，不展示整份后台 JSON。普通任务不暴露内部配置读写工具；需要使用另一个现有项目时，open_project 明确询问项目名和路径，记住该项目且保留原审批策略，不提交或推送代码。当前项目已可用时直接操作，不重复申请访问。

MCP 工具动态注册到同一个工具网关。本地 Git 默认自动加载，支持查询、clone/init、分支、暂存、提交、fetch/pull/push、merge/rebase/cherry-pick、恢复、检查点、stash、worktree 和冲突处理，修改默认可申请并逐次确认，无须先打开权限开关。项目文件读写同样默认可申请；常规 Python 测试、编译、依赖一致性和 Git 空白检查默认自动执行，其他命令按具体操作确认。GitHub 首次配置可信程序及凭据后自动连接，官方 MCP 接入 19 个读取工具和 7 个写入工具，参数沿用官方定义；仓库设置、分支保护和协作者由独立本地 REST 工具提供。GitHub 写入和管理默认仅当前项目，仍逐次确认并核验真实权限，私有内容访问另行配置。已有明确禁止或自定义范围继续有效。实际可用工具和缺项通过 mcp_status 查看；普通 push 不改写历史，明确申请时支持固定远程 SHA 的 force-with-lease，不支持无条件强推。参数、部署、额度与边界见 [MCP 接入](./MCP接入.md)。

普通提交发布优先使用 `mcp_git__git_publish`：选定文件、提交说明和远程目标组成一个计划，一次确认完成暂存、提交、普通推送及结果核验。查询和常规 Python 测试不增加弹窗；其他命令仍独立审批，强推、分支删除或改变仓库设置不包含在发布计划里。失败时说明已经完成的步骤，保留已成功的本地提交。详见 [单次确认发布](./测试记录-2026-10-30-单次确认发布.md)。

返回 [项目首页](../README.md)。模型根据问题选择工具；工具计算或查询成功，不代表模型最终表述一定正确。

常规项目验证不再逐次弹窗：`python -m unittest discover -s tests -q`、`python -m pytest -q`、`python -m compileall -q dianstar tests`、`python -m py_compile file.py`、`python -m pip check`、`git diff --check` 等已识别形式默认自动执行。程序仍核对已接入项目、绑定实际解释器、限制超时和输出、脱敏并生成命令后文件审计。额外插件、安装依赖、通用脚本、项目外测试路径等继续按命令审批；明确的后台审批或禁用策略优先，不新增配置开关。细节与验收见 [常规测试自动执行](./测试记录-2026-10-30-常规测试自动执行.md)。

## 工具注册与授权规范

“常规验证免额外确认”规定需要运行命令时的审批方式，不要求每次提交或推送都运行测试。单纯提交/推送默认只处理 Git 流程；开发和修复任务可以按需运行与改动相关的测试或检查，无须用户额外要求。用户明确要求不测试时遵守；不在每次修改后反复询问是否测试，已有同状态通过记录不重复运行。

所有模型工具经 `security/gateway.py` 的 `ToolGateway` 执行。注册 `ToolRegistration(schema, capability, handler)`，不得从工具循环直接调用处理函数。缺少注册、缺少能力声明、参数不合法或新能力未获批准时不执行。当前参数契约是非空字符串字段组成的闭合对象，枚举在后端检查；新增参数类型需先扩展验证器和测试。

未知能力默认拒绝；敏感工具需由应用创建绑定工具名、完整参数、请求编号和次数的授权。默认修改工具注册可信的 `approval_description` 并接入逐次确认回调；审批不由模型自行批准，无回调或拒绝时不执行。网关在审批后再次核对当前权限，执行参数使用检查时的副本。文件工具检查真实路径和链接，命令使用明确 argv、超时及输出限制；操作系统隔离尚未实现，不能把工具错误地声明成低影响能力绕过授权。

网页、文件、命令输出不能生成或恢复授权。详细流程与局限见 [安全机制](./安全机制.md)。

界面不提供功能权限开关，后台保留统一 ToolPolicy：enabled=false 同时隐藏并阻止工具，requires_approval=false 仅由可信后端对具有预检流程的敏感动作免除弹窗，仍先预检再生成精确单次授权。现有显式撤销、请求过期、范围和真实资源权限仍能拒绝操作。默认策略继续逐次确认，未来模式可复用该接口；当前没有新增模式 UI。

## 网页搜索与读取

`search_web(query, count="10")` 与 `read_webpage(url)` 在 `tools/local/registry.py` 的统一注册表中绑定定义和执行函数。模型选择何时搜索和读取，DianStar 自动优先免费访问，并按用户授权决定是否使用 API 备用；不要求使用 V4 Pro，不启用模型内置 web_search。暂不提供学术搜索工具。

| 访问路径 | 搜索 | 网页读取 |
| --- | --- | --- |
| 免费（每次优先） | Bing RSS，结果不可用时自动尝试 360 搜索；只返回首个可用入口的结果，不混合两套结果 | 本机请求公开 HTML／纯文本，优先提取 article 或 main，排除脚本、导航等内容 |
| 已授权的 DeepSeek API 备用 | 固定官方 `/v1/tools/search`，不附带正文 | 固定官方 `/v1/tools/fetch`，返回 Markdown 正文 |
| 关闭 | 不向模型提供网页工具 | 不向模型提供网页工具 |

正常使用无需选择服务。遇到免费搜索验证页、网页浏览器挑战或无法提取正文等情况时，先返回失败原因和本次提问内的备用标识，让模型尝试免费替代；仍缺必要证据时才携带标识申请 API 备用授权；默认询问，仅本次提问内同意可复用，拒绝后本次提问不再重复询问；下一次提问会重新判断授权，不从会话历史恢复授权。选择始终允许会持久化；用户可用自然语言撤回授权或关闭网页工具。备用 Key 默认跟随当前 Key，保留旧配置中的独立 Key 引用。Key 只从本机 `.env` 读取并发送到固定官方 API 主机，不作为工具参数或模型消息传递，也不跟随重定向。模型只看到统一工具结果，不负责选择服务或替用户授权。

网页正文提取失败、明确浏览器验证提示和相关不支持响应仍可产生读取备用候选。免费搜索改用独立判断：一次搜索最多先后尝试 Bing RSS 与固定 360 入口，结果无关、为空、结构异常或网络故障均不产生付费搜索标识；只有两个入口都明确受到访问限制，才提供付费搜索候选。单个入口故障不能据此申请付费。普通网页 401／403 权限拒绝不触发备用；明确标注浏览器挑战的 403 可作为页面受限处理。网络／DNS／TLS 错误、404、429、5xx、安全拦截、响应大小限制和空搜索结果不触发备用。没有凭据、无法取得授权或用户拒绝时不调用 API。

免费结果执行词面检查，覆盖中文、短英文关键词和混合查询。英文词设边界匹配，避免把 TES 匹配到 latest、contest 等子串；日期不单独计作相关，主要缩写不能只靠无关通用词命中。中文通过词组和双字片段做基础检查；网址查询参数不计入相关性，避免跟踪参数回显关键词。`site:` 与 `-site:` 还会核对实际结果域名和可选路径，包含 API 返回结果。此检查不是语义排序，可能漏掉不同语言别名；结果仍需模型核实，不因通过检查就认定支持结论。

360 仅解析普通结果标题、摘要及可取得的直接源地址，仍校验公开 URL，不读取广告、执行脚本、登录、自动通过验证或跟随搜索接口跳转。每个免费入口最多等待 8 秒，响应体最多 2 MiB，一次工具操作最多访问两个入口；首个入口已有可用结果时不发送给第二个。每轮 30 次免费操作最多对应 60 次搜索入口请求，仍受原操作预算和每次 20 秒总超时约束。`free_search_attempts` 只记录入口、状态及结果数，便于区别搜索质量问题与访问限制。

查询词限 1–128 字符，返回条数为字符串整数 1–20，默认 10；请求数量会传给免费和 API 后端，实际返回可能因来源或筛选而减少。搜索返回 `results`，每项包含标题、URL、最长 1000 字符摘要及可获得的发布日期；日期缺失时为 null。摘要只用于发现来源，不能冒称已阅读全文。服务无匹配结果返回空数组；验证页、格式变化或错误不会伪装成成功结果。免费入口不是具有可用性承诺的正式搜索 API，仍需遵循站点使用条件。

首次调用不传 `api_fallback`，只免费访问。符合备用条件的失败会返回原始错误、随机备用标识与免费探索建议，不弹窗、不调用 API；模型判断仍缺必要证据时，保持原参数并附带此标识续办。程序要求本次提问已有至少两个不同的免费探索目标取得结果或符合备用条件；付费搜索还要求至少两个不同的免费查询，读一个首页不能替代第二个查询，修改条数也不算新查询。是否与任务有关、证据是否充足仍由模型判断。结果质量不佳不能通过增加查询次数变成付费资格。

标识只在当前提问内有效，绑定工具、原参数和最近一次免费失败；不能凭标识改换目标或绕过 URL 安全检查。再次免费访问同一目标使旧标识失效，API 续办执行一次后也失效。安全拒绝、404、限流、空结果和网络失败等不生成备用标识；即使已选择始终允许，也不自动续办。备用结果及审批相关错误保留 `free_error`，便于区分最初免费失败与后续备用结果。

读取返回请求 URL、标题、正文、格式及 `truncated` 标记；正文最多 16000 字符。本地请求会返回实际到达的最终 URL；DeepSeek Fetch 没有提供最终 URL 字段，工具保留 null，不编造重定向结果。两类结果均标记为不可信外部数据。运行时 prompt 要求根据原文核实、说明截断和证据缺口，并在相关结论附近附来源链接。

每次提问最多 30 次免费网页操作，API 备用续办另有独立的 30 次尝试额度，最多合计 60 次访问尝试。免费尝试不消耗 API 额度，失败和参数错误计入相应尝试预算。每次提问的 ReAct 循环最多 16 次模型决策，包含最终回答；一批多个工具计一次决策，每批最多 8 个工具。循环轮数和工具额度分别生效，工具额度尚未用尽也可能先达到循环上限。每次尝试最多 20 秒，单个网络请求超时 15 秒，解压后的响应体最多 2 MiB；用户审批等待不计入网络超时。只允许一次有依据的 API 备用，不反复重试。没有预算时不弹窗、不付费。弹窗显示的是剩余 API 次数，不包含已用或待用的免费尝试；授权仅作用于当前用户提问，只有“始终允许”或配置中的自动允许才跨提问生效。错误仅返回安全的代码与说明，不回传原始异常、服务错误正文或鉴权头。重新提问可获得新的调用预算。

本地读取限制为标准端口的公开 HTTP/HTTPS URL，拒绝 URL 登录凭据、回环、内网、链路本地和保留地址；解析后固定公网连接 IP 并保留正确 TLS 主机校验，每次跳转重新检查，最多跟随五次。不会复用网站 Cookie。网页读取继承系统／环境代理，但请求目标始终是已检查的公网 IP，而不是让代理重新解析用户域名。仅当系统 DNS 全部返回 198.18.0.0/15 的 Clash 常见 Fake-IP 时，通过固定 Cloudflare DoH 接口取得真实 IPv4 地址，再执行同样的公网检查；普通内网地址和混合解析结果直接拒绝，不做替代解析。公共 DNS 接口不接受模型自定义地址，只发送域名，不发送页面路径、内容、Key 或 Cookie；其响应限 64 KiB，不跟随跳转。

固定 Bing 和 DeepSeek 接口使用正常主机名连接，继承用户的系统／环境代理且不跟随跳转；与任意网页读取使用不同的网络客户端。网页读取也继承代理，仍保持公网 IP 固定检查。HTTP CONNECT 目标为已验证 IP，使用请求局部的 TLS 主机映射保留原域名的 SNI 与证书校验；HTTPS 代理自身的不同主机名保持不变。证书链和域名验证均未关闭，并禁用读取客户端的空闲连接复用，避免同一 IP 上不同域名复用错误的 TLS 身份。DeepSeek Fetch 的目标 URL 先经过语法和直接 IP 检查，远端 DNS 和跳转安全由 DeepSeek 服务控制，本机不声称能检查远端实际连接。第一版不登录、不提交表单、不运行页面脚本，也不保证提取动态页面、PDF、图片或其他附件。

接口规范与计费见 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/guides/search/)。接入时文档价格为 Search／Fetch 各每千次成功且有结果的请求 5 元；模型处理结果另计费用，后续以服务商最新说明为准。验证范围见 [网页工具测试记录](./测试记录-2026-10-25-网页工具.md)。

读取客户端的证书信任来源与 HTTPX 普通客户端一致：优先 `SSL_CERT_FILE`，其次 `SSL_CERT_DIR`，否则使用 certifi CA 包。自定义 TLS 主机映射不会关闭证书链或域名检查。

## 引用与来源获取记录

`dianstar/evidence/source_evidence.py` 在编排层记录成功的 `search_web` / `read_webpage` 工具返回，并把程序生成的 `evidence` 元数据交给模型。元数据分为 `search_summary`、`abstract`、`fulltext_page`、`page_text` 和 `unavailable`，另含获取依据、截断标记与 `complete_document_verified=false`。外部返回的同名字段会被重新生成，不作为权限或已读全文证明。

摘要页通过有限的已知站点路径识别；正文页面仅对已知 arXiv / ar5iv 正文路径且实际文本有 Introduction 标题时识别。普通网页文本保持未知全文范围，不靠字数宣称论文完整。请求 URL 与确实返回的最终 URL 同时登记，API 未提供最终 URL 时不编造。URL 归一化忽略页内锚点，但保留查询参数，不把同域名的其他页面当作已经取得。

最终回答解析 Markdown 链接、参考链接、自动链接和普通文本 URL，排除代码示例和图片。按去重后的引用顺序追加来源核验说明：未命中台账的链接标为未核验，搜索摘要不算读取原文，读取失败不算已读来源。引用链接本身保留，不将“未核验”直接断言为假链接。没有引用链接的普通回答不增加注记，也不自动为无引用的结论编造出处。来源台账只恢复有对应工具调用 ID 的历史工具结果，不从用户文本或历史模型回答恢复已读状态；最终说明与工具元数据随正常会话保存。

这不是语义事实核查，不能证明标题、作者、实验数字和具体结论被来源支持，也不能全面识别所有网站的摘要或正文。流式草稿可能先显示生成文本，完成时才补充核验说明并同步最终回答；不增加模型修订请求或网页访问。

## Git 操作目标与核对记录

Git 目标链接与资料引用分开处理。`dianstar/evidence/git_operations.py` 只从对应 Git 工具的结构化返回登记操作记录：`git_remotes` 是配置地址，`git_push` / `git_publish` 只有成功且远程提交核对通过时才标记已核对，同时绑定仓库、远程、分支和完整提交号。执行失败或连接中断保留计划目标，但不认定成功；同一目标分支的新失败不会沿用旧成功状态。内部预览令牌仍不进入模型或操作记录。

最终回答中，已登记的仓库目标及对应 GitHub 分支、已核对提交链接放入“Git 操作核对”，不再因为没有读取网页而追加“引用未核验”。README 等其他链接仍按资料台账核验；同一个仓库链接若确实读取过网页，也保留独立的读取结果。历史记录明确标注非本轮新核对，配置地址也不会变成推送成功证明。这些标记不证明仓库内容已经读取，也不核实回答的所有语义结论。实现与用例范围见 [Git 操作核对记录](./修复记录-2026-10-31-Git操作核对.md)。

## 网页权限管理

`manage_web_access` 定义在 `dianstar/tools/local/web_access.py`。普通问答只注册 `WEB_ACCESS_STATUS_TOOL`，只允许 `action=status`，网页关闭时仍可查询。以下修改操作仅由独立用户权限流程通过控制注册表执行，不能由研究模型调用。只操作固定 `.local/search.json`，不接受路径、密钥或任意配置字段。

| action | 效果 |
| --- | --- |
| status | 只查询开关和付费策略，不写文件 |
| ask | 撤销长期付费授权，恢复每次提问需要授权 |
| deny | 禁止付费备用，保留免费访问 |
| allow | 请求长期付费授权，用户明确确认后才保存 |
| enable / disable | 开关搜索与读取，保持付费策略不变 |

成功返回 `web_enabled`、`paid_policy`、`saved` 和作用范围；失败返回结构化错误，不声称已保存。只查询不写文件，撤销或关闭不依赖原备用 Key 仍然存在。长期付费授权没有确认入口、用户拒绝或仅允许本次提问时均不保存为始终允许。权限管理本身不调用付费网页服务。

独立流程只读取当前原始用户输入。严格完整匹配的独立收紧命令可直接执行；复杂表达经无工具、无历史或网页的模型解析后仍必须确认，开启和扩大权限也需确认。解析不是授权证明。当前每轮最多处理一项权限变更，先应用再研究；成功后同步当前网页工具列表并撤销临时付费批准。关闭后尝试调用网页工具也被拒绝，开启后同次提问可以检索。配置供后续提问使用，不授予文件或系统权限。仅本轮付费授权保存在当前授权上下文，不修改长期策略，且不能覆盖明确禁止。

## 天气工具怎样工作

`dianstar/app/runtime.py` 编排本轮任务；`dianstar/providers/deepseek.py` 把工具名称及参数说明发给 DeepSeek。模型请求 `get_weather(location, date)` 后，`dianstar/tools/local/weather.py` 用 [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) 查城市，再用[天气预报 API](https://open-meteo.com/en/docs) 查天气数据。程序把工具结果连同模型上一条工具调用消息及其推理内容交回模型，`dianstar/core/loop.py` 继续循环，由模型组织最终回答。

`date` 可为 `today`、`tomorrow` 或未来 7 天内的 `YYYY-MM-DD`。查询以目的地当地日期为准。天气工具统一逗号格式，并尝试中文城市名有无“市”字；未提供地区的中文城市名会先尝试带“市”的写法，避免优先匹配到同名乡镇。它不保存自治区简称表。工具会检查查询到的中文城市名是否与请求的城市名一致；跨语言名称尚不能完全独立核对，仍依赖地名服务的解析结果。查不到地点、地点有歧义、日期无效或服务暂不可用时，工具只返回错误代码和原请求参数，不提供天气数据。模型可结合用户问题及历史决定下一步，同名同参数可以按需再次调用；总循环次数、工具额度与权限检查仍然生效。每日天气现象代表该日最强的预报天气现象，不代表全天每小时的状况。最高、最低气温为预报，当前气温也来自天气模型，并非温度计实测值。工具交给模型的数据不包含来源字段，来源在本节记录。查询需要联网；使用 Open-Meteo 免费接口前请查看其[使用条件](https://open-meteo.com/en/terms)。

## 日期计算工具怎样工作

日期工具的名称、用途、参数和限制位于 `dianstar/tools/local/date_calculator.py` 的 `DATE_TOOL`。`info` 查询日期及星期，`add` 要求字符串格式的整数 `days`，`difference` 要求 `end_date`；可选 `date` 默认为 `today`。沿用现有 SDK 适配层的字符串参数约定，错误作为结构化结果交回模型。示例提问：“2028 年 2 月 28 日过两天是哪天？”、“2028-02-28 到 2028-03-01 相差几天？”、“纽约今天星期几？”；本机当天日期的简单提问也可直接由注入日期回答。

## 数字计算工具怎样工作

工具定义在 `dianstar/tools/local/number_calculator.py` 的 `NUMBER_TOOL`，仅接收字符串参数 `expression`，由 `tools/local/registry.py` 的统一注册表分派。运行时 Prompt 要求具体数值运算和数值比较使用该工具；模型负责正确列式，工具负责计算。支持最多 512 字符、128 个语法节点、32 层求值嵌套，数字字面量最多 50 位有效数字，数量级指数在 ±1000 内；整数幂指数限 -1000 至 1000。中间和最终运算采用 50 位有效数字、四舍六入五成双；发生非精确舍入时返回 `approximate=true`。不支持函数、变量、单位换算、符号求解、`%`、`^` 或 `//`。计算本身离线完成，经模型选择工具仍需网络。

示例提问：“0.1 加 0.2 等于多少？”、“9.11 和 9.8 哪个数字大？”、“本金 100 元，每年增长 5%，三年后是多少？”

Fake-IP 兼容中的加密 DNS 格式见 [Cloudflare 官方文档](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。这是网络兼容措施，不代表能防御用户主动配置的恶意代理或本机环境篡改。
