# 工具说明

## Windows 命令安全边界（2026-11-03）

最终后端采用权限更少的 LPAC，排除普通 `ALL APPLICATION PACKAGES` 授权。保留运行时所需的注册表只读查询；固定系统 PowerShell 另有日志和 COM 运行时能力，不授予磁盘、驱动或系统服务管理能力。仅模型传递工具名或参数不能增加这些能力。SDK权限与撤销使用专用跨进程互斥段，避免多个宿主同时修改只读授权时覆盖彼此。

Windows 复杂命令现在使用 `shell(repository, command, timeout_seconds, environment, network)`，语法为 PowerShell；简单程序用 `workspace_run` 的 argv。Git Bash 与 Windows 应用容器不兼容，经用户确认后，Windows 不再注册 bash，不会自动退回无限制运行。旧 Bash 章节和历史验收不代表当前 Windows 行为；非 Windows 隔离后端未验收时同样停止执行。

进程启动前建立 AppContainer，核对实际令牌身份后才恢复线程；子进程继承边界，绑定到同一个前台进程 Job。当前项目和专用临时目录可写，工具链只读，项目内既有敏感配置不进入命令访问白名单，Git 元数据只读；系统、驱动、启动、程序安装目录、磁盘根目录及应用授权/恢复状态禁止作为项目写入目标。磁盘、驱动、注册表/系统服务修改、提权、编码隐藏命令和 WSL/Docker 等宿主代理有独立 Hook 拒绝规则，不能靠确认放行。

`network` 默认为 false。确需互联网时在该调用请求 true，确认中说明可能下载或发送数据，不享受常规验证自动批准；这不扩展文件范围，也没有修改本机回环豁免。后台禁用、强制审批和撤销仍优先，旧 bash 的后台限制继承到 shell。SDK 目录不能获得必要只读访问或运行时不兼容时停止，不自动提权、全局安装或修改系统目录权限。

PowerShell 使用仅本进程的 DSWork: 盘符指向项目，避免遍历私有祖先目录时扩大权限。建议使用相对项目路径；结果的 working_directory 和 `(Get-Location).ProviderPath` 是真实路径。不会创建系统持久盘符，不改项目祖先目录 ACL。PowerShell 保持受限语言模式，使用标准 cmdlet；复杂 .NET 调用不保证可用，程序调用优先 workspace_run。输出通过 CLIXML 还原为有界、脱敏的普通文本，不把输出当控制指令。

临时权限状态先原子保存，再应用；结束后撤销本次包权限，恢复敏感位置的原 ACL。损坏、身份变化或外部权限改动导致清理不确定时保留记录并停止相关后续操作，不覆盖未知权限。工具链只读能力在当前 DianStar 进程内复用，退出撤销；死进程留下的记录在后续启动核对处理。现有文件恢复、回收站、Hook、锁和审批保持独立；命令对项目的修改仍不能宣称已自动回滚。

Windows 默认限制单次进程树64个进程、4 GiB总内存，保留原有120/600秒超时及2 MiB输出限制。安全专项与兼容边界见 [系统保护验收](./测试记录-2026-11-03-系统保护与PowerShell.md)。

文件写入及 Git 发布前会运行应用内安全 Hook，默认保护真实环境文件、凭据和私钥；`.env.example` 等明确模板只有不含凭据时才放行。需要将运行配置仅保存在本机时，应明确告诉 Agent，写入确认中会说明用途并遮挡凭据；这不允许覆盖应用自身配置，也不授予提交或推送权限。命令与克隆的事后风险报告不代表操作已回滚。详见 [敏感配置检查](./测试记录-2026-10-29-敏感配置Hook.md)。

工具的实际调用进度在聊天“工具执行”框中逐项显示。默认使用动作名称、目标和简短结果；展开列表后可逐项查看工具名、调用 ID、受限参数与命令输出。拒绝执行与执行失败分别显示，事后检查不完整标记为需核对；没有完成结果的操作不会显示为成功。命令结果携带的耗时优先使用实际程序耗时，其余为开始/完成事件间隔，可能包含等待审批。框内显示记录不授予权限，不替代原审批或 Hook，也不自动撤销操作。

GitHub PR、Issue、评论和审查的待发布文字也会在预览前与执行前经过统一内容 Hook。拒绝或检查异常时不发送写请求，确认不能跳过检查；不增加额外确认步骤，不向官方工具加入自定义参数。真实模型、私有仓库、成功/失败 CI 及远程拒绝测试见 [完整链路验收](./测试记录-2026-10-31-GitHub完整链路.md)。

工具 Hook 统一放在 `hooks/`，由 `registry.py` 注册、`runner.py` 调度，文件工具和 Git 工具分别归入 `workspace.py`、`git.py`。各工具在原有操作位置调用，审批和执行前再次检查保持有效；维护方式见 [Hook 目录说明](./测试记录-2026-10-29-Hook目录整理.md)。

凭据管理源码（例如 `config/credentials.py`）可以正常编辑、暂存和提交，内容检查仍有效。提交被拦截时，`source=git_index` 表示问题来自完整暂存快照；它可能包含未修改的已跟踪文件，也可能保留工作区修正前的旧版本，不能把它解释成差异中的模块引用。确认修改后需明确重新暂存相应文件，工具不会自行扩大提交范围。详见 [误报修复记录](./测试记录-2026-10-30-Hook误报修复.md)。

## 临时工作区与回收站

临时脚本和中间文件使用受管理的 tmp，普通文件/目录删除优先移入 trash。它们位于 `%LOCALAPPDATA%/DianStar/file-state`，不会给项目增加待提交的 tmp 目录。Git 历史、原有文件事务恢复和这两项能力各自保留：修改文本后撤销仍用 file_restore；回收整个项目会一起保留 `.git`、未跟踪文件、二进制和空目录，不创建 Git 提交。

| 工具 | 用途 |
| --- | --- |
| `workspace_scratch_create(repository)` | 准备当前任务的临时工作区，返回 `id` 和可用于 read/write/bash/workspace_run 的 `repository`；命令复用原项目的会话开发环境 |
| `workspace_scratch_list(limit)` / `workspace_scratch_open(id)` | 查询、重新打开同会话的临时工作区；其他会话不可打开，另一任务仍持有时拒绝 |
| `workspace_trash_put(paths)` | 将明确绝对路径的文件或目录整批回收，最多20个目标；一次自然语言确认，返回每项恢复 `id` |
| `workspace_trash_list(limit)` | 查询允许范围内的编号、原位置、状态、大小、保留标记和到期时间；不返回备份正文 |
| `workspace_trash_restore(id, destination?)` | 恢复至原位置或明确的新位置；目标已存在即停止，不覆盖后来创建的内容；新位置的父目录须已存在 |
| `workspace_storage_recover(id, mode?)` | 续办中断的回收、恢复或清理；`resume` 按记录核对，`keep_current` 保留当前现场及副本，不改文件 |
| `workspace_storage_pin(id, pinned)` | 设置或取消长期保留标记 |
| `workspace_storage_cleanup(limit, small_only?)` | 清理满30天且未保留、未活跃、无冲突及操作残留的副本 |
| `workspace_trash_purge(ids)` | 对具体副本永久清理；需单独说明不可恢复并确认，不能用来代替普通删除 |

trash 从回收成功起保留30天，tmp 从任务释放起保留30天。每轮正常结束通过原授权网关尝试维护一项不超过64 MiB、5000项的到期对象；较大对象可明确请求清理到期副本。没有独立常驻定时器，超过期限后在应用使用时清理，不承诺精确时刻删除。活跃任务的跨进程使用锁、保留标记、恢复冲突、修改过的副本和操作残留均阻止自动清理；异常退出的临时任务在后续维护时重新开始30天宽限。后台停用、只读、撤销及强制审批仍有效；闲时维护不会自行弹出强制审批框。磁盘不足时报告并保留数据，不提前清空。

回收当前支持普通目录和文件，单批总数据最多4 GiB，每个目标最多50000项；拒绝符号链接、junction、硬链接、NTFS附加数据流、加密/离线文件及系统/应用自身数据。配置了仓库或创建根范围时仍受其约束，默认自动接入模式可对其他明确位置逐次确认。受保护的 `.env` 等不能单独回收；完整目录内的此类文件作为本机不透明副本保留，不读取正文给模型。回收站 `id` 和文件事务 `transaction_id` 不能混用。普通 shell 删除和外部程序操作不会自动转入 trash；不能靠 shell 绕过不支持类型或拒绝结果。细节及实测边界见 [tmp 与 trash 验收](./测试记录-2026-11-02-tmp与trash.md)。

## 项目文件工具

基础读写使用五个独立本地工具，统一经 `ToolGateway` 执行。`repository` 指向本轮已接入项目，`path` 使用项目内相对路径和 `/`；不需要用户手动开通 MCP。现已提供 patch、move、持久文件恢复，以及临时工作区和目录回收站。

| 工具 | 用途与主要参数 |
| --- | --- |
| `read` | 读取 UTF-8 文本，显示行号；`offset` 从 1 开始，`limit` 控制行数；目录或 `.` 返回直接子项，包括空目录 |
| `glob` | 按 `pattern` 找文件，如 `**/*.py`；可限定目录 `path`，支持 `hidden` 和从 0 开始的分页 |
| `grep` | 按内容找文件和行号；默认正则，可用 `literal=true`，支持 `case_sensitive`、文件模式 `include`、目录及分页 |
| `edit` | 使用 `old_string` / `new_string` 精确替换；默认唯一匹配，明确指定 `replace_all=true` 才替换多处 |
| `write` | 新建或完整写入 `content`，自动创建父目录；局部修改优先使用 `edit` |

现有文件须在本轮先成功 `read` 才能修改或覆写。审批前和执行前核对快照，其他人修改过的版本不会被直接覆盖。写入保留 UTF-8 BOM 和原换行，以同目录临时文件完成单文件替换；不支持二进制和其他编码的自动转换。读取、搜索默认不增加确认，写入沿用后台审批策略，不新增权限页面。

读取前 Hook 拒绝受保护路径；普通源码中的凭据先脱敏再返回或搜索，且保留行号。Git 项目的目录列举、glob、grep 尊重 Git 忽略规则和否定规则，隐藏文件需明确指定；真实 `.env`、私钥、应用本地目录和越界链接继续排除。直接 read 普通被忽略文件仍可使用。搜索结果有截断、跳过或失败标记，不能当作全项目无匹配证明。

单文件最大 2 MiB，搜索累计最多 32 MiB、候选最多 10000 项；单页最多 500 项、输出最多 24000 字符，单行片段最多 1000 字符。正则在固定可信子进程执行，5 秒超时终止；不运行模型代码或项目脚本。非 Git 目录若存在无法准确处理的 `.gitignore` 会明确失败。实现、验收及边界见 [第一批文件工具记录](./测试记录-2026-10-31-文件工具第一批.md)。

文件写入和删除现在自动记录本机恢复编号，并使用所有实例共享的文件锁。需要一起生效的修改用 `file_batch(repository, operations)`：操作项为 `edit`、`write` 或 `delete`，每路径一次，最多 20 个文件，快照原文总量最多 32 MiB，完整差异仍受预览上限约束。批次只确认一次，执行失败或取消会尝试恢复整批；发生外部改动时停止补偿并报告冲突。

`file_history(repository, limit)` 列出记录编号、文件和状态，不返回备份内容。`file_restore(repository, transaction_id)` 预览后撤销一条记录或继续中断恢复；成功恢复也有记录，可再次撤销。只有确认保留中断/冲突现场时才用 `keep_current=true`，它不覆盖文件，副本继续保留。读取只提示中断记录，严格只读模式不会偷偷恢复。逻辑错误可通过这些记录撤销，但测试失败本身不会自动选择恢复目标。完整范围、加密与限制见 [恢复和并发验收](./测试记录-2026-11-01-文件恢复与并发.md)。

`move(repository, source, destination)` 同时承担文件移动和重命名。源文件须先 read 当前版本，源/目标均限定同一项目，目标必须不存在；自动创建目标父目录，保留源字节、BOM、换行和文件模式。当前支持至多 2 MiB 的普通 UTF-8 文件，不移动目录、二进制、链接、跨项目路径，也不支持仅改变大小写。纯移动预览直接显示源与目标，避免重复展示整个大文件。

`patch(repository, patch)` 接受以下文本补丁格式，一项事务最多 256 KiB 补丁、200 个修改段、20 个源/目标路径，移动计两个路径，每个路径只能出现一次。所有段完整预检后一次确认；新增目标必须不存在，修改、删除和移动源均须先 read。上下文精确匹配且必须唯一，多个段按原文件顺序匹配，不根据前一段新内容匹配；空白字符不做模糊处理。已有文件的未触及换行、BOM 和末尾有无换行保持，新增行使用原文件检测到的换行，新增文件默认 LF。

```text
*** Begin Patch
*** Update File: settings.py
@@
-TIMEOUT = 10
+TIMEOUT = 20
*** Add File: docs/notes.md
+说明：调整请求超时。
*** Update File: legacy/helper.py
*** Move to: src/helper.py
*** Delete File: obsolete.txt
*** End Patch
```

修改段可以在最后加 `*** End of File`，限定匹配文件末尾；新增空文件可只写 Add File 头。该格式不接受标准 unified diff 的 `@@ -1 +1 @@` 数字头，也不调用 shell 或 `git apply`。补丁可在 Update File / Move to 后附修改段，实现移动时修改内容。普通移动和补丁均复用 Hook、源/目标排序锁、确认后版本复查、持久备份和失败补偿；移动先发布目标再删除源，两步中断可恢复，但不承诺外部程序看到多文件瞬间原子变化。可通过同一 `file_restore` 记录撤销，源/目标出现其他人的修改时保留并报告冲突。补丁和移动没有 `local_only` 参数，不能搬运敏感配置来绕过保护；基础写入/删除工具被禁用时组合工具也不可用。验收见 [补丁与移动记录](./测试记录-2026-11-01-文件补丁与移动.md)。

## 修改复核与任务记录

文件写入、删除、批量修改和恢复返回的事务编号会由应用层记录。改变文件的工具批次结束后，自动生成并回填本轮脱敏差异，供模型根据任务目标复核，不要求用户手动提供长指令。文件已有的本地修改作为修改前基线保留；检查差异不依赖 GitHub，也不要求文件已经提交。

| 工具 | 用途 |
| --- | --- |
| `review_changes(offset, limit)` | 本轮事务的文件列表、恢复编号、脱敏 diff、当前版本及真实验证证据；字符分页，`next_offset` 非空须继续读取 |
| `record_review(decision, reason, evidence_call_ids)` | 记录模型判断：`keep`、`repair`、`restore` 或 `uncertain`；证据只能引用当前修改后实际执行的工具编号，不执行写入或恢复 |
| `task_status(task_id, offset, limit)` | 查看当前任务台账，或分页读取同会话历史任务结果；旧结果不是当前状态或授权 |

差异过期、未读完整、当前检查仍失败或证据编号无效时不能确认保留。未运行测试可以明确说明限制，不把文本核对当测试通过；单纯提交推送仍不附加测试。达到 16 次模型决策时保存已执行结果并报告尚未完成的状态，不额外调用模型来宣称成功。

所有工具类型都进入同一个最多四项的并发调度，包括网页搜索/读取、文件读写、命令、Git 和 GitHub 操作。不同资源可并行，冲突操作按原调用顺序等待；通用命令锁定整个项目，项目切换/共享配置独占，未知范围保守串行。弹窗逐个显示，独立操作无需等待其他操作的确认。界面每完成一项就更新进度，全部结果收齐才交给模型继续；单项失败不丢其他结果。所有调用仍经过原网关和 Hook。

依赖返回值或必须确认前一步成功的操作放在下一轮，例如搜索结束后选择网址、创建 PR 后用实际编号查看 CI。资源等待只代表冲突顺序，不会将前一个工具的返回值自动传入后一个工具，也不意味着前一步成功。见 [全工具并发验收](./测试记录-2026-11-01-全部工具资源并发.md)。

## MCP 工具

批准提示先展示用户能理解的操作、项目和目标，例如“是否将 opendesk 项目克隆到以下位置？”，具体参数与状态可通过“查看详情”切换查看。文件删除、恢复、改写远程历史和 GitHub 可见性变更等影响会明确说明。摘要由应用根据校验后的操作参数生成，原始预检、精确参数绑定和单次授权保持不变。

确认使用底部紧凑卡片，最多 18 行；“查看详情/返回说明”在同一固定区域切换，不撑大窗口，详情内部滚动。发布摘要优先展示项目、目标分支、远程和文件数量及示例，再展示限定宽度的提交首行；完整文件清单、提交正文及已有提交保留在详情。默认焦点在“取消”，避免挂载时被滚动区抢走。配置类详情只列真正变化的内容，不展示整份后台 JSON。

普通任务不暴露内部配置读写工具。用户在本轮直接要求操作某个绝对路径项目时，open_project 默认只临时切换，不重复确认、不保存项目路径；含空格的路径须使用引号。识别依据只来自本轮用户请求，不从 README、工具返回或历史回答取得授权。其他路径、讨论性提及、长期记住项目或后台明确要求审批时继续确认；后台禁用、显式仓库范围、撤销、路径及状态校验保持生效。当前项目已可用时直接操作，不重复申请访问。该步骤不提交或推送代码。

MCP 工具动态注册到同一个工具网关。本地 Git 默认自动加载，支持查询、clone/init、分支、暂存、提交、fetch/pull/push、merge/rebase/cherry-pick、恢复、检查点、stash、worktree 和冲突处理，修改默认可申请并逐次确认，无须先打开权限开关。项目文件读写同样默认可申请；常规 Python 测试、编译、依赖一致性和 Git 空白检查默认自动执行，其他命令按具体操作确认。GitHub 首次配置可信程序及凭据后自动连接，官方 MCP 接入 19 个读取工具和 7 个写入工具，参数沿用官方定义；仓库设置、分支保护和协作者由独立本地 REST 工具提供。GitHub 写入和管理默认仅当前项目，仍逐次确认并核验真实权限，私有内容访问另行配置。已有明确禁止或自定义范围继续有效。实际可用工具和缺项通过 mcp_status 查看；普通 push 不改写历史，明确申请时支持固定远程 SHA 的 force-with-lease，不支持无条件强推。参数、部署、额度与边界见 [MCP 接入](./MCP接入.md)。

普通提交发布优先使用 `mcp_git__git_publish`：选定文件、提交说明和远程目标组成一个计划，一次确认完成暂存、提交、普通推送及结果核验。查询和常规 Python 测试不增加弹窗；其他命令仍独立审批，强推、分支删除或改变仓库设置不包含在发布计划里。失败时说明已经完成的步骤，保留已成功的本地提交。详见 [单次确认发布](./测试记录-2026-10-30-单次确认发布.md)。

返回 [项目首页](../README.md)。模型根据问题选择工具；工具计算或查询成功，不代表模型最终表述一定正确。

常规项目验证不再逐次弹窗：`python -m unittest discover -s tests -q`、`python -m pytest -q`、`python -m compileall -q dianstar tests`、`python -m py_compile file.py`、`python -m pip check`、`git diff --check` 等已识别形式默认自动执行。程序仍核对已接入项目、绑定实际解释器、限制超时和输出、脱敏并生成命令后文件审计。额外插件、安装依赖、通用脚本、项目外测试路径等继续按命令审批；明确的后台审批或禁用策略优先，不新增配置开关。细节与验收见 [常规测试自动执行](./测试记录-2026-10-30-常规测试自动执行.md)。

## 工具注册与授权规范

`bash(repository, command, timeout_seconds, environment)` 提供 Bash 字符串入口，和 `workspace_run` 共用命令准备、权限、进程执行、项目锁、脱敏及审计。Windows 定位已安装 Git Bash 实际程序，排除 WSL 和启动 shim；其他平台使用可用 Bash。缺失时返回 `bash_unavailable`，不会自行安装 Bash 或默默换 shell；本机程序仍可通过 `workspace_run` 的 argv 执行，PowerShell 也可显式作为程序调用。

Bash 以 `--noprofile --norc -o pipefail -c` 启动，支持管道、条件和多行；不继承 BASH_ENV、用户令牌等额外环境变量，不提供交互终端或后台服务。默认超时120秒，上限600秒，合并标准/错误输出；累计至多2 MiB，模型输出至多24000字符且先脱敏。返回真实退出码、超时/输出超限标志、工作目录、程序路径和耗时。超限停止进程且不能返回成功；前台退出、超时或取消时清理所拥有的子进程，避免子进程继续占用管道。

单条没有 shell 展开、管道、重定向或拼接的常规验证复用 argv 分类和程序绑定，返回 `execution_mode=direct_validation`、`shell=null`、`requested_shell=bash`，不再经 Bash 重新解析；复杂脚本返回 `execution_mode=shell` 并按策略确认，不能靠包含测试名称免确认。禁用 `workspace_run` 或命令能力也会禁用 bash。Python 常规验证可免确认不表示 npm、构建脚本或安装命令也自动放行；工具链需项目已有或另获授权。

`before_command` Hook 在预览和执行前检查命令中的凭据，`after_command` 审计文件副作用，免弹窗也不跳过。命令能执行项目代码并访问本机，检查不是操作系统隔离；命令写文件没有文件工具的逐文件备份和自动回滚。单纯提交/推送仍不附带测试。范围及验收见 [Bash 与开发闭环](./测试记录-2026-11-01-Bash与开发闭环.md)。

开发环境由模型根据项目说明、构建配置和锁定版本判断，不内置每种语言的安装工作流。需要构建/运行时先检查已有工具及路径；`executable_not_found` 或 shell 的找不到命令结果不等于未安装，应区分 PATH 未刷新、环境未激活、版本不符或组件缺失。优先复用已有兼容版本，安装须在明确授权和后台策略内，安装器返回成功后还要核验工具版本及任务相关构建/运行。只要求检查、测试或提交推送，不默认授予系统安装权限。

`workspace_environment_inspect(repository, programs)` 一次查询 Go、Python、Node、Rust/Cargo、Java、GCC 或 CMake 的本机位置和版本（每次最多4项）。检查当前会话项目环境的 PATH；Go 额外检查有限常见安装位置，优先实际编译器而非 Scoop shim。版本查询固定参数、单程序最多两个候选、每次最多4秒，Go 设置 `GOTOOLCHAIN=local` 防止查询触发工具链下载。返回可见包管理器位置，不执行安装器、不枚举软件全目录、不访问 WSL；未发现仅表示检查范围内未发现。默认不再逐条弹窗查询版本，后台禁用和强制审批仍有效。

应用从本轮明确的“在桌面新建某项目”等直接请求绑定一个项目范围；项目不存在或为空时初始化、范围内新增普通文件，以及已明确要求的 Go `run/build`（项目内 `.go` 文件或当前包 `.`）可免重复确认。普通源码内容仍先经过 Hook 和文件事务；覆盖已有文件、删除、其他项目、额外脚本、软件安装和后台强制审批保留确认。不识别的表述保守地走原审批，不从历史或模型参数取得新授权。`bash` 的普通 Go/版本单条命令绑定实际程序直接执行，返回 `execution_mode=direct_command`；复杂脚本仍实际由 Bash 执行。

安装提示正文说明软件、方式与账号影响，例如“是否通过 Scoop 为当前账号安装 Go”；完整脚本和本次环境值留在详情，界面显示当前正在检查环境、写文件或安装软件。Go 运行作为独立执行证据记录，不能冒充单元测试通过。完整范围与真实流程见 [Hello World 流程验收](./测试记录-2026-11-01-HelloWorld审批与耗时.md)。

`workspace_run` 和 `bash` 新增可选 `environment` 对象，只允许公开构建变量，例如 `JAVA_HOME`、`PATH`、`CC/CXX`、编译标志、`CARGO_HOME/RUSTUP_HOME`、`VIRTUAL_ENV` 和 SDK/包含库路径。宿主中已配置的这些变量可继承，已知凭据及启动注入变量不会因此放行。覆盖值经统一 Hook 检查，使用同一份准备环境定位程序并执行，批准后环境变化会停止；任何非空环境覆盖默认不享受常规测试免确认，后台显式策略仍有效。

`environment` 值按字面传递，不展开 `$PATH`；仅本次子进程生效，不改变应用进程、其他任务、系统注册表或已保存配置，结果只列变量名而不回传完整宿主环境。每个 Bash 调用都是新进程，上次 `cd/export/source` 和激活状态不会保留；可在同一次调用激活并构建，或明确保存公共开发环境。安装后应用 PATH 可能仍旧，可重新定位绝对程序路径或按本次环境传递；不能据此反复安装。不提供自动安装/提权或长时间后台安装器，超过前台限制时应说明并保留进展。原单次环境验收见 [模型驱动环境准备](./测试记录-2026-11-01-模型驱动环境准备.md)。

会话项目环境提供三个工具：`workspace_environment_get(repository)` 查询配置及 `revision`；`workspace_environment_set(repository, environment, path_prepend, expected_revision)` 整体替换；`workspace_environment_clear(repository, expected_revision)` 清除。保存公开构建变量和最多16个已存在的本机绝对搜索目录；不保存完整 PATH 快照、令牌、shell 状态或审批。后续 `workspace_run/bash` 自动使用：本次 `environment` > 当前会话项目配置 > 当前宿主允许的环境。`path_prepend` 追加在宿主 PATH 前并去重；显式的本次 PATH 替换该组合。

配置位于现有 `tasks.sqlite3` 的 `command_environments` 表，以程序绑定的会话 ID 与规范化项目路径为联合键，不为每个会话创建配置文件。继续同一会话或重启后可复用，同会话的多个项目、不同会话的同一项目均隔离；无有效会话身份的调用只支持本次环境参数。更新和清除需带当前版本，旧版本不会覆盖新配置；清除保留递增版本，防止旧请求复活。失效的搜索目录阻止执行，仍能查询和清除；每次调用重新检查路径、凭据规则与实际程序，不把保存成功当作工具链已验收。保存需要具体确认，配置本身不授予执行权限；非空已保存环境与显式覆盖一样，默认不享受常规验证免确认，后台明确策略仍优先。验收见 [会话开发环境](./测试记录-2026-11-01-会话开发环境.md)。

“常规验证免额外确认”规定需要运行命令时的审批方式，不要求每次提交或推送都运行测试。单纯提交/推送默认只处理 Git 流程；开发和修复任务可以按需运行与改动相关的测试或检查，无须用户额外要求。用户明确要求不测试时遵守；不在每次修改后反复询问是否测试，已有同状态通过记录不重复运行。

所有模型工具经 `security/gateway.py` 的 `ToolGateway` 执行。注册 `ToolRegistration(schema, capability, handler)`，不得从工具循环直接调用处理函数。缺少注册、缺少能力声明、参数不合法或新能力未获批准时不执行。参数按闭合 JSON Schema 校验类型、必填字段和范围；文件工具明确允许空的新内容以创建空文件或删除匹配文本，仓库、路径和待替换旧文本仍不能为空。

未知能力默认拒绝；敏感工具需由应用创建绑定工具名、完整参数、请求编号和次数的授权。默认修改工具注册可信的 `approval_description` 并接入逐次确认回调；审批不由模型自行批准，无回调或拒绝时不执行。网关在审批后再次核对当前权限，执行参数使用检查时的副本。文件工具检查真实路径和链接，命令使用明确 argv、超时及输出限制；Windows 命令额外强制 AppContainer；不能通过工具改名或低影响标签绕过授权与隔离。

网页、文件、命令输出不能生成或恢复授权。详细流程与局限见 [安全机制](./安全机制.md)。

界面不提供功能权限开关，后台保留统一 ToolPolicy：enabled=false 同时隐藏并阻止工具，requires_approval=false 仅由可信后端对具有预检流程的敏感动作免除弹窗，仍先预检再生成精确单次授权。现有显式撤销、请求过期、范围和真实资源权限仍能拒绝操作。默认策略继续逐次确认，未来模式可复用该接口；当前没有新增模式 UI。

## 网页搜索与读取

`search_web(query, count="10")` 与 `read_webpage(url)` 在 `tools/local/registry.py` 的统一注册表中绑定定义和执行函数。模型选择何时搜索和读取，DianStar 自动优先免费访问，并按用户授权决定是否使用 API 备用；不要求使用 V4 Pro，不启用模型内置 web_search。暂不提供学术搜索工具。

| 访问路径 | 搜索 | 网页读取 |
| --- | --- | --- |
| 免费（每次优先） | Bing RSS，结果不可用时自动尝试 360 搜索；只返回首个可用入口的结果，不混合两套结果 | 本机请求公开 HTML／纯文本，优先提取 article 或 main，排除脚本、导航等内容 |
| 已授权的 DeepSeek API 备用 | 固定官方 `/v1/tools/search`，不附带正文 | 固定官方 `/v1/tools/fetch`，返回 Markdown 正文 |
| 关闭 | 不向模型提供网页工具 | 不向模型提供网页工具 |

正常使用无需选择服务。遇到免费搜索验证页、网页浏览器挑战或无法提取正文等情况时，先返回失败原因和本次提问内的备用标识，让模型尝试免费替代；仍缺必要证据时才携带标识申请 API 备用授权；默认询问，仅本次提问内同意可复用，拒绝后本次提问不再重复询问；下一次提问会重新判断授权，不从会话历史恢复授权。选择始终允许会持久化；用户可用自然语言撤回授权或关闭网页工具。备用 Key 默认跟随当前 Key，保留旧配置中的独立 Key 引用。Key 只从本机 `.env` 读取并发送到固定官方 API 主机，不作为工具参数或模型消息传递，也不跟随重定向。模型只看到统一工具结果，不负责选择服务或替用户授权。

网页正文提取失败、明确浏览器验证提示和相关不支持响应仍可产生读取备用候选。免费搜索改用独立判断：一次搜索最多先后尝试 Bing RSS 与固定 360 入口，结果无关、为空、结构异常或网络故障均不产生付费搜索标识；只有两个入口都明确受到访问限制，才提供付费搜索候选。单个入口故障不能据此申请付费。普通网页 401／403 权限拒绝不触发备用；明确标注浏览器挑战的 403 可作为页面受限处理。网络／DNS／TLS 错误、404、429、5xx、安全拦截、响应大小限制和空搜索结果不触发备用。没有凭据、无法取得授权或用户拒绝时不调用 API。

免费结果执行词面检查，覆盖中文、短英文关键词和混合查询。英文词设边界匹配，避免把 TES 匹配到 latest、contest 等子串；日期不单独计作相关，主要缩写不能只靠无关通用词命中。中文通过词组和双字片段做基础检查；网址查询参数不计入相关性，避免跟踪参数回显关键词。`site:` 与 `-site:` 还会核对实际结果域名和可选路径，包含 API 返回结果。此检查不是语义排序，可能漏掉不同语言别名；结果仍需模型核实，不因通过检查就认定支持结论。

360 仅解析普通结果标题、摘要及可取得的直接源地址，仍校验公开 URL，不读取广告、执行脚本、登录、自动通过验证或跟随搜索接口跳转。每个免费入口最多等待 8 秒，响应体最多 2 MiB，一次工具操作最多访问两个入口；首个入口已有可用结果时不发送给第二个。每轮 30 次免费操作最多对应 60 次搜索入口请求，仍受原操作预算和每次 20 秒总超时约束。`free_search_attempts` 只记录入口、状态及结果数，便于区别搜索质量问题与访问限制。

查询词限 1–128 字符，返回条数为字符串整数 1–20，默认 10；请求数量会传给免费和 API 后端，实际返回可能因来源或筛选而减少。搜索返回 `results`，每项包含标题、URL、最长 1000 字符摘要及可获得的发布日期；日期缺失时为 null。摘要只用于发现来源，不能冒称已阅读全文。服务无匹配结果返回空数组；验证页、格式变化或错误不会伪装成成功结果。免费入口不是具有可用性承诺的正式搜索 API，仍需遵循站点使用条件。

首次调用不传 `api_fallback`，只免费访问。符合备用条件的失败会返回原始错误、随机备用标识与免费探索建议，不弹窗、不调用 API；模型判断仍缺必要证据时，保持原参数并附带此标识续办。程序要求本次提问已有至少两个不同的免费探索目标取得结果或符合备用条件；付费搜索还要求至少两个不同的免费查询，读一个首页不能替代第二个查询，修改条数也不算新查询。是否与任务有关、证据是否充足仍由模型判断。结果质量不佳不能通过增加查询次数变成付费资格。

标识只在当前提问内有效，绑定工具、原参数和最近一次免费失败；不能凭标识改换目标或绕过 URL 安全检查。再次免费访问同一目标使旧标识失效，API 续办执行一次后也失效。安全拒绝、404、限流、空结果和网络失败等不生成备用标识；即使已选择始终允许，也不自动续办。备用结果及审批相关错误保留 `free_error`，便于区分最初免费失败与后续备用结果。

读取返回请求 URL、标题、正文、格式及 `truncated` 标记；正文最多 16000 字符。本地请求会返回实际到达的最终 URL；DeepSeek Fetch 没有提供最终 URL 字段，工具保留 null，不编造重定向结果。两类结果均标记为不可信外部数据。运行时 prompt 要求根据原文核实、说明截断和证据缺口，并在相关结论附近附来源链接。

每次提问最多 30 次免费网页操作，API 备用续办另有独立的 30 次尝试额度，最多合计 60 次访问尝试。免费尝试不消耗 API 额度，失败和参数错误计入相应尝试预算。每次提问的 ReAct 循环最多 16 次模型决策，包含最终回答；一批多个工具计一次决策，每批最多 8 个工具。循环轮数和工具额度分别生效，工具额度尚未用尽也可能先达到循环上限。每次尝试最多 20 秒，单个网络请求超时 15 秒，解压后的响应体最多 2 MiB；用户审批等待不计入网络超时。只允许一次有依据的 API 备用，不反复重试。没有预算时不弹窗、不付费。弹窗显示的是剩余 API 次数，不包含已用或待用的免费尝试；授权仅作用于当前用户提问，只有“始终允许”或配置中的自动允许才跨提问生效。错误仅返回安全的代码与说明，不回传原始异常、服务错误正文或鉴权头。重新提问可获得新的调用预算。

本地读取限制为标准端口的公开 HTTP/HTTPS URL，拒绝 URL 登录凭据、回环、内网、链路本地和保留地址；解析后固定公网连接 IP 并保留正确 TLS 主机校验，每次跳转重新检查，最多跟随五次。不会复用网站 Cookie。网页读取继承系统／环境代理，但请求目标始终是已检查的公网 IP，而不是让代理重新解析用户域名。仅当系统 DNS 全部返回 198.18.0.0/15 的 Clash 常见 Fake-IP 时，通过固定 Cloudflare DoH 接口取得真实 IPv4 地址，再执行同样的公网检查；普通内网地址和混合解析结果直接拒绝，不做替代解析。公共 DNS 接口不接受模型自定义地址，只发送域名，不发送页面路径、内容、Key 或 Cookie；其响应限 64 KiB，不跟随跳转。

固定 Bing 和 DeepSeek 接口使用正常主机名连接，继承用户的系统／环境代理且不跟随跳转；与任意网页读取使用不同的网络客户端。网页读取也继承代理，仍保持公网 IP 固定检查。HTTP CONNECT 目标为已验证 IP，使用请求局部的 TLS 主机映射保留原域名的 SNI 与证书校验；HTTPS 代理自身的不同主机名保持不变。证书链和域名验证均未关闭，并禁用读取客户端的空闲连接复用，避免同一 IP 上不同域名复用错误的 TLS 身份。DeepSeek Fetch 的目标 URL 先经过语法和直接 IP 检查，远端 DNS 和跳转安全由 DeepSeek 服务控制，本机不声称能检查远端实际连接。第一版不登录、不提交表单、不运行页面脚本，也不保证提取动态页面、PDF、图片或其他附件。

接口规范与计费见 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/guides/search/)。接入时文档价格为 Search／Fetch 各每千次成功且有结果的请求 5 元；模型处理结果另计费用，后续以服务商最新说明为准。验证范围见 [网页工具测试记录](./测试记录-2026-10-25-网页工具.md)。

读取客户端的证书信任来源与 HTTPX 普通客户端一致：优先 `SSL_CERT_FILE`，其次 `SSL_CERT_DIR`，否则使用 certifi CA 包。自定义 TLS 主机映射不会关闭证书链或域名检查。

## 引用与来源获取记录

`dianstar/evidence/source_evidence.py` 在编排层记录成功的 `search_web` / `read_webpage` 工具返回，并把程序生成的 `evidence` 元数据交给模型。元数据分为 `search_summary`、`abstract`、`fulltext_page`、`page_text` 和 `unavailable`，另含获取依据、截断标记与 `complete_document_verified=false`。外部返回的同名字段会被重新生成，不作为权限或已读全文证明。

摘要页通过有限的已知站点路径识别；正文页面仅对已知 arXiv / ar5iv 正文路径且实际文本有 Introduction 标题时识别。普通网页文本保持未知全文范围，不靠字数宣称论文完整。请求 URL 与确实返回的最终 URL 同时登记，API 未提供最终 URL 时不编造。URL 归一化忽略页内锚点，但保留查询参数，不把同域名的其他页面当作已经取得。

最终回答解析 Markdown 链接、参考链接、自动链接和普通文本 URL，排除代码示例和图片。按去重后的引用顺序追加来源核验说明：未命中台账的链接标为未核验，搜索摘要不算读取原文，读取失败不算已读来源。引用链接本身保留，不将“未核验”直接断言为假链接。没有引用链接的普通回答不增加注记，也不自动为无引用的结论编造出处。来源台账只恢复有对应工具调用 ID 的历史工具结果，不从用户文本或历史模型回答恢复已读状态；最终说明与工具元数据随正常会话保存。

这不是语义事实核查，不能证明标题、作者、实验数字和具体结论被来源支持，也不能全面识别所有网站的摘要或正文。流式草稿可能先显示生成文本，完成时才补充核验说明并同步最终回答；不增加模型修订请求或网页访问。

## Git 操作目标与核对记录

Git 目标链接与资料引用分开处理。`dianstar/evidence/git_operations.py` 只从对应 Git 工具的结构化返回登记操作记录：`git_remotes` 是配置地址，`git_push` / `git_publish` 只有成功且远程提交核对通过时才标记已核对，同时绑定仓库、远程、分支和完整提交号。执行失败或连接中断保留计划目标，但不认定成功；同一目标分支的新失败不会沿用旧成功状态。内部预览令牌仍不进入模型或操作记录。

最终回答中，已登记的仓库目标及对应 GitHub 分支、已核对提交链接放入“Git 操作核对”，不再因为没有读取网页而追加“引用未核验”。README 等其他链接仍按资料台账核验；同一个仓库链接若确实读取过网页，也保留独立的读取结果。历史记录明确标注非本轮新核对，配置地址也不会变成推送成功证明。这些标记不证明仓库内容已经读取，也不核实回答的所有语义结论。实现与用例范围见 [Git 操作核对记录](./修复记录-2026-10-31-Git操作核对.md)。

## 网页权限管理

`manage_web_access` 定义在 `dianstar/tools/local/web_access.py`。普通问答只注册 `WEB_ACCESS_STATUS_TOOL`，只允许 `action=status`，网页关闭时仍可查询。以下修改操作仅由独立用户权限流程通过控制注册表执行，不能由研究模型调用。只操作固定 `.local/search.json`，不接受路径、密钥或任意配置字段。

| action | 效果 |
| --- | --- |
| status | 只查询开关和付费策略，不写文件 |
| ask | 撤销长期付费授权，恢复每次提问需要授权 |
| deny | 禁止付费备用，保留免费访问 |
| allow | 请求长期付费授权，用户明确确认后才保存 |
| enable / disable | 开关搜索与读取，保持付费策略不变 |

成功返回 `web_enabled`、`paid_policy`、`saved` 和作用范围；失败返回结构化错误，不声称已保存。只查询不写文件，撤销或关闭不依赖原备用 Key 仍然存在。长期付费授权没有确认入口、用户拒绝或仅允许本次提问时均不保存为始终允许。权限管理本身不调用付费网页服务。

独立流程只读取当前原始用户输入。严格完整匹配的独立收紧命令可直接执行；复杂表达经无工具、无历史或网页的模型解析后仍必须确认，开启和扩大权限也需确认。解析不是授权证明。当前每轮最多处理一项权限变更，先应用再研究；成功后同步当前网页工具列表并撤销临时付费批准。关闭后尝试调用网页工具也被拒绝，开启后同次提问可以检索。配置供后续提问使用，不授予文件或系统权限。仅本轮付费授权保存在当前授权上下文，不修改长期策略，且不能覆盖明确禁止。

## 天气工具怎样工作

`dianstar/app/runtime.py` 编排本轮任务；`dianstar/providers/deepseek.py` 把工具名称及参数说明发给 DeepSeek。模型请求 `get_weather(location, date)` 后，`dianstar/tools/local/weather.py` 用 [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) 查城市，再用[天气预报 API](https://open-meteo.com/en/docs) 查天气数据。程序把工具结果连同模型上一条工具调用消息及其推理内容交回模型，`dianstar/core/loop.py` 继续循环，由模型组织最终回答。

`date` 可为 `today`、`tomorrow` 或未来 7 天内的 `YYYY-MM-DD`。查询以目的地当地日期为准。天气工具统一逗号格式，并尝试中文城市名有无“市”字；未提供地区的中文城市名会先尝试带“市”的写法，避免优先匹配到同名乡镇。它不保存自治区简称表。工具会检查查询到的中文城市名是否与请求的城市名一致；跨语言名称尚不能完全独立核对，仍依赖地名服务的解析结果。查不到地点、地点有歧义、日期无效或服务暂不可用时，工具只返回错误代码和原请求参数，不提供天气数据。模型可结合用户问题及历史决定下一步，同名同参数可以按需再次调用；总循环次数、工具额度与权限检查仍然生效。每日天气现象代表该日最强的预报天气现象，不代表全天每小时的状况。最高、最低气温为预报，当前气温也来自天气模型，并非温度计实测值。工具交给模型的数据不包含来源字段，来源在本节记录。查询需要联网；使用 Open-Meteo 免费接口前请查看其[使用条件](https://open-meteo.com/en/terms)。

## 日期计算工具怎样工作

日期工具的名称、用途、参数和限制位于 `dianstar/tools/local/date_calculator.py` 的 `DATE_TOOL`。`info` 查询日期及星期，`add` 要求字符串格式的整数 `days`，`difference` 要求 `end_date`；可选 `date` 默认为 `today`。沿用现有 SDK 适配层的字符串参数约定，错误作为结构化结果交回模型。示例提问：“2028 年 2 月 28 日过两天是哪天？”、“2028-02-28 到 2028-03-01 相差几天？”、“纽约今天星期几？”；本机当天日期的简单提问也可直接由注入日期回答。

## 数字计算工具怎样工作

工具定义在 `dianstar/tools/local/number_calculator.py` 的 `NUMBER_TOOL`，仅接收字符串参数 `expression`，由 `tools/local/registry.py` 的统一注册表分派。运行时 Prompt 要求具体数值运算和数值比较使用该工具；模型负责正确列式，工具负责计算。支持最多 512 字符、128 个语法节点、32 层求值嵌套，数字字面量最多 50 位有效数字，数量级指数在 ±1000 内；整数幂指数限 -1000 至 1000。中间和最终运算采用 50 位有效数字、四舍六入五成双；发生非精确舍入时返回 `approximate=true`。不支持函数、变量、单位换算、符号求解、`%`、`^` 或 `//`。计算本身离线完成，经模型选择工具仍需网络。

示例提问：“0.1 加 0.2 等于多少？”、“9.11 和 9.8 哪个数字大？”、“本金 100 元，每年增长 5%，三年后是多少？”

Fake-IP 兼容中的加密 DNS 格式见 [Cloudflare 官方文档](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。这是网络兼容措施，不代表能防御用户主动配置的恶意代理或本机环境篡改。
