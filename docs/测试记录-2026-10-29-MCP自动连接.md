# MCP 自动连接验收（2026-10-29）

本记录保留第一轮自动连接及只读默认策略的验收。随后用户明确要求工具默认可用，已改为修改工具默认可申请并逐次确认，见 [工具默认可用验收](./测试记录-2026-10-29-工具默认可用.md)。

## 行为变化

- 无 mcp.json 时，本地 Git 在提问时自动连接并注册 11 个读取工具及单独确认的 clone，不要求用户先开启 MCP。Git 未安装时报告明确原因。
- 自动识别启动目录所在的普通 Git 项目或关联核验通过的 worktree；额外配置范围继续有效。GitHub 自动模式从当前项目 origin 推断公开读取仓库，配置过可信程序和凭据后自动连接。
- 连接方式缺省/null 为自动，true 仅使用配置范围，false 明确停用。旧布尔设置、Git 只读、文件/命令开关、私有/写入/管理范围及 Git 凭据后备开关均不自动扩大。无效配置仍关闭服务并报告错误。
- clone 不需要打开已有仓库的通用写开关。前置检查展示 URL 与目标，用户确认后消费单次令牌；拒绝不创建、不登记、不保存。目标必须不存在、父目录已存在，禁止网络共享/链接；配置了创建根目录时继续限制在其范围内。不会信任整个父目录。
- clone 成功后可当轮读取文件和 Git 状态，并只保存确认创建的仓库，下一轮继续可读。当前项目和自动推断的 GitHub 范围不自动持久化，写开关保持原值。
- 配置界面改为自动/配置范围/停用三种连接方式。保存不启动程序，测试连接展示具体缺项；configure_mcp 支持确认后切回自动模式并在当轮重连。

## 真实模型现场验收

在原先没有 mcp.json 的日常环境中，通过实际模型和 DianStar 的 run_turn 入口发起 Pi 克隆。审批回调只允许地址 `https://github.com/earendil-works/pi.git`、目标 `C:\Users\wang\Desktop\pi`、depth=1 的一次 clone，其他写入均不批准；没有预先保存 Git 写开关或桌面创建范围。

克隆成功，独立 Git 核验：

- origin 为上述地址；HEAD 为 `ad702637fdf6fbd3f965c5dba0b14bae100b74eb`。
- README.md 与 .git 存在，工作区干净。
- 自动保存的 mcp.json 只登记 Pi 仓库；git_enabled/github_enabled 为 null，git_write_enabled、workspace_write_enabled、github_use_git_credentials 均为 false；创建根目录、GitHub 写入/管理范围仍为空。

首次验收脚本在 run_turn 返回后的日志归档阶段误把 tool 消息当作包含 name 字段，报 KeyError；实际克隆和配置保存已经完成。修正的是忽略目录下的验收脚本，没有重新克隆或重跑写入。随后使用同一真实模型只读复核，实际调用 `mcp_status`、`workspace_read`、`mcp_git__git_status`、`mcp_git__git_log`，没有工具错误，没有申请写入，配置字节未变。模型读取 README 前 120 行并如实标注截断，报告工作区干净和最新提交 ad70263。

现场结果和第二轮完整工具消息保存在本机忽略目录 `.local/mcp-auto-live/`。GitHub 官方 MCP 的首次程序路径仍未保存，因此 status 如实报告缺少程序；这不影响本地 Git 克隆和读取。没有安装 Pi 依赖、执行项目脚本或修改真实远程仓库。

## 范围

连接仍在每轮提问自动建立、结束后关闭；本次没有增加永久后台进程或操作系统沙箱。GitHub 程序和凭据需要首次配置，自动识别只开放公开读取，私有、Issue/PR 写入及仓库管理继续独立授权。旧配置明确停用时不会自动打开，可在界面将连接方式改为自动。未执行旧完整配置提案中的桌面全目录信任、GitHub 管理或凭据后备授权。
