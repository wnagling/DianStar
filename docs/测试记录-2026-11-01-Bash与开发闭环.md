# Bash 与开发闭环验收（2026-11-01）

## 当前能力

新增 `bash(repository, command, timeout_seconds)`，与原有 `workspace_run` 共用程序准备、授权、项目锁、进程执行、脱敏和文件审计。已有 argv 工具本来就能启动测试，本轮新增 Bash 字符串、管道/条件/多行、明确的原生 Bash 定位和进程树生命周期收尾，不增加权限或 MCP 页面。

Windows 使用当前已安装的 Git Bash，排除 WSL 的启动器和普通 shim，不自动安装程序或切换 shell；POSIX 定位本机 Bash。参数固定为 `--noprofile --norc -o pipefail -c`，不继承 BASH_ENV 等额外启动配置或用户凭据环境变量。缺少 Bash 时明确返回 `bash_unavailable`；纯程序调用可继续使用 argv 工具。

简单无展开的常规验证沿用已有分类，绑定实际程序直接执行；结果为 `execution_mode=direct_validation`、`shell=null`、`requested_shell=bash`，不经过 shell 重新解析。复杂脚本走真正 Bash，返回 `execution_mode=shell`、`shell=bash`。均返回实际程序路径、工作目录、退出码、耗时及超时/超限标志。管道、条件、重定向、展开、安装和未知参数不能因为包含测试名称而免审批；后台对基础 `workspace_run` 的明确禁用或强制审批也不能通过新入口绕过。组合工具依赖的显式强制审批作为限制继承，不继承默认分类以扩大授权。

新增统一 `before_command` Hook，在预览和执行前复用公共内容规则检查命令中的已知凭据；异常或拒绝不执行。结束后保留原 `after_command` 文件审计。批次调度把 Bash 当作项目独占命令，跨会话仍使用同一项目系统锁；项目切换时移除并重建命令注册，避免留用旧上下文。

## 进程与范围d

- 默认120秒，最多600秒；仅前台、非交互执行，没有终端输入、后台任务句柄、长期服务或跨轮日志查询能力。
- 标准/错误输出合并，累计上限2 MiB，返回文本最多24000字符，先整段脱敏再截断。输出超限立即终止且不能记为成功。
- Windows 创建挂起进程，放入 kill-on-close Job 后恢复；不建立无管理的静默回退。前台退出、超时和取消清理该 Job 所拥有的进程树。POSIX 使用进程组。输出管道在终止后排空并收尾，不因继承管道的后台子进程长期阻塞。
- 文件工具的精确备份不覆盖任意命令写入；退出成功不等于所有业务断言正确。复杂 shell 的成功退出也不冒充确定的测试证据；只有实际识别的验证记录参与 app 的测试结论。应用取消、磁盘/系统错误等中断需核对现场，不能说已经回滚。
- 这是进程生命周期管理，不是文件/网络沙箱。命令能执行项目代码并以用户账号访问本机；审计范围有限，不自动撤销网络、数据库或部署副作用。创建挂起进程到加入 Job 的窄窗口不能承诺抵御任意外部强杀并完全没有挂起资源遗留。

Windows 机制依据：[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread)、[线程枚举结构](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-threadentry32)。生命周期行为另由本机真实进程用例核对，不只依靠文档推断。
