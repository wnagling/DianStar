# 当前架构

返回 [项目首页](../README.md)。本页描述**已经实现**的 Python 程序。长期设想见 [产品文档](./产品文档.md)；历史决策见 [编程语言选型](./编程语言选型.md)。

## 依赖方向

```text
__main__.py                 终端输入输出、命令与会话切换
    ├── conversations.py    本机会话持久化
    └── agent.py            一轮任务的编排和工具分派
        ├── prompts.py      读取系统提示词
        ├── system_prompt.md  通用助手系统提示词
        ├── loop.py         有界 Think → Act → Observe 状态推进
        ├── deepseek.py     SDK 请求、消息格式和响应解析
        └── tools/
            ├── weather.py           地名解析和天气 HTTP 查询
            ├── weather_contract.py  发给模型的天气数据裁剪
            ├── number_calculator.py  受限十进制表达式与精度标记
            └── date_calculator.py   公历日期、星期、日期加减、差值与时区
```

`deepseek.py` 只负责与模型服务通信，不执行天气查询。`agent.py` 用注册表将工具定义与执行函数配对，从这份注册表生成发给模型的工具列表，并按模型返回的名称查找执行函数；天气执行函数从 `tools/weather.py` 获得数据，把相关字段交给 `deepseek.py`。`loop.py` 不知道具体工具名称或模型服务商。`prompts.py` 读取 `system_prompt.md` 作为运行时系统提示词；天气工具的用途和参数在工具定义中。`tools/weather_contract.py` 裁剪发送给模型的天气数据。

## 一轮天气任务

1. `__main__.py` 收到问题，从 `conversations.py` 取得本轮可用的历史。
2. `agent.py` 每轮通过 `prompts.py` 将固定规则和本机当天日期组装为系统提示词，再创建 DeepSeek 会话并调用 `run_loop()`；同一轮工具循环复用该提示词，下一轮重新获取日期。系统提示词不写入聊天记录。模型根据问题和对话上下文决定是否调用天气工具，程序不做天气关键词分流。
3. `deepseek.py` 以 thinking 模式请求模型，返回文字回答或一组结构化工具动作，并按注册工具的参数定义校验。遇到模型把工具标记当文字返回时，也按同一组工具定义解析完整调用。它不判断天气地点是否需要合并或追问。
4. `loop.py` 执行模型本轮提出的各次工具调用；`agent.py` 分派天气工具，裁剪成功结果，或把地点、日期、服务错误作为结构化结果交回 DeepSeek 会话。同一批调用中某个地点失败，不阻止其他地点。模型结合问题、历史和工具结果决定继续调用工具、追问或回答。`tools/weather.py` 校验日期与中文城市名解析结果；跨语言名称核对仍有限制。
5. 模型收到查询结果后组织最终回答，程序不检查回答中的气温措辞和数值；回答显示并保存。会话同时保存这一轮的工具调用、工具结果及模型返回的 `reasoning_content`，供后续提问和恢复会话使用；TUI 在每轮问题与回答之间保留独立思考框，默认预览最近四行，点击标题展开全文；纯文本模式只显示最终回答。工具执行仍有参数、日期与地名检查，循环次数用尽则报错。

## 日期计算任务

`calculate_date` 与天气工具共同注册在 `agent.py` 的同一份 `tool_registry` 中；从注册表生成 API 的工具定义，并按工具名称分派执行。所有模型参数沿用当前 SDK 适配层的字符串约定，`operation` 为 `info`、`add` 或 `difference`。可选参数在工具端校验，错误带代码、说明和原请求返回模型，模型可修正后继续调用。

计算本身不联网、不读写用户文件或日程，不依赖模型心算。每次执行读取同一时刻，在所选时区解析相对日期；未指定时区则用本机时区。按天偏移和日期差使用公历日期运算，不把夏令时的一天固定换算成 24 小时。日期差为结束日期减开始日期，可为零或负数。系统提示词日期仍固定为提问开始时的快照，工具结果明确携带执行时参考日期及参考 UTC 偏移；跨天时以工具实际计算依据为准。

## 数字计算任务

`calculate_number` 的定义和执行函数接入同一注册表。模型传入字符串 `expression`，程序先限制长度和字符，再解析 AST，仅接受数字、正负号、加减乘除和整数次幂；不使用 `eval`，不执行用户代码。十进制数字直接从源码文本读取，避免经浮点数转换丢失精度。

求值限制语法节点、递归深度、字面量有效数字、幂指数和数字量级；采用独立的 50 位 Decimal 上下文，不改变调用者精度。结果以十进制字符串返回，`approximate` 标识中间或最终运算发生非精确舍入。错误带代码和说明交回模型，允许在原有循环限额内修正表达式。工具不联网、不读写用户文件，列式、单位含义和最终表述仍由模型负责。

## 数据与权限边界

- `.env` 由本地 SDK 适配层读取，API Key 不作为模型消息发送；`.gitignore` 防止普通 Git 暂存纳入密钥文件，但不限制本机文件访问。
- `.local/conversations/` 存放本机会话明文，包括名称、推理内容及工具结果，不进入 Git。首次成功提问生成默认名称；`/rename` 更名，`/resume 会话名` 按名称加载，`/switch` 按最近修改时间列出并选择。`/compress` 仅改变后续请求的上下文起点。
- 当前注册天气查询、日期计算和数字计算工具。项目文件读取、命令执行、日程、提醒和密钥进程隔离尚未实现，后续工作见 [待办](./开发日志/2026-10-21-待办.md)。
- 提示词中的指令边界和授权规则是模型行为约定，不是权限控制的实现。未实现能力在 [System Prompt 蓝图](./system_prompt_blueprint.md) 留空，蓝图不参与运行时请求。
