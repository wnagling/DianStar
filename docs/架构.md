# 当前架构

本页描述**已经实现**的 Python 程序。长期设想见 [产品文档](./产品文档.md)；历史决策见 [编程语言选型](./编程语言选型.md)。

## 依赖方向

```text
__main__.py                 终端输入输出、命令与会话切换
    ├── conversations.py    本机会话持久化
    └── agent.py            一轮任务的编排和工具分派
        ├── loop.py         有界 Think → Act → Observe 状态推进
        ├── deepseek.py     SDK 请求、消息格式和响应解析
        └── tools/
            ├── weather.py           地名解析和天气 HTTP 查询
            └── weather_contract.py  天气任务目标与完成验收
```

`deepseek.py` 只负责与模型服务通信，不执行天气查询。`agent.py` 是当前唯一的工具分派处；它从 `tools/weather.py` 获得数据，只将回答所需的字段交给 `deepseek.py`。`loop.py` 不知道具体工具名称或模型服务商。天气任务的提示与验收规则在同目录的 `tools/weather_contract.py`，不在通用循环里。

## 一轮天气任务

1. `__main__.py` 收到问题，从 `conversations.py` 取得本轮可用的历史。
2. `agent.py` 判断是否需要天气查询，创建 DeepSeek 会话并调用 `run_loop()`。
3. `deepseek.py` 请求模型，返回文字回答或结构化工具动作；只有有效的 `get_weather` 参数会被接受。遇到模型把工具标记当文字返回时，它只解析完整且合法的天气调用。
4. `agent.py` 执行天气工具，裁剪数据字段并将结果交回 DeepSeek 会话。若地名有歧义或找不到，直接向用户追问国家、地区或拼写；用户补充信息后沿用原天气问题继续查询。`loop.py` 随后进入下一轮决策。
5. 候选回答经 `weather_contract.py` 检查。通过后才显示并保存；缺少地点会向用户追问，验证失败会让模型修正；循环次数用尽则报错。

## 数据与权限边界

- `.env` 由本地 SDK 适配层读取，API Key 不作为模型消息发送；`.gitignore` 防止普通 Git 暂存纳入密钥文件，但不限制本机文件访问。
- `.local/conversations/` 存放本机会话明文，不进入 Git。`/compress` 仅改变后续请求的上下文起点。
- 当前只注册天气查询工具。项目文件读取、命令执行和密钥进程隔离尚未实现，后续工作见 [待办](./开发日志/2026-10-21-待办.md)。
