## 依赖方向

TUI 使用 `ChatLog` 显示历史和生成中的回答。流式阶段最多每秒合并更新 30 次，`StreamLines` 只对新收到的字符按显示宽度折行，已完成显示行只写一次，仅重绘末尾未完成的显示行；长段落没有换行时也不重排全文。截断临时尾行时原地修改列表，不复制历史行；状态栏只在开始回答时更新。完成后替换当前回答为 Markdown，不重复追加整条回答。流式临时文本不写入会话，最终回答和来源核验说明一起保存。`ui/tui/rendering.py` 为 Markdown、裸网址和行内代码网址保留链接样式；屏幕处理左键点击后在后台工作线程打开系统默认浏览器，避免阻塞界面。滚动到底部时跟随新内容，向上阅读时保留位置。

依赖方向：界面 → 应用服务 → 通用循环、模型适配、工具及 MCP 接入。`core/` 不导入 Textual、具体模型和产品工具；纯文本运行按需加载 TUI，禁止导入 Textual 时仍能运行。Git 业务代码不导入 MCP SDK 或服务入口；MCP 服务调用 Git 实现。通用 MCP 连接不加载产品工具和应用服务。

敏感配置规则集中在 `security/content_guard.py`。应用内 Hook 按工具能力组织在 `hooks/`，通过 `registry.py` 注册、`runner.py` 统一执行；`workspace.py` 负责文件写入和命令后的有界观察，`git.py` 负责真实索引、提交树、待上传历史及克隆检查。工具在取得实际内容时调用，执行点再次强制检查；网关审批不能替代这些内容校验。Hook 不提供进程隔离，参见 [Hook 结构与验收](./测试记录-2026-10-29-Hook目录整理.md)。

同一轮允许按需多次调用相同名称、相同参数的工具，包括修改后重新读取、修复后重跑测试、轮询和重试；每次实际执行并保留独立结果，不按参数缓存或一律拦截。总循环上限、每批调用数量、工具额度和权限校验仍然生效；敏感操作重复执行仍需满足当次授权，Git 内部令牌仍不可重放。详见 [重复调用修复验收](./测试记录-2026-10-27-工具重复调用.md)。

工具按调用方式明确区分：`tools/local/` 是直接调用的内置工具；`tools/mcp/` 负责 MCP 接入，`servers/` 保存我们维护的 MCP 服务实现。Git 属于我们实现的 MCP 服务，GitHub 属于外部 MCP 服务。内置注册表与 MCP 注册表分别构建，在应用层合并给同一个权限网关和循环使用。MCP 客户端只依赖共享契约，不导入 Git 服务端实现；内置业务不导入 MCP SDK。项目文件工具借用本轮已核验仓库范围，GitHub 管理 REST 工具复用访问范围与凭据适配器；它们仍属于直接调用工具，不冒用官方 MCP 名称。

这里的 local 表示由 DianStar 直接调用，天气和网页工具仍会访问网络。`tools/` 的两个实现子目录是 `local/` 和 `mcp/`，不再保留 `builtin/` 或 `integrations/` 转发路径。

当前工具归类的验证范围见 [工具目录验收](./测试记录-2026-10-27-工具目录归类.md)。

UI 提供流式、思考和授权回调；`app/chat_service.py` 负责在成功返回后保存会话，并保留工具调用、结果和多段思考。异常和取消不会把半条提问保存为成功会话。`/new`、重命名、上下文清空和同名会话解析由两个界面共用；弹窗、选择列表及输入提示留在 UI。

根目录仅保留 `__init__.py` 和 `__main__.py` 两个 Python 文件。迁移期的旧路径转发文件已删除，内部引用和测试全部使用实际实现模块；旧 Python 导入路径不再支持。`DS`、`dianstar` 与 `python -m dianstar` 启动方式保持可用。内部 Git MCP 服务使用 `python -m dianstar.tools.mcp.servers.git.server`；启动参数和打包脚本已同步。`.env`、`.local/` 的路径和数据格式不变，无需迁移已有 Key、配置或会话。

本轮整理继续使用一个 Python 包，不引入多包发布、通用插件框架或新的事件总线。分步验收见 [项目结构整理测试记录](./测试记录-2026-10-27-项目结构整理.md)。

`providers/deepseek.py` 只负责与模型服务通信，不执行天气查询。`tools/local/registry.py` 将工具定义与执行函数配对；`app/runtime.py` 从注册表生成模型可见的工具列表，通过授权入口按名称分派执行。天气执行函数从 `tools/local/weather.py` 获得数据，把裁剪后的字段交给模型适配层。`core/loop.py` 不知道具体工具名称或模型服务商。`prompts/builder.py` 读取 `prompts/system.md` 作为运行时系统提示词；天气工具的用途和参数在工具定义中。`tools/local/weather_contract.py` 裁剪发送给模型的天气数据。

## 一轮天气任务

1. `ui/cli.py` 或 `ui/tui/app.py` 收到问题，调用 `app/chat_service.py`，从 `sessions/conversations.py` 取得本轮可用历史。
2. `app/runtime.py` 每轮通过 `prompts/builder.py` 将固定规则和本机当天日期组装为系统提示词，再创建 DeepSeek 会话并调用 `run_loop()`；同一轮工具循环复用该提示词，下一轮重新获取日期。系统提示词不写入聊天记录。模型根据问题和对话上下文决定是否调用天气工具，程序不做天气关键词分流。
3. `providers/deepseek.py` 以 thinking 模式请求模型，返回文字回答或一组结构化工具动作，并按注册工具的参数定义校验。遇到模型把工具标记当文字返回时，也按同一组工具定义解析完整调用。它不判断天气地点是否需要合并或追问。
4. `core/loop.py` 推进各次工具调用；`app/runtime.py` 通过 `ToolGateway` 和 `tools/local/registry.py` 中的处理函数执行天气工具，裁剪成功结果，或把地点、日期、服务错误作为结构化结果交回 DeepSeek 会话。同一批调用中某个地点失败，不阻止其他地点。模型结合问题、历史和工具结果决定继续调用工具、追问或回答。`tools/local/weather.py` 校验日期与中文城市名解析结果；跨语言名称核对仍有限制。
5. 模型收到查询结果后组织最终回答，程序不检查回答中的气温措辞和数值；回答显示并保存。会话同时保存这一轮的工具调用、工具结果及模型返回的 `reasoning_content`，供后续提问和恢复会话使用；TUI 在每轮问题与回答之间保留独立思考框，默认预览最近四行，点击标题展开全文；纯文本模式只显示最终回答。工具执行仍有参数、日期与地名检查，循环次数用尽则报错；每次提问的 ReAct 循环统一最多 16 次模型决策，包含最终回答。一批工具调用计一次决策，每批仍最多 8 个工具。`core/loop.py` 的 `DEFAULT_MAX_STEPS` 是默认上限，应用入口直接使用该默认值；网页等工具的独立额度不再决定循环轮数。详见 [16 轮循环验收](./测试记录-2026-10-27-ReAct循环上限.md)。

## 日期计算任务

`calculate_date` 与天气工具共同注册在 `tools/local/registry.py` 生成的同一份 `tool_registry` 中；从注册表生成 API 的工具定义，并按工具名称分派执行。日期工具参数保留字符串约定，`operation` 为 `info`、`add` 或 `difference`；MCP 适配支持其他 JSON 参数类型。可选参数在工具端校验，错误带代码、说明和原请求返回模型，模型可修正后继续调用。

计算本身不联网、不读写用户文件或日程，不依赖模型心算。每次执行读取同一时刻，在所选时区解析相对日期；未指定时区则用本机时区。按天偏移和日期差使用公历日期运算，不把夏令时的一天固定换算成 24 小时。日期差为结束日期减开始日期，可为零或负数。系统提示词日期仍固定为提问开始时的快照，工具结果明确携带执行时参考日期及参考 UTC 偏移；跨天时以工具实际计算依据为准。

## 数字计算任务

`calculate_number` 的定义和执行函数接入同一注册表。模型传入字符串 `expression`，程序先限制长度和字符，再解析 AST，仅接受数字、正负号、加减乘除和整数次幂；不使用 `eval`，不执行用户代码。十进制数字直接从源码文本读取，避免经浮点数转换丢失精度。

求值限制语法节点、递归深度、字面量有效数字、幂指数和数字量级；采用独立的 50 位 Decimal 上下文，不改变调用者精度。结果以十进制字符串返回，`approximate` 标识中间或最终运算发生非精确舍入。错误带代码和说明交回模型，允许在原有循环限额内修正表达式。工具不联网、不读写用户文件，列式、单位含义和最终表述仍由模型负责。

## 数据与权限边界

`app/mcp_startup.py` 将保存的连接方式解析为本轮有效设置：缺省/null 自动识别启动目录的项目，GitHub 从 origin 推断公开读取范围；false 明确停用，true 保留配置范围。自动范围不写回配置。Git 安装检测、GitHub 缺少程序/凭据等原因通过 mcp_status 报告。服务在提问时自动连接，结束时释放；不要求手动开启，也没有新增后台常驻进程。

修改工具默认可申请，仍不预先授予执行权限。git_write_enabled/workspace_write_enabled 缺省或 null 在运行时解析为逐次申请，false 明确禁止；GitHub 写入/管理范围缺省/null 取当前项目 origin 与允许范围的交集，空列表明确禁止，额外只读仓库不自动扩大为写入/管理范围。凭据后备和私有内容读取保持独立配置。

功能权限控制只保留在后台，MCP 界面没有启用、禁止或审批选项。security/tool_policy.py 定义 ToolPolicy(enabled, requires_approval)，由可信应用层通过 run_turn(tool_policies=...) 提供，工具名规则优先于能力名规则。ToolGateway 在发布工具 schema 和执行时都检查可用性；免弹窗策略仍须完成可信预检、参数/请求绑定的单次授权和工具端状态重查。规则按请求快照保存，不由模型修改，重连与工具列表刷新不解除规则。后台模式接口和实际模式产品分开：本次没有增加只读/全权限菜单或完整模式切换。

默认策略通过 confirm_destinations 对具体 clone/init/worktree 目标逐次确认，配置了创建根目录时仍受其限制；旧只读模式可保留独立 clone 申请。客户端权限网关和服务端单次状态绑定令牌均保留，无确认入口或用户拒绝时不执行。成功创建后只保存该仓库，不保存自动识别的当前项目、GitHub 范围或父目录信任。

工具分派全部经过 `ToolGateway`，研究资料和 `Authorization` 分开。普通问答只能查询网页权限；修改走独立流程，非确定性提案必须由用户确认，按本轮请求及精确参数批准。DSML 兼容结果保留成对工具消息，不提升为用户消息。文件工具检查明确仓库与路径，命令工具默认可申请并逐次确认，也可明确禁止；操作系统隔离仍未实现。具体实现及限制见 [安全机制](./安全机制.md)。

- `.env` 由本地 SDK 适配层读取，API Key 不作为模型消息发送；`.gitignore` 防止普通 Git 暂存纳入密钥文件，但不限制本机文件访问。
- `.local/conversations/` 存放本机会话明文，包括名称、推理内容及工具结果，不进入 Git。首次成功提问生成默认名称；`/rename` 更名，`/resume 会话名` 按名称加载，`/switch` 按最近修改时间列出并选择。`/compress` 仅改变后续请求的上下文起点。
- 当前注册天气、日期、数字及网页搜索／读取工具；关闭网页服务时不向模型暴露网页工具。MCP 每轮按连接方式自动发现并连接服务，将筛选后的工具注册到同一网关。Git、文件和命令默认开放逐次申请，可信异步预检先生成状态绑定的预览；确认后授予精确参数的单次权限，服务端消费内部令牌并重查状态。GitHub 官方参数由 schemas.py 适配，github_contract.py 定义读写及方法集合，github_search.py 检查搜索范围，github_adapter.py 检查公开/私有访问，github_writes.py 负责写入预览和状态重查；GitHub 写入/管理默认仅当前项目，每次通过同一网关单独确认。详细流程见 [MCP 接入](./MCP接入.md)。新接入范围通过 app/mcp_configuration.py 展示前后配置并确认后重连。日程、提醒、后台命令管理和操作系统沙箱尚未实现。
- 提示词中的指令边界和授权规则是模型行为约定，不是权限控制的实现。未实现能力在 [System Prompt 蓝图](./system_prompt_blueprint.md) 留空，蓝图不参与运行时请求。

## 目录收尾

本轮已移除旧模块兼容壳，配置拆为路径、模型和密钥职责，授权拆为状态、参数校验和执行网关；`core/registry.py` 保存工具注册契约。Windows 功能、欢迎字符画、会话、来源核验和运行时提示词分别归档。详见 [收尾验收记录](./测试记录-2026-10-27-结构收尾.md)。

透明工具接入：配置菜单和原 MCP 设置页面已移除。app/mcp_startup.py 自动识别项目及发现连接组件；tools/mcp/github_server.py 校验应用管理的固定版本组件或发现 PATH 中的安装。账号身份仍由独立凭据策略处理，普通用户不需要配置 MCP。
