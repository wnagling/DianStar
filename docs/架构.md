# 当前架构

Windows 命令安全链路：ToolGateway → CommandTools 的参数/程序/环境准备 → before_command Hook → 项目独占锁及执行前复查 → `platform/command_isolation.py` 建立包权限 → 固定 Windows worker 以 AppContainer 启动 → 结果脱敏、项目审计和权限收尾。`security/system_paths.py` 为文件、项目接入、Git 和回收提供共同系统禁区；`host_commands.py` 拒绝机器管理和宿主代理，命令文字检查不替代内核边界。

Windows 使用 shell/PowerShell，workspace_run 保持原生 argv；不注册不兼容的 Git Bash，不绕去 WSL 或无限制进程。`command_reads.py` 在宿主生命周期复用SDK只读能力，`windows_acl.py` 只负责底层权限原语，原子、DPAPI保护的恢复记录位于本机状态根。64进程/4 GiB内存及超时/输出约束由 Job 与进程执行器统一落实。PowerShell的 DSWork: 仅属于该子进程，避免扩大宿主祖先目录的权限；CLIXML 只作为文本传输解析。支持与限制见 [系统保护验收](./测试记录-2026-11-03-系统保护与PowerShell.md)。

最终启动器设置 LPAC 的公共应用包退出属性。原生程序仅保留必要的注册表只读能力，固定系统PowerShell增加日志/COM运行时能力，模型不能指定运行时能力表。SDK目录权限用单独的跨进程互斥段保护，修改、撤销及中断恢复均按所有权处理。既有包身份验证与 Job 生命周期约束继续生效。

文件生命周期新增 `tools/local/storage/`：tree 负责有界树快照、复制和逐项校验清理，journal 保存持久元数据，trash 负责目录回收与恢复，scratch 管理会话/任务临时目录及系统使用锁，maintenance 负责重启续办与到期清理，tools 提供 schema、预览和网关注册。`hooks/storage.py` 复用内容与路径规则；`app/storage_lifecycle.py` 在正常轮结束经原 ToolGateway 尝试小批维护，异常收尾仍释放临时使用锁。运行时重连复用该管理器，任务日志保存恢复编号，工具框显示实际操作。

本机文件状态根下增加 `tmp/<会话摘要>/<任务>/<编号>/`、`trash/<编号>/payload` 和 `storage.sqlite3`。正文保留在物理文件中，数据库仅保存状态、身份、校验、期限和归属，避免目录再复制一份到数据库；同盘回收以移动原件为主。tmp 可作为既有文件/命令工具的工作目录，继承原项目会话开发环境；其脚本创建不会被当作正式项目改动复核，也不冒充项目测试证据。旧文本事务日志和 Git 各自独立，不能混用恢复编号。保留期限和支持边界见 [工具说明](./工具说明.md#临时工作区与回收站)。

## 依赖方向

TUI 使用 `ChatLog` 显示历史和生成中的回答。流式阶段最多每秒合并更新 30 次，`StreamLines` 只对新收到的字符按显示宽度折行，已完成显示行只写一次，仅重绘末尾未完成的显示行；长段落没有换行时也不重排全文。截断临时尾行时原地修改列表，不复制历史行；状态栏随工具开始、完成更新进度。完成后替换当前回答为 Markdown，不重复追加整条回答。流式临时文本不写入会话，最终回答和来源核验说明一起保存。`ui/tui/rendering.py` 为 Markdown、裸网址和行内代码网址保留链接样式；屏幕处理左键点击后在后台工作线程打开系统默认浏览器，避免阻塞界面。滚动到底部时跟随新内容，向上阅读时保留位置。

`app/tool_events.py` 从实际开始/完成事件生成有界、脱敏的工具显示数据；每项带请求、会话和独立事件标识，不从思考文字猜测执行。`sessions/tool_activity.py` 聚合并校验显示记录，`chat_service.py` 在成功轮次把它保存到会话助手消息的 `tool_activity`，与发送给模型的工具消息分开。旧会话从已有成对消息恢复显示，不迁移或重放执行。`ui/tui/tool_view.py` 在聊天中绘制独立可展开的工具框，结果最多每100毫秒合并一次界面重绘；单项先完成就先更新。工具参数/输出使用纯文本，正文不展示原始脚本，文件正文不复制到显示记录。缩放只响应聊天区实际宽度变化，避免无关布局通知清掉选区；回调还校验会话身份和本轮有效标记，阻止上一轮延迟事件串入新轮次。

敏感配置规则集中在 `security/content_guard.py`。应用内 Hook 按工具能力组织在 `hooks/`，通过 `registry.py` 注册、`runner.py` 统一执行；`workspace.py` 负责文件写入和命令后的有界观察，`git.py` 负责真实索引、提交树、待上传历史及克隆检查。工具在取得实际内容时调用，执行点再次强制检查；网关审批不能替代这些内容校验。Hook 不提供进程隔离，参见 [Hook 结构与验收](./测试记录-2026-10-29-Hook目录整理.md)。

同一轮允许按需多次调用相同名称、相同参数的工具，包括修改后重新读取、修复后重跑测试、轮询和重试；每次实际执行并保留独立结果，不按参数缓存或一律拦截。总循环上限、每批调用数量、工具额度和权限校验仍然生效；敏感操作重复执行仍需满足当次授权，Git 内部令牌仍不可重放。详见 [重复调用修复验收](./测试记录-2026-10-27-工具重复调用.md)。

工具按调用方式明确区分：`tools/local/` 是直接调用的内置工具；`tools/mcp/` 负责 MCP 接入，`servers/` 保存我们维护的 MCP 服务实现。Git 属于我们实现的 MCP 服务，GitHub 属于外部 MCP 服务。内置注册表与 MCP 注册表分别构建，在应用层合并给同一个权限网关和循环使用。MCP 客户端只依赖共享契约，不导入 Git 服务端实现；内置业务不导入 MCP SDK。项目文件工具借用本轮已核验仓库范围，GitHub 管理 REST 工具复用访问范围与凭据适配器；它们仍属于直接调用工具，不冒用官方 MCP 名称。

当前工具归类的验证范围见 [工具目录验收](./测试记录-2026-10-27-工具目录归类.md)。

## 修改复核与工具批次

`commands.py` 在 Windows 注册 argv 型 `workspace_run` 与字符串型 `shell`（PowerShell），共用程序计划、后台策略和项目独占锁。`platform/shells.py` 定位系统 PowerShell，`process_runner.py` 强制建立 AppContainer，并管理有界输出/超时/取消；Job 所有权与令牌验证均在目标程序恢复前完成。`hooks/commands.py` 处理机器管理指令及凭据检查。环境检测也持项目独占锁，逐个完成版本探针；其他项目可并发。实际测试证据由 app 根据 validation_kind 和修改代次记录，复杂脚本退出成功不冒充测试通过。其他平台缺少已验收隔离后端时拒绝执行。

环境准备遵循模型规划、提示词规定原则、工具执行的分工，不增加语言安装状态机。`platform/command_environment.py` 统一构造公共构建环境与本次覆盖，`security/command_policy.py` 按同一 PATH 定位并绑定程序；准备和执行环境前后核对，不通过全局 `os.environ` 修改来共享激活状态。覆盖参数属于本次精确授权，独立任务互不继承。环境准备和安装后的核验要求在 system prompt 中；Bash schema 说明每次新进程及环境边界。

`platform/toolchains.py` 提供有限本机候选位置和固定版本参数，`tools/local/environment_inspection.py` 一次返回发现结果，减少多轮 shell 查询。`app/task_scope.py` 只解释当前用户明确的新项目/Go 运行请求，向工作区和 Git 注册默认审批分类；不改变通用 core 或后台策略。`security/command_summary.py` 将有限已知动作转换为用户可读用途，未知脚本保留保守提示，完整参数留在详情；TUI 进度使用可信活动名称。`change_review.py` 区分 Go 运行/构建证据和测试证据，不再用“没有单元测试记录”代替简单程序的实际运行结果。

`sessions/environments.py` 在现有 `tasks.sqlite3` 中保存会话项目开发环境；`sessions/task_database.py` 统一该库的首开与 schema 初始化，任务记录和环境记录复用同一数据库。`tools/local/environments.py` 负责查询、具体预览、安全检查、版本比较和保存/清除，`app/runtime.py` 在首次连接和重新连接时传入实际会话 ID。一会话可有多项目记录，不产生每会话配置文件；命令本次覆盖优先于会话项目配置，再继承当前公开宿主环境。保存内容不包含全量 PATH、shell 内存或授权；记录版本在命令取得项目锁后再次检查，配置失效或改变则停止。复用既有配置不等于项目版本兼容性已经得到模型验证。

`core/scheduler.py` 使用 asyncio TaskGroup 和信号量，所有工具类型都参与统一调度，最多四项同时执行。`app/tool_resources.py` 从可信工具契约和参数声明文件、项目及远程仓库的读写范围；不同文件的写入、不同项目的命令与 Git 修改、不同仓库的 GitHub 操作、网页搜索/读取可以并行。共享资源存在写入时，后调用等待先调用完成，等待不占执行名额；边只指向较早调用，不产生调度依赖环。项目切换、共享配置和复核台账操作独占运行；未知范围默认独占，通用命令按整个项目处理，无法提前确定远程目标的 Git 网络写入保守地占用远程总范围。`parallel_safe` 仅用于查询超时分类和没有资源声明时的保守兼容，不再限制所有写工具串行。

资源顺序不等于业务依赖或前一步成功。后一步需要前一步返回值或根据成功/失败决定是否执行时，必须等本批结果交给模型，在下一轮生成调用，例如搜索后选择网址、创建 PR 后使用返回编号。当前接口没有同批参数引用或任意语义依赖推断；提示词禁止猜返回值，网关仍校验实际范围、版本和权限，但不能保证模型永远不会猜错。单项普通失败保留其结果，不取消其他独立操作。

每项完成后，`app/turn_log.py` 先持久保存脱敏结果，再通知界面；模型适配器等整批结束后按原调用顺序收齐成对结果，再发下一轮请求。MCP stdio 的单个生命周期任务持有 SDK 上下文，最多四个请求子任务共享连接；个别请求取消或超时不关闭共享连接。文件磁盘操作交给线程，继续使用统一系统文件锁，无须引入 fiber。

文件事务在持久记录生成前取得跨进程存活锁，提交/补偿结束后释放。独立写入不再为常规恢复预检取得整仓库独占锁；发现已无存活锁的中断事务才退出共享锁、重新取得仓库独占锁恢复，不升级锁，也不把另一个仍在执行的事务误当崩溃。Git 预览缓存和仓库清单用短互斥段保护，实际 Git 工作仍可在不同仓库并行。网页服务选择使用请求上下文隔离，付费决定串行核对、实际请求可并行。审批弹窗共用界面互斥锁，等待确认不持系统文件锁，独立操作仍可推进。

文件工具继续只负责准确执行和恢复。`app/change_review.py` 收集可信事务编号，按本轮最初快照与最新快照生成本地 diff，不把 Git HEAD 当用户修改基线。改变文件的批次结束后，应用自动把 `review_changes` 结果作为完整工具消息对回填模型；模型用 `record_review` 记录保留、修复、恢复或不确定。过期版本、捏造证据、失败检查或未读完的差异不能确认保留。修复和恢复仍由普通文件工具执行，Reflect 判断本身不写文件。

`patches.py` 只解析有界文本补丁并精确匹配原文件上下文；`transforms.py` 将 patch/move 转换为现有事务条目，不直接执行磁盘修改。移动先创建目标再删除源，保留源字节和模式。注册表、网关、差异预览、内容 Hook、文件锁和恢复模块继续共用；资源调度覆盖补丁所有路径以及移动源/目标，复核结果携带移动关系，便于模型识别源删除与目标创建之间的关联。范围见 [补丁与移动](./测试记录-2026-11-01-文件补丁与移动.md)。

最终回答前还会检查当前版本和复核状态；缺少复核时在同一个最多 16 次决策预算内要求继续判断，不另开反思循环或第 17 次请求。应用区分“模型复核”“真实测试命令成功”和“未验证”，不会把写入成功当作功能正确。任务异常、取消和预算耗尽的逐项结果独立保留，可通过同会话 `task_status` 查阅；历史状态不恢复旧授权。范围及验收见 [编排复核与工具并发](./测试记录-2026-11-01-编排复核与工具并发.md)。

根目录仅保留 `__init__.py` 和 `__main__.py` 两个 Python 文件。迁移期的旧路径转发文件已删除，内部引用和测试全部使用实际实现模块；旧 Python 导入路径不再支持。`DS`、`dianstar` 与 `python -m dianstar` 启动方式保持可用。内部 Git MCP 服务使用 `python -m dianstar.tools.mcp.servers.git.server`；启动参数和打包脚本已同步。`.env`、`.local/` 的路径和数据格式不变，无需迁移已有 Key、配置或会话。

本轮整理继续使用一个 Python 包，不引入多包发布、通用插件框架或新的事件总线。分步验收见 [项目结构整理测试记录](./测试记录-2026-10-27-项目结构整理.md)。

`providers/deepseek.py` 只负责与模型服务通信，不执行天气查询。`tools/local/registry.py` 将工具定义与执行函数配对；`app/runtime.py` 从注册表生成模型可见的工具列表，通过授权入口按名称分派执行。天气执行函数从 `tools/local/weather.py` 获得数据，把裁剪后的字段交给模型适配层。`core/loop.py` 不知道具体工具名称或模型服务商。`prompts/builder.py` 读取 `prompts/system.md` 作为运行时系统提示词；天气工具的用途和参数在工具定义中。`tools/local/weather_contract.py` 裁剪发送给模型的天气数据。

## 一轮天气任务

1. `ui/cli.py` 或 `ui/tui/app.py` 收到问题，调用 `app/chat_service.py`，从 `sessions/conversations.py` 取得本轮可用历史。
2. `app/runtime.py` 每轮通过 `prompts/builder.py` 将固定规则和本机当天日期组装为系统提示词，再创建 DeepSeek 会话并调用 `run_loop()`；同一轮工具循环复用该提示词，下一轮重新获取日期。系统提示词不写入聊天记录。模型根据问题和对话上下文决定是否调用天气工具，程序不做天气关键词分流。
3. `providers/deepseek.py` 以 thinking 模式请求模型，返回文字回答或一组结构化工具动作，并按注册工具的参数定义校验。遇到模型把工具标记当文字返回时，也按同一组工具定义解析完整调用。它不判断天气地点是否需要合并或追问。
4. `core/loop.py` 推进各次工具调用；`app/runtime.py` 通过 `ToolGateway` 和 `tools/local/registry.py` 中的处理函数执行天气工具，裁剪成功结果，或把地点、日期、服务错误作为结构化结果交回 DeepSeek 会话。同一批调用中某个地点失败，不阻止其他地点。模型结合问题、历史和工具结果决定继续调用工具、追问或回答。`tools/local/weather.py` 校验日期与中文城市名解析结果；跨语言名称核对仍有限制。
5. 模型收到查询结果后组织最终回答，程序不检查回答中的气温措辞和数值；回答显示并保存。会话同时保存这一轮的工具调用、工具结果及模型返回的 `reasoning_content`，供后续提问和恢复会话使用；TUI 在每轮问题与回答之间保留独立思考框，默认预览最近四行，点击标题展开全文；纯文本模式只显示最终回答。工具执行仍有参数、日期与地名检查，循环次数用尽则报错；每次提问的 ReAct 循环统一最多 16 次模型决策，包含最终回答。一批工具调用计一次决策，每批仍最多 8 个工具。`core/loop.py` 的 `DEFAULT_MAX_STEPS` 是默认上限，应用入口直接使用该默认值；网页等工具的独立额度不再决定循环轮数。详见 [16 轮循环验收](./测试记录-2026-10-27-ReAct循环上限.md)。

## 日期计算任务

`calculate_date` 与天气工具共同注册在 `tools/local/registry.py` 生成的同一份 `tool_registry` 中；从注册表生成 API 的工具定义，并按工具名称分派执行。日期工具参数保留字符串约定，`operation` 为 `info`、`add` 或 `difference`；MCP 适配支持其他 JSON 参数类型。可选参数在工具端校验，错误带代码、说明和原请求返回模型，模型可修正后继续调用。

计算本身不联网、不读写用户文件或日程，不依赖模型心算。每次执行读取同一时刻，在所选时区解析相对日期；未指定时区则用本机时区。按天偏移和日期差使用公历日期运算，不把夏令时的一天固定换算成 24 小时。日期差为结束日期减开始日期，可为零或负数。系统提示词日期仍固定为提问开始时的快照，工具结果明确携带执行时参考日期及参考 UTC 偏移；跨天时以工具实际计算依据为准。

## 数字计算任务

`calculate_number` 的定义和执行函数接入同一注册表。模型传入字符串 `expression`，程序先限制长度和字符，再解析 AST，仅接受数字、正负号、加减乘除和整数次幂；不使用 `eval`，不执行用户代码。十进制数字直接从源码文本读取，避免经浮点数转换丢失精度。

求值限制语法节点、递归深度、字面量有效数字、幂指数和数字量级；采用独立的 50 位 Decimal 上下文，不改变调用者精度。结果以十进制字符串返回，`approximate` 标识中间或最终运算发生非精确舍入。错误带代码和说明交回模型，允许在原有循环限额内修正表达式。工具不联网、不读写用户文件，列式、单位含义和最终表述仍由模型负责。

## 数据与权限边界

`app/mcp_startup.py` 将保存的连接方式解析为本轮有效设置：缺省/null 自动识别启动目录的项目，GitHub 从 origin 推断公开读取范围；false 明确停用，true 保留配置范围。自动范围不写回配置。Git 安装检测、GitHub 缺少程序/凭据等原因通过 mcp_status 报告。服务在提问时自动连接，结束时释放；不要求手动开启，也没有新增后台常驻进程。

修改工具默认可申请，仍不预先授予执行权限。git_write_enabled/workspace_write_enabled 缺省或 null 在运行时解析为逐次申请，false 明确禁止；GitHub 写入/管理范围缺省/null 取当前项目 origin 与允许范围的交集，空列表明确禁止，额外只读仓库不自动扩大为写入/管理范围。凭据后备和私有内容读取保持独立配置。

功能权限控制只保留在后台，MCP 界面没有启用、禁止或审批选项。security/tool_policy.py 定义 ToolPolicy(enabled, requires_approval)，由可信应用层通过 run_turn(tool_policies=...) 提供，工具名规则优先于能力名规则。ToolGateway 在发布工具 schema 和执行时都检查可用性；免弹窗策略仍须完成可信预检、参数/请求绑定的单次授权和工具端状态重查。规则按请求快照保存，不由模型修改，重连与工具列表刷新不解除规则。后台模式接口和实际模式产品分开：本次没有增加只读/全权限菜单或完整模式切换。

默认策略通过 confirm_destinations 对具体 clone/init/worktree 目标逐次确认，配置了创建根目录时仍受其限制；旧只读模式可保留独立 clone 申请。客户端权限网关和服务端单次状态绑定令牌均保留，无确认入口或用户拒绝时不执行。成功创建后只保存该仓库，不保存自动识别的当前项目、GitHub 范围或父目录信任。

工具分派全部经过 `ToolGateway`，研究资料和 `Authorization` 分开。普通问答只能查询网页权限；修改走独立流程，非确定性提案必须由用户确认，按本轮请求及精确参数批准。DSML 兼容结果保留成对工具消息，不提升为用户消息。文件工具检查明确仓库与路径，命令工具按后台策略确认或禁止，并强制使用实际隔离后端。具体实现及限制见 [安全机制](./安全机制.md)。

- `.env` 由本地 SDK 适配层读取，API Key 不作为模型消息发送；`.gitignore` 防止普通 Git 暂存纳入密钥文件，但不限制本机文件访问。
- `.local/conversations/` 存放本机会话明文，包括名称、推理内容及工具结果，不进入 Git。首次成功提问生成默认名称；`/rename` 更名，`/resume 会话名` 按名称加载，`/switch` 按最近修改时间列出并选择。`/compress` 仅改变后续请求的上下文起点。
- 当前注册天气、日期、数字及网页搜索／读取工具；关闭网页服务时不向模型暴露网页工具。MCP 每轮按连接方式自动发现并连接服务，将筛选后的工具注册到同一网关。Git、文件和命令默认开放逐次申请，可信异步预检先生成状态绑定的预览；确认后授予精确参数的单次权限，服务端消费内部令牌并重查状态。GitHub 官方参数由 schemas.py 适配，github_contract.py 定义读写及方法集合，github_search.py 检查搜索范围，github_adapter.py 检查公开/私有访问，github_writes.py 负责写入预览和状态重查；GitHub 写入/管理默认仅当前项目，每次通过同一网关单独确认。详细流程见 [MCP 接入](./MCP接入.md)。新接入范围通过 app/mcp_configuration.py 展示前后配置并确认后重连。日程、提醒及后台命令管理尚未实现；Windows 命令隔离见本页开头。
- 提示词中的指令边界和授权规则是模型行为约定，不是权限控制的实现。未实现能力在 [System Prompt 蓝图](./system_prompt_blueprint.md) 留空，蓝图不参与运行时请求。
