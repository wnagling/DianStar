## 暴露的问题和建议优先级

1. **相对目录与PowerShell入口**：部分未显式限定项目的递归查询尝试访问盘根后被拒绝；模型通过改用明确项目路径恢复。应统一shell/workspace_run启动PowerShell时的目录语义，并补充常用默认路径回归，不能放宽盘根访问权限解决。
2. **审批过密**：首轮91次，Java单题10次。目录查看、局部文件处理和明确任务内的编译/运行应梳理任务授权范围，仍保留网络、安装、越界及高影响动作的具体确认，不能用全局放行替代。
3. **复核证据难用**：首轮真实工具结果中11次invalid_review_evidence、1次review_incomplete。模型多次引用无效或过期call_id，导致重复复核。建议由应用提供可直接引用的当前证据，并区分命令结果、读回及diff；任务正确但复核往返多也计入调用成本。
4. **环境探测绕路**：Java最终找到了可用IDE工具链，但现有有限发现未返回它，模型多次手动探测。可增加受控已安装SDK候选，继续拒绝无权访问的位置，不扫描全盘或偷偷更改ACL。
5. **生成二进制后的审计**：Go实际成功却持续事后检查不完整，需明确按类型/大小区分可扫描文本与构建产物，仍如实报告未覆盖部分，不能直接把complete改成true。
6. **出题与评分**：区分读取转换与原地修改，明确空行、空格、并列排序和编码规则。应保留初轮、补验及评分修正历史，防止把评分器错误记成模型缺陷。

本轮没有为提高成绩修改产品提示词或权限，不覆盖用户输入，不删除失败夹具。独立目录和已有保护均保持，未执行破坏系统盘或驱动的真实操作。
