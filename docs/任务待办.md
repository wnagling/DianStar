# 任务待办与右侧栏

待办使用 Tool 和程序状态实现。Skill 可以补充规划方法，但不承担实时进度、版本核对或持久化。当前一份会话保存一份当前计划，新的任务可用新标题和完整步骤替换当前计划；本版不是多任务调度器。

## 使用与界面

模型应在复杂、多步骤或需要修改并验证的任务中建立2至12项待办，普通问答不建立。已有计划跨轮保留，是否属于当前任务仍需模型结合用户要求判断；不能保证任意模型总能正确识别复杂度。

是否建立待办取决于任务的实际复杂度，由模型通过工具选择，不按“建项目、实现、测试”等关键词强制创建。简单任务、小程序加测试和少量直接操作可直接完成；多个独立交付项、跨模块依赖或需要持续跟踪的阶段性工作才适合待办。已确认真实运行中模型可能不调用工具，因此目前不承诺所有复杂任务都能稳定触发；不能为了展示侧栏而给简单任务硬塞计划。

宽度达到110个终端单元时，右侧自动显示目标、已完成数量和步骤状态，侧栏约30%且最多45列。顶部按钮可收起。较窄窗口默认折叠，点“待办”切换为单独查看，再点一次回到聊天。列表可滚动，界面使用纯文本渲染，标题中的方括号等不会被当成格式指令。无待办的会话不显示按钮，也不占用聊天宽度。

状态为待处理、进行中、待核验、已完成、受阻、等待你确认。同时最多一个进行中步骤。停止一轮后不再显示仍在执行的假象，保留“上次进行”；取消、失败和预算耗尽分别显示停止原因。重新打开会话可恢复显示；其他会话的更新不串入当前页面。

## 工具契约

- `todo_read()`：读取当前会话计划与 revision，没有计划时返回 null。
- `todo_write(revision, title, steps)`：提交完整计划。新建 revision=0，更新须使用读取到的最新版本。每步包含 id、title、status、evidence；evidence 为成功工具结果的 call_id 列表。重复编号或多个进行中步骤被拒绝。

两者统一经过 ToolGateway，使用独立 `task.progress` 能力，每轮默认最多32次，可被后台停用或明确撤销。工具只改进度元数据，不授予文件、命令或网络权限。没有会话标识的独立运行不提供这些持久待办工具。模型不能指定存储路径或操作其他会话。

新标记完成的步骤须引用本轮实际成功结果；错误、失败退出、超时、输出超限、明确不完整结果以及待办工具自身不算完成证据。原计划中完全不变的已完成步骤可保留旧引用，换任务标题后不能借此复用旧完成证明。证据只证明对应操作成功，**程序尚不能判断“这个测试是否充分证明这个业务目标”**；修改相关代码后将旧测试步骤改回待核验仍依赖模型遵守规则。

## 状态、恢复与边界

复用本机私有 tasks.sqlite3，在独立 todo_plans 表保存每会话当前计划。Windows 使用现有 DPAPI 保护正文，其他系统依赖私有目录权限，不声称正文加密。更新使用数据库事务和版本比较，防止较旧计划覆盖新计划；旧运行的结束事件也不会覆盖另一个写入者已更新的进度。存储失败不报告更新成功。敏感数据复用公共扫描与脱敏规则，不保存可识别的密钥。

应用运行时在开始时附上同会话历史计划作为待核对的数据，更新时通过独立事件通知界面，工具结果进入原有日志；正常收尾、取消、失败和预算耗尽保存停止状态。进程被强制终止时可能只保留最后一次成功落盘的进度，界面将其视为历史待核对状态。

本版不恢复批准、预览令牌或运行进程，不自动重复已执行操作，不提供完整上下文摘要或语义恢复。待办标题及步骤是模型生成的进度标签，不能替代用户原话或修改权限边界。

## 验证

`python -m unittest tests.test_task_plan -q` 覆盖持久恢复、会话隔离、版本冲突、成功证据、敏感内容、后台撤销、并发结束保护、宽窄布局和原始文本渲染，以及假模型经真实运行时更新与下一轮载入。模型调用为模拟，不代表真实模型任务规划能力验收。
