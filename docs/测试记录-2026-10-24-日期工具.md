# 2026-10-24 日期计算工具验收

## 实现范围

新增 `dianstar/tools/date_calculator.py`，工具名为 `calculate_date`：

- `info`：公历日期与星期，`date` 可省略，默认为 `today`。
- `add`：在起始日期上加减整数天，`days` 沿用当前工具适配层的字符串格式。
- `difference`：返回 `end_date - date` 的有符号天数，不按首尾均计入计数。
- 支持 `today`、`tomorrow`、`yesterday`、严格的 `YYYY-MM-DD`，以及 IANA 时区；未指定时区使用本机时区。
- 参数与日期范围错误通过带错误码的结构化结果交回模型；不读写用户文件、日程或提醒，计算本身不联网。

工具定义和执行函数共同接入 `agent.py` 的 `tool_registry`，API 工具列表从该注册表生成。运行时 System Prompt 增加日期工具选择规则，蓝图中的日期模块标记为已实现；日程和提醒模块继续留空。

## 离线验证

`python -m unittest discover -s tests`：101 项通过，其中新增日期工具测试 11 项，包含多个边界子场景。

- 月末、年末、闰年、正负和零天偏移。
- 日期差的正、负、零值及计数口径。
- 同一时刻在不同时区属于不同日期，夏令时参考偏移。
- 无效日期、时区、参数组合、超长数字和日期溢出。
- DSML 按同一工具定义解析可选参数。
- 经注册表执行日期工具，将错误交回模型，修正参数后一次执行多个日期调用，并把结果写入模型上下文。
- 现有天气、配置、会话、日期注入和 TUI 测试仍通过。

## 真实模型验证

使用当前默认 `deepseek-flash`，共 4 个场景、8 次模型请求。覆盖流式和非流式回答；未模拟日期计算，也没有执行 shell 或修改用户文件。

| 提问 | 实际工具调用 | 结果 |
| --- | --- | --- |
| 2028 年 2 月 29 日星期几 | `info`，日期 `2028-02-29` | 星期二，回答与工具一致 |
| 2028 年 2 月 28 日往后两天 | `add`，起始日期 `2028-02-28`，`days="2"` | `2028-03-01`，回答与工具一致 |
| 2028-02-28 到 2028-03-01 相差几天，不按首尾双计 | `difference`，指定起止日期 | 2 天，回答与工具一致 |
| 纽约、上海现在的日期与星期 | 两次 `info`，分别使用 `America/New_York` 和 `Asia/Shanghai` | 本次纽约 2026-10-23 星期五、上海 2026-10-24 星期六，与工具一致 |

每次模型请求都能看到 `get_weather` 和 `calculate_date` 两个工具；本批日期任务没有调用天气工具。原始输入、参数、计算结果、回答和耗时保存在 `.local/evaluations/date-tool-20261024-010034.json`，已检查不含当前使用的 API Key。

## 边界

- 以上真实用例各采样一次，不代表所有问法都能稳定选对工具或回答正确。
- 相对日期由工具执行时同一时刻在目标时区的日期确定；系统提示词日期仍是提问开始时按天注入的快照。
- 本次没有增加日程、定时提醒、工作日、节假日、农历、时刻转换或按月／年偏移计算。
- 本轮更新源码和测试，既有 Windows 便携包需要重新构建后才包含该能力。
