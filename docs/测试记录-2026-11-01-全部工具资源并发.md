# 全部工具资源并发验收（2026-11-01）

本记录补充此前的[编排与查询并发验收](./测试记录-2026-11-01-编排复核与工具并发.md)，扩展所有工具类型参与资源调度。历史记录的查询限制和 633 项结果不作为本轮新实现的验收结论。

## 行为及依赖边界

- 文件读写、网页搜索/读取、命令、Git、GitHub、计算及项目管理工具都进入同一个调度器。最多四项实际执行；不同资源可并行，冲突资源按原调用顺序等待。等待前项不占工作名额，依赖边始终指向较早调用。
- 文件按路径，命令按整个项目，Git 按项目，GitHub 按远程仓库声明读写范围。项目切换、共享配置和复核台账独占运行。未知工具/范围保守独占；Git 网络写入的远程目标在预检前尚未确定，暂用远程总范围；跨 fork PR 的来源读取范围也保守处理。这些操作都参与调度，不承诺没有资源信息时仍可并行。
- 每项完成先持久化，再更新界面；整批完成才按原调用顺序把完整工具结果交给模型。所有工具继续经过 ToolGateway、审批与 Hook。
- 资源等待只能保证冲突顺序，不表示前一步成功，也不自动传递返回值。需要搜索返回的网址、PR 返回的编号、最新文件内容或根据成功/失败决定下一步时，必须由下一轮模型决策生成调用。系统提示词明确要求这样规划；当前没有任意语义依赖推断或同批参数引用机制，不能承诺模型一定不会猜参数。
- 审批弹窗依旧逐个展示，但不把全部写入或等待审批的操作当成全局屏障。审批不持系统文件锁。

## 执行和恢复保护

独立文件写入的常规预检不再取得整仓库独占恢复锁。事务在持久日志生成前取得跨进程存活锁，提交/补偿完成后释放；其他写入识别活跃事务，不会误触发回滚。只有检测到中断事务，才释放共享仓库锁，重新取得独占锁进行恢复。父目录与文件去重后按固定路径顺序加锁，独占优先，不做锁升级。

Git 预览缓存与一次性令牌用短互斥段保护，不同仓库的实际操作保持并行；初始化的仓库清单更新也只锁住元数据更新。网页请求用各自的上下文保存免费/付费服务选择，并发付费请求在共享决定锁内重新核对本轮授权，释放锁后进行网络请求。

这些锁协调 DianStar 的协作实例，不约束任意外部编辑器或命令跨目录访问；不宣称远程副作用可自动回滚或所有存储故障均可恢复。

用例包括：

| 范围 | 验收方式 |
| --- | --- |
| 所有工具类型 | 写入、命令、Git/GitHub 修改使用不同资源声明，四项确实同时进入处理函数；不以工具类别排除修改 |
| 网页混合调度 | 使用实际本地注册表，搜索、已知网址读取和文件写入在同批重叠执行，网页响应为模拟 |
| 文件实际写入 | 两个文件在保存 prepared 日志后相互等待；只有同时执行且未误恢复才能完成 |
| 跨进程事务 | 两个真实进程各自保存日志后等待另一个标记，均成功提交；未把活跃日志误当中断 |
| 命令实际并发 | 不同项目中的两个 Python 子进程各等待对方标记，均返回成功 |
| Git 修改 | 两个真实临时仓库在预览与实际创建分支阶段分别设置会合点，两枚令牌保留、各仅能使用一次 |
| 初始化 | 两个真实临时仓库初始化在进入执行阶段会合，仓库清单均保留 |
| 审批 | Git 操作停在真实审批回调，独立计算等待弹窗进入后才开始，完成后再放行批准 |
| 返回值依赖 | 两个搜索全部返回后，第二次模拟模型请求才用搜索返回网址构造读取；记录表明读取在两个搜索完成后开始 |
| 网页服务隔离 | 两个付费备用与免费读取重叠，每项仍使用各自服务，付费只询问一次、计数准确 |
| 冲突和顺序 | 同资源顺序等待且不占工作名额；多资源以相反顺序声明也能完成；跨 fork 来源使用保守范围 |
