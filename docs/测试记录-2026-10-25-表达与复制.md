# 2026-10-25 表达与聊天记录复制

## 调整

运行时 Prompt 与蓝图补充：简单算术和大小比较通常一句话给出结果，不主动播报工具名称、参数、原始错误码和精度字段。精度信息用于内部判断，近似值自然使用“约”；精确值不机械追加“精确结果”。需要时简短说明复利等计算假设，用户要求过程或技术细节时再展开。

当前安装的 Textual 8.2.8 中，RichLog 没有实现自身内容的文字提取及字符坐标。新增 ChatLog 子类，为已有富文本行补充字符坐标、选区高亮与文字提取；中文按字符定位，保留原 Markdown 样式，通过 Screen 的复制操作写入剪贴板。切换或清空聊天记录时清理旧选区。

## 保留右键前选区与 Windows 系统菜单控件

再次收到用户截图：右键后选区扩大到整页。根因是 Textual 8.2.8 的 Screen._forward_event 在 Widget 处理鼠标事件之前，已经把非左键也当成新选择起点；仅在 ChatLog 中 stop/prevent_default 无法阻止。现用 ChatScreen 作为默认页面，在这层先截住非左键事件，右键仅查询既有选区并请求菜单，不重建选择状态；没有选区时不使用历史缓存文字。

Windows 的实际运行使用 Windows Forms ContextMenuStrip：深灰背景、普通菜单项、复制图标、Ctrl+C 提示和系统菜单的外部点击／Esc 关闭。通过固定 PowerShell 资源启动，标准输入只传鼠标坐标；真正选择复制后才把原选中文字交给系统剪贴板。后台异步等待不阻塞 TUI，取消、退出或超时会关闭子进程；非 Windows 与 headless 测试继续使用已有浮层。`assets/copy_menu.ps1` 已列入包数据，便携构建的 collect-data 会包含它。

实际 Windows 菜单测试：运行真实资源，自动触发取消与复制，分别返回 cancel／copy，均正常退出；未改动系统剪贴板。通过控件 DrawToBitmap 获得预览 `.local/evaluations/native-copy-menu.png` 并目视检查。这里使用 Windows Forms 菜单控件，并不声称完全复刻 Windows 11 编辑器菜单的每一项或圆角效果。

专项测试 21 项通过，包含既有选区和内部选择状态在右键前后完全相同、右键点到其他位置也只复制原选区、原生菜单路径不创建终端浮层、取消不复制、坐标数据传递和取消时回收子进程。完整测试 117 项全部通过。此次未推送。

## 未选择时静默与菜单进程预热复用

移除“请先用鼠标左键拖选需要复制的文字。”状态提示；没有选区时右键直接返回，不改变状态栏，也不启动菜单。

此前每次右键都启动 PowerShell 并 Add-Type 编译菜单，导致可见等待。现每个 DianStarApp 持有 WindowsCopyMenuClient，启动时以 worker 在后台预热；PowerShell 资源启动后编译一次，发送 ready，逐行读取后续坐标请求，每轮发送 shown 和 copy／cancel／outside。菜单关闭后保留后台进程等待下一次请求，不重新启动或编译。协议仅传坐标，不传聊天文字。退出应用时回收进程；取消、超时或协议错误会关闭旧连接，避免旧返回误用于新请求；下次使用可重新初始化。

## 禁用右键连击全选

Textual 会在 MouseDown／MouseUp 后另外生成带 chain 的 Click 事件；Widget 默认对 chain=2 全选控件、chain=3 选择容器，未区分左右键。补齐 ChatScreen 的非左键 Click 拦截，阻止右键连击进入全选逻辑，保留左键拖选及原有右键复制。新增回归验证右键双击、三击不扩大已有选区，无选区时也不产生全选。
