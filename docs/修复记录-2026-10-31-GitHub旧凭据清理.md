# GitHub 旧凭据清理记录（2026-10-31）

## 问题

新登录覆盖账号元数据后再清理旧凭据，清理异常被忽略。系统凭据库暂时不可用时，旧登录引用可能丢失；旧版退出失败记录也可能被下一次登录覆盖。

## 本次实现

- 账号元数据增加有界 `pending_cleanup`，只保存已识别的账号名和 DianStar 命名空间，不保存令牌。新账号与旧清理引用通过同一次原子文件替换保存，避免先覆盖后丢失旧引用。
- 新账号切换成功后再清理旧记录。清理失败保留条目并提示；确认删除成功后才移除条目。旧版 `signed_out` 加账号/命名空间的记录会一并保留和重试。
- 账号页面的既有“检查状态”操作会重试待清理记录，不新增确认弹窗。退出先保存禁用状态及清理队列，即使清理失败也不会重新启用凭据后备。
- 不允许待清理记录包含令牌字段、其他应用命名空间、重复条目或当前活动账号。为退出操作预留队列容量；队列接近上限时暂停新登录并提示先检查状态。
- 账号服务实例内用异步锁串行处理登录、退出和检查。清理中取消后保留已保存的新账号与旧记录，不回滚到旧登录；不宣称提供跨进程账户事务隔离。
- 对失败登录的临时清理，只有能够识别账号时才进入持久化清理流程；无法读取临时账号时仍不能确认其清理结果。

## 验证状态

补充了切换后清理失败及重启重试、旧版退出失败记录迁移、清理中取消、激活保存失败不删除现用账号、退出容量预留，以及元数据字段限制的回归用例。

初次实现时只修改代码、补充用例并审阅差异，未运行测试。用户随后澄清：开发和修复可以按需测试，只是单纯提交、推送时不附加测试。现已补做相关离线回归，具体命令、结果和环境限制见 [回归记录](./测试记录-2026-10-31-账号与Git核对回归.md)。本轮未操作真实凭据库，不将离线结果当作真实账号验收。
