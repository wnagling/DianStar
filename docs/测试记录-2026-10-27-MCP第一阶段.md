# MCP 第一阶段测试记录

日期：2026-10-27（Asia/Shanghai）。

## 已实现

- MCP 官方 Python SDK 1.x stdio 客户端；服务初始化、分页工具发现、调用、超时、取消及进程清理。
- 外部工具注册到现有 ToolGateway；本地 JSON Schema 校验支持嵌套参数，禁止远程引用解析，循环对嵌套参数做稳定去重。
- 内置 Git MCP Server：指定普通仓库的 status、diff、log，不开放写操作。
- GitHub 官方本地 Server 的固定只读工具适配；指定公开仓库及 method 检查，调用前不带 Token 核验公开元数据。
- `/config` → MCP 配置入口，启停范围、仓库、程序路径、遮挡 Token、测试连接。
- 外部资料提示词、GitHub API 来源记录、长度限制、错误归一化和已知本地密钥字面值遮挡。

## 验证结果

- `python -m unittest discover -s tests`：**265 项通过，53.080 秒**。
- MCP 与配置界面专项：**23 项通过**。测试使用一次性 Git 仓库、真实本地 stdio 子进程、模拟模型和模拟 GitHub 结果。
- 真实 MCP 连接可发现 3 个 Git 工具，查询工作区差异、状态和提交历史；查询前后索引相同。
- 未配置仓库、未开放的 commit 请求、私有性无法确认的 GitHub 目标、未知 method 均被拒绝。
- 关闭/取消初始化可清理服务；工具列表变化后拒绝继续使用本轮定义。
- 测试验证外部 diff 不执行、工作区配置不能改变查询根目录、filter/include 配置被拒绝、常见密钥文件名不进入 staged diff。
- 80×24 配置界面测试通过；保存配置不启动服务，Token 遮挡，保存后清空，不写入 MCP JSON。
- `python -m pip check`：无依赖冲突。安装 MCP 时发现现有 FastAPI 对 Starlette 的版本约束，已在本机恢复兼容的 Starlette/SSE 组合。
- Python 编译检查与 `git diff --check` 通过；Git 仅提示已有工作副本的 LF/CRLF 转换。

## 未声称完成的验证

- 本机未配置 GitHub 官方 Server 程序，因此没有真实 GitHub MCP 网络查询；其参数适配、只读范围和返回处理使用模拟结果验收。
- 没有调用真实 DeepSeek 模型；模型驱动真实本地 MCP 的编排使用模拟响应验证，无模型/API 费用。
- 没有提交或推送项目改动，没有修改用户真实仓库的暂存区、提交或远程分支。
- 未实现操作系统沙箱、通用文件读写、Git 写操作、私有仓库读取或通用隐私外传检测。
