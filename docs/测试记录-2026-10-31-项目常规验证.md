## 当前自动范围

以下范围描述任务需要验证时的审批方式，不是提交或推送的强制前置步骤。开发和修复时可以按需运行相关测试，无须用户另行要求；单纯提交、推送现有改动不附加验证，也不在每次修改后反复询问是否测试。下文串联流程是“明确需要验证并发布”的集成验收示例。

- Python unittest/pytest：保持原有测试选择和参数检查。
- Python compileall：允许明确的、实际存在的项目内文件或目录，以及常见输出、递归、优化、有限并发和缓存失效模式。不会默认遍历 sys.path，不读取 `-i` 文件列表或 stdin。执行计划补上项目内源文件链接限制；这不是操作系统隔离。
- Python py_compile：编译明确的项目 Python 文件，支持安静模式；不从 stdin 接收文件列表。
- Python pip check：仅检查当前解释器环境中的依赖一致性，不包含 install、uninstall 或其他子命令。
- Git diff --check：允许工作区或暂存区空白检查。复用 GitWorkspace 的元数据与配置检查、禁用全局配置的受控环境和固定参数，关闭外部 diff、textconv、fsmonitor。Git 的推送、删除、重置、配置修改等不因此获得自动执行权限。

所有自动验证仍先检查已接入项目，绑定实际执行程序与参数，使用精确单次授权，遵守超时、输出限制、脱敏和命令后审计。显式后台审批/禁用、撤销和过期继续有效。未知参数和其他工具保持原有规则，不增加 UI 开关。测试和第三方模块本身仍能执行项目代码，分类不证明没有副作用。

## 实现与文档

`security/command_policy.py` 负责分类、参数和路径检查；`tools/local/workspace.py` 准备真实命令并为 Git 验证复用现有 Git 安全上下文，执行前重新核对。没有增加模型可控制的环境覆盖参数。系统提示、工具说明、首页和 MCP 文档同步说明验证范围。
