# 文件补丁与移动验收（2026-11-01）

## 实现范围

- 新增 `patch(repository, patch)`：多文件新增、精确修改、删除，以及 Update File / Move to 组合。独立 `@@` 修改段精确匹配原文件，拒绝缺失、重复、乱序或重叠上下文；可限定文件末尾，不接受数字 unified diff 头或模糊匹配。
- 新增 `move(repository, source, destination)`：同项目文件移动与重命名，目标不存在才执行，自动创建父目录，原始字节、BOM、换行和文件模式保留。移动时修改内容可以放进一份 patch。
- 两者复用现有网关、Hook、确认后复查、统一文件锁、持久事务和撤销恢复，注册 `project.files` 副作用；应用自动回填差异，包含移动源/目标关系。系统提示词、权限依赖、审批摘要、资源范围和文档同步维护。
- 移动先发布目标，再删除源；失败或取消逆序补偿。成功、撤销和再次撤销都记录事务，反向移动关系继续保留，使大文件移动和撤销使用紧凑预览。

边界：普通 UTF-8 文件至多 2 MiB，当前不处理目录、二进制、链接、跨项目移动及 Windows 仅改大小写的重命名。补丁至多 256 KiB、200 段和 20 个源/目标路径，每路径一次；移动算两个事务路径。完整修改差异受原 24000 字符预览限制，纯移动只显示路径关系；补丁和移动均没有 `local_only` 参数。文件事务为可恢复补偿，不承诺外部程序看到多文件瞬间原子变化，也不能自动撤销外部副作用。
